# 프로그램 개요

이 파일은 프로그램이 어떻게 구성되고 작동하는지를 정리한 문서이다.

## 화면의 큰 구조

프로그램을 켜면 먼저 **홈 화면(랜딩)** 이 뜬다. 여기서 운송 거리·지역·착공일 같은 사업 공통 조건을 입력하고 "새 프로젝트 시작"을 누르면 본격적인 작업 화면으로 들어간다.

작업 화면은 두 층위로 나뉜다.

- **상단 메뉴 줄 (전역 기능)**: 설계안 하나에 매이지 않고 사업 전체에 공통으로 쓰이는 기능을 모아 둔 곳. 프로젝트 설정(현장 위치·운송 조건 등 공통 입력, 트럭 카탈로그 관리 포함)이 여기에 있다.
- **탭 줄 (하나의 설계안 작업 흐름)**: 하나의 설계안을 처음부터 끝까지 진행하는 순서다. 총 10개 탭으로, **모듈 정의 → 배치 설계 → 접합부 설계 → 구조해석 → 단면 설계 → 물량 → 운송 → 공정표 → 종합 → 비교** 순이다. (앞의 모듈 정의·배치 설계 두 탭을 묶어 "디자인"이라 부른다.)

아래는 먼저 홈 화면을 설명하고, 이어서 각 탭을 작업 순서대로(디자인·접합부·구조해석·단면설계·물량·운송·공정표·종합·비교) 정리한 뒤, 마지막 절에서 상단 메뉴 줄(전역 기능)을 다룬다.

---

## 0. 홈 화면 (시작 화면)

프로그램 실행 시 가장 먼저 보이는 화면으로, 본격 작업에 들어가기 전 사업 공통 조건을 입력받는 곳이다.

- 상단에 프로그램 제목과 부제가 표시되고, 가운데 큰 시작 카드 안에 **프로젝트 설정 입력 폼이 그대로 들어가 있다**(상단 메뉴의 프로젝트 설정과 같은 입력 폼). 좌측은 운송(편도 거리·운임 방식·단가·고정비), 우측은 공기·현장 제한·비내력벽(지역·착공일·중량/폭/높이 제한·벽 단위중량)을 받는다.
- **"새 프로젝트 시작" 버튼**을 누르면 입력값이 프로젝트 설정에 적용되고, 화면이 탭 줄(모듈 정의 탭부터)로 전환된다.
- 아래쪽에 배치→접합→해석→물량→운송→공정표로 이어지는 작업 순서 안내가 단계 카드로 표시된다.

## 1. 디자인 — 모듈 정의 탭 + 배치 설계 탭

디자인 단계는 두 탭으로 나뉜다.

- **모듈 정의 탭**: 모듈·패널·수직모듈 같은 컴포넌트를 (종속 부재·개구부·실까지 묶어) 하나의 "정의"로 만들어 라이브러리에 저장하는 곳.
- **배치 설계 탭**: 저장한 정의를 가져와 배치하거나 부재를 직접 놓아 건물 모델을 완성하고, 실(공간)·개구부·벽까지 구성하는 곳. 여기서 만든 배치 결과가 이후 모든 탭(접합부 설계부터 평가까지)의 출발점이 된다.

두 탭은 부재 팔레트·2D 평면 배치·3D 확인·자동 정렬/간격/층 복사 등 핵심 조작을 공유한다(동일 코드 재사용). 2D 화면에서 한 개 층의 평면을 배치하고 층수를 정하면, 3D 화면에서 전체 층수만큼 쌓인 건물을 확인하는 구조다. 아래는 먼저 공통 기능을, 이어서 각 탭 고유 기능을 정리한다.

**이 탭에서 하는 일 (공통 — 부재 배치)**

건물을 이루는 각 부재(모듈·바닥패널·벽체패널·보·기둥·코어 등)를 평면에 배치하여 건물 모델을 만든다.

**화면 구성**

- 좌측: 부재 팔레트 — 무엇을 놓을지 선택
- 가운데: 2D 평면 배치 화면 — 어디에 놓을지 결정
- 우측: 속성 패널 — 선택한 부재 정보 확인
- 별도 3D 화면: 배치 결과를 입체로 확인

**(1) 좌측 — 부재 팔레트**

배치할 수 있는 부재는 9종이며, 부재마다 사용자가 입력하는 값이 다르다. 대부분의 치수는 자동으로 정해지고 꼭 필요한 값만 입력받는다.

| 부재 | 사용자가 입력하는 값 | 자동으로 정해지는 값 |
|---|---|---|
| 모듈 | 가로·세로 | 높이 = 층고 설정값 |
| 바닥패널 | 가로·세로 | 두께 고정 |
| 벽체패널 | 벽 길이 | 두께 고정, 높이 = 층고 설정값 (바닥패널과 합칠지 선택) |
| 캔틸레버보 | 돌출 길이 | 단면 고정 |
| 캔틸레버슬래브 | 돌출 길이 | 폭은 붙는 부모 변 길이로 자동, 두께 고정 |
| 중간보 | (입력 없음) | 옆 기둥/바깥 보까지 길이 자동 |
| 중간기둥 | 높이 | 단면 고정 |
| 수직 3층 모듈 | (입력 없음) | 가로·세로 = 층고 설정값, 높이 = 층고×3 + 40mm |
| RC 코어 | 벽 길이·두께 | 높이 = 층고 설정값, 모든 층 슬래브는 버튼으로 자동 생성 |

높이 관련 값은 부재마다 따로 입력하지 않는다. 별도의 "층고 설정"칸에서 층고를 한 번 정하면, 모듈·벽체패널·RC 코어의 높이와 수직 3층 모듈의 치수가 그 값에 맞춰 자동으로 결정된다. (예: 수직 3층 모듈은 높이가 층고의 3배에 40mm를 더한 값, 가로·세로는 층고와 같은 값이 된다.)

현재는 사용자가 치수를 직접 입력하지만, 추후 대표 예시 치수를 제공해 선택만으로 배치할 수 있게 보강할 예정이다. 중간보·중간기둥처럼 이해가 어려운 부재에는 도움말 설명을 함께 제공해 이해를 돕는다. 보가 들어가는 부재(모듈·바닥패널·수직3층모듈·벽패널)는 보 단면을 **각형강관·H형강 중 선택**할 수 있고(부재 단위, 종속 부재·합체 벽패널은 부모를 따라감, 기둥은 항상 각형강관), 선택에 따라 화면에 각형강관 또는 H형강(I자) 단면으로 표시된다. 실제 단면 크기는 구조해석을 거쳐 강종별 카탈로그(각형강관/H형강)에서 최종 결정된다.

또한 모든 모듈에는 4면 비내력 벽이 자동으로 생긴다. 이 벽은 벽패널의 채움 패널처럼 하중·물량에는 들어가지 않는 순수 표현용 벽(두께 100mm)으로, 아래 개구부 기능으로 창을 뚫거나 한 면을 통째로 열 수 있다.

- 사용자가 세대 내부 칸막이벽(내벽)을 직접 배치할 수 있다. ✅ 구현 완료
  - 내벽은 벽패널의 채움 패널 형태(기둥·보 없는 벽체)인 **독립 부재**로, 두께는 100mm(벽패널 채움과 동일), 높이는 올려놓는 부모에 맞춰 **위아래가 막히게 자동**으로 정해진다 — 부모가 모듈이면 모듈 높이(모듈 바닥~천장), 바닥패널·캔틸레버슬래브면 그 층 높이(슬래브 윗면~윗층 바닥).
  - 배치 방법은 기존 부재와 비슷하다 — 먼저 **부모(모듈·바닥패널·캔틸레버슬래브)를 고른 뒤** 벽 길이를 입력하면 벽 한 장이 고스트로 마우스를 따라오고, **직각(0/90/180/270°)으로 방향을 돌려** 부모 모서리·기둥에 맞춰(안 되면 100mm 격자) 클릭으로 놓는다.
  - 부모에 **종속**되어 부모를 옮기면 함께 따라가고, 부모가 여러 층이면 각 층에 자동으로 같이 생긴다(캔틸레버슬래브에 놓으면 그 슬래브가 속한 모듈/패널 그룹에 종속된다).
  - 놓은 뒤에는 **이동·복사·회전·삭제·되돌리기**가 모두 되고, 내벽에도 **개구부(문구멍 등)** 를 낼 수 있다.
  - 내벽 배치는 실 배치와 함께 **"실 및 벽 배치 모드"** 영역에서 이뤄진다("실 그리기"·"벽 배치(내벽)" 버튼으로 구분). "벽 배치"를 누르면 부재 배치 머신을 재사용하므로 자동으로 부재 편집 모드로 전환된다.
  - 모듈 정의 탭에서도 정의 안에 내벽을 포함해 저장·불러오기할 수 있다(단일층 1세트로 저장).
  - 표현은 **반투명**이며, 기존 모듈 자동 4면 벽과 벽패널의 채움 패널도 함께 반투명으로 통일된다(기둥·보는 불투명 유지). 하중·물량에는 들어가지 않는다(순수 표현용) — 반영 여부는 추후 구조해석 단계에서 노드 추가와 함께 검토한다.

**(2) 가운데 — 2D 평면 배치 화면**

선택한 부재의 필요한 값을 입력한 뒤 화면을 클릭해 위치를 확정한다. 배치 과정에는 시공성을 고려한 자동 보정이 들어간다.

- 자동 정렬·간격: 부재를 놓으면 격자와 인접 부재 모서리에 자동으로 맞춰지고, 부재 사이에 20mm의 시공 간격이 자동으로 확보된다. (사용자가 따로 맞추지 않아도 적용되며, 필요하면 직접 수정 가능)
- 층간 자동 복사: 한 층에 부재를 하나 놓으면 위층 같은 자리에도 같은 부재가 자동으로 생긴다.
- 중간보 자동 짝 생성: 바닥에 보를 놓으면 같은 모듈 천장에도 보가 자동으로 생기고, 직교 방향 반대편 보까지 자동으로 이어진다.
- 종속(부모-자식) 관계: 벽체패널·캔틸레버보·캔틸레버슬래브·중간보·중간기둥은 모듈이나 바닥패널에 종속시킬 수 있다. 부모를 옮기거나 지우면 종속된 부재가 함께 따라간다.
- 편집: 배치된 부재는 키 조작으로 복사·이동·회전·삭제할 수 있고, 직전 작업을 되돌릴 수 있다.
- 층수: 수직 3층 모듈을 고려해 3의 배수 단위로 층수를 정한다. 층수를 바꾸면 종속 부재까지 포함해 전체가 다시 생성된다.
- 저장·불러오기: 배치한 결과를 파일로 저장하고 다시 불러올 수 있다.

**(3) 우측 — 속성 패널**

화면에서 부재를 선택하면 그 부재의 종류, 위치 좌표, 크기, 종속 여부(부모 또는 자식인지) 등의 정보를 보여준다. (구조해석에서 쓰는 보 중심선 좌표 안내도 함께 표시)

**(4) 3D 화면**

2D 화면에서 만든 한 개 층의 평면이, 설정한 층수만큼 쌓인 건물 전체로 입체화되어 보인다.

### 모듈 정의 탭 고유 기능

- **독립 작업공간**: 배치 설계 탭과 완전히 분리된 자체 작업공간(자체 3D·2D 화면)에서 컴포넌트를 만든다.
- **단일 층 1세트로 정의**: 정의는 "건물 층 복제 없는 1개 인스턴스"로 저장된다 — 일반 모듈은 1개, 수직 3층 모듈은 그 자체로 3층 높이 1개. (배치 탭에서 가져올 때 그 탭 층수만큼 복제된다.) 그래서 정의 탭에는 층수 입력이 없다.
- **정의 라이브러리(우측)**: 현재 작업공간을 이름 붙여 저장하거나, 목록에서 골라 불러오고, 새로 만들고, 삭제한다. 라이브러리는 파일(json)로 영구 저장되어 프로그램을 다시 켜도 유지된다. 저장은 하나의 루트 묶음(모듈/패널/수직모듈 + 그 종속 부재·개구부·실)만 허용하며, 종속 부재만 단독으로 정의할 수는 없다.
- **건물 파일에서 불러오기**: 배치 설계·접합부 설계 탭에서 저장한 건물 파일(접합 변경 포함, 같은 양식)을 정의 탭 작업공간으로 직접 열 수 있다. 불러온 건물에서 필요 없는 부재를 지우고 남긴 한 부재(모듈 등)를 다시 정의로 저장하는 식으로 재활용한다.
- (향후 계획) 정의 시 보를 각형강관/H형강 중 선택, 대표 표준모델(LH 평형별 등) 프리셋 내장.

### 배치 설계 탭 고유 기능

- **정의 가져오기 배치**: 팔레트 버튼이나 숫자키로 부재 타입을 고르면, 그 타입으로 저장된 정의가 있을 때 "새로 만들기 / 가져오기"를 묻는다. 가져오기를 고르면 정의 전체(부재·개구부·실)가 반투명 그룹 고스트로 마우스를 따라오고, R로 90° 회전·V로 기준점(루트 모서리)을 바꾼 뒤 클릭으로 배치한다. 배치하면 배치 탭의 층수만큼 자동으로 층이 복제된다(되돌리기 가능).
- **실(공간) 배치**: 2D에서 점을 찍어 폴리곤으로 실 영역을 그리고 용도를 지정한다. 용도 목록은 KDS 41 12 00(건축물 설계하중)의 실 용도(거실·침실·주방·욕실·발코니·복도·계단 등)에 맞춰 두어, 추후 하중 정의와 자연스럽게 이어진다. 실은 2D 색면+용도 라벨과 3D 슬래브 위 반투명 색면으로 표시되며, 선택해 이동·복사·회전·삭제할 수 있다.
- **개구부**: 벽·슬래브에 사각 개구부를 실제로 뚫는다(메시 관통). 개구부 모드에서 크기를 넣고 반투명 고스트를 대상 면 위에 올려 R(가로/세로)·V(기준점)·클릭으로 배치하며, 배치된 개구부는 이동·복사·삭제·되돌리기가 된다. 문/창 종류 구분 없이 크기만 입력하며, 한 면의 채움을 통째로 덮으면 그 면 벽이 사라진다(기둥·보는 유지).
- **하중 정의**: 실 용도별 활하중(KDS 41 12 00)과 마감 등 부가 고정하중(SDL)을 정의해 구조해석에 반영한다. ✅ 구현 완료
  - 실 속성 패널에서 활하중·부가하중 칸을 제공한다 — 용도를 고르면 KDS·표준 기본값이 자동으로 채워지고, 사용자가 값을 바꾸면 그 값으로 덮어쓴다.
  - 한 바닥 슬래브에 여러 실이 걸치면 **면적 비율로 가중 평균**해 그 슬래브에 적용하고, 실을 안 그린 빈 영역은 주거 기본값(2.0)으로 채운다.
  - **옥상(지붕)은 자동 검출**한다 — 최상단 바닥패널 레벨을 옥상으로 보고(코어 옥탑 슬래브는 제외) 지붕 활하중(1.0)과 옥상 마감 부가하중을 강제 적용한다. 사용자는 1층만 배치하고 반복 복제되므로 옥상을 직접 지정하지 않는다.
  - **벽 자중**도 반영한다 — 모듈 자동 4면 벽과 벽패널 채움은 외부/내부를 자동 판별(외벽 55, 내벽 30 kg/m² 가중평균)해 그 변의 보에 선하중으로, 세대 내부 칸막이(내벽)는 30 kg/m²로 올라간 바닥 슬래브에 면적평균 부가하중으로 더한다. 개구부가 있으면 그 부피만큼 무게를 차감한다. 모두 노드 추가 없이 둘레 보 등가하중으로 처리한다.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 사용자가 배치한(또는 정의에서 가져온) 각 부재의 종류, 필요한 치수, 평면 위치, 층수. 그리고 실·개구부.
- 내부 처리: 자동 정렬, 20mm 시공 간격, 층간 복사, 부모-자식 종속 관계 연결, 정의 가져오기 시 층 복제, 개구부 메시 관통.
- 아웃풋(다음 탭으로 전달): 완성된 배치 결과 = 각 부재의 종류·위치 좌표(mm)·치수·회전·소속 층·부모-자식 관계 + 개구부 + 실 묶음. 이 묶음 전체가 접합부 설계 탭의 입력이 된다. (실·개구부·비내력 벽은 현재 시각/데이터로만 다루며, 구조해석·물량 반영은 향후 하중·단면 단계에서.)

## 2. 접합부 설계 탭

**이 탭에서 하는 일**

디자인 탭의 배치 결과를, 구조해석이 이해할 수 있는 골조 모델(선 요소 + 절점 + 접합부)으로 변환하고, 그 변환 결과를 와이어프레임으로 확인·점검하는 단계다. 여기서는 해석을 직접 돌리지 않고 모델만 만들어 미리 보여준다. (실제 해석은 다음 구조해석 탭에서 수행)

**화면 구성**

- 가운데: 3D 와이어프레임 — 부재를 보·기둥·트러스 선과 절점으로 추상화해 표시
- 우측: 접합부 설계 패널

**(1) 가운데 — 와이어프레임 변환 결과**

- 디자인 탭의 각 부재가 선 요소(보·기둥)와 절점으로 바뀐다.
- RC 코어벽은 비선형 휨·전단 거동을 표현하는 **MVLEM 요소**로 변환된다. 와이어프레임에서는 코어벽 단면이 **fiber(경계요소+웹) 셀로 나뉜 사각형 벽**으로 표시되어, 실제 단면 분할을 눈으로 확인할 수 있다.
- 부재가 서로 맞닿는 곳마다 접합부가 자동으로 추출되어 색이 다른 선으로 표시된다. 자동으로 찾아내는 접합부 종류는 다음과 같다.
  - 모듈 ↔ 모듈 (수평으로 붙는 경우 / 위아래로 쌓이는 경우)
  - 바닥패널 ↔ 모듈, 바닥패널 ↔ 바닥패널
  - 벽체패널 ↔ 바닥, 벽체패널 ↔ 모듈, 벽체패널 ↔ 벽체패널, 벽체패널 ↔ 캔틸레버
  - RC 코어 결합
- 각 접합부는 맞닿는 두 부재의 절점을 묶어 연결하는 방식으로 표현되며, 강체 연결과 다이어프램(같은 바닥이 한 덩어리처럼 거동) 정보도 함께 만들어진다.

**(2) 우측 — 접합부 설계 패널**

- 규칙 범례: 어떤 종류의 접합부가 있는지 색으로 구분해 보여준다. 종류별로 켜고 끄며 화면에서 확인할 수 있다. (시각화만 바뀌고 실제 접합은 유지)
- 다이어프램 시각화: 같은 바닥(모듈·바닥패널·코어슬래브)이 하나의 강체처럼 거동하는 다이어프램을 화면에 표시한다.
- **접합부 직접 편집** ✅ 구현 완료 — 자동 추출된 접합을 3D에서 클릭해 골라 강접(강결)/핀(힌지)으로 바꾸거나 제거하고, 새 접합을 직접 추가할 수 있다.
  - 변경·제거: 접합을 클릭하면 강조되고 버튼으로 성질(강접/핀)을 바꾸거나 없앤다. 같은 자리에 종류가 다른 수직 접합이 겹쳐 있어도 종류별로 구분해 그 종류에만 적용된다(범례 켜고 끄기와 연동).
  - 다층 일괄 / 이 층만: 한 층의 접합을 편집하면 같은 평면 위치의 모든 층에 자동 적용된다. "이 층만" 옵션을 켜면 클릭한 그 층에만 적용한다.
  - 신규 접합 추가: 부재(보) 모서리 위 두 점을 클릭해 새 접합을 만든다. 점 선택 시 미리보기 점·연결선·스냅 후보가 보이고 핀/강접을 고른다. 점 자리에 기존 절점이 없으면 보를 분할해 절점을 새로 만들어 잇고, 스냅한 점이 기존 꼭지점인지 보 위 임의 점인지가 실제 연결 방식에 그대로 반영된다.
  - 직각(ㄴ자) 결합 추가: 평면·높이가 모두 다른 두 점을 중간 가교 절점을 거쳐 수직+수평 두 단계로 잇는다. 직각·추가 접합은 한 묶음으로 선택·제거되며, 제거 시 허공에 남는 가교 절점도 함께 정리된다.
  - 안전·초기화: 제거로 구조가 불안정(메커니즘)해질 수 있으면 즉시 경고한다(차단은 안 함). "모든 접합 변경 초기화" 버튼으로 자동 규칙 상태로 되돌린다.
  - 저장: 이 탭의 "디자인 + 접합 변경 저장" 버튼으로 현재 건물과 접합 변경을 **기존 건물 저장과 같은 양식(같은 JSON 파일)** 으로 저장한다(접합 변경이 부재·실·개구부와 함께 들어간다). 불러오기는 배치 설계 탭에서 한다.
  - 불러오기 정책: 저장한 파일을 배치 설계 탭에서 불러온 뒤 이 탭으로 오면 "저장된 접합 사용 / 새 자동 계산"을 묻고, 디자인이 바뀌었으면 자동 초기화한다. 변경 결과는 구조해석 5개 하중조합에 그대로 반영된다.
- (향후 계획) 합성거동 옵션: 위층 모듈의 바닥보와 아래층 모듈의 천장보가 하나의 합성 단면처럼 거동한다고 보는 옵션이다. 사용자가 접합부 설계 탭에서 직접 묶을 수도 있고, 구조해석 결과를 바탕으로 강재 단면 크기를 최대한 같게 유지하도록 프로그램이 몇 군데를 알아서 합성 처리해 주는 옵션도 둘 예정이다.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 디자인 탭의 배치 결과(부재 종류·위치·치수·층·부모-자식 관계) + 사용자의 접합부 편집(강접/핀/제거/추가) 정보.
- 내부 처리: 선 요소+절점 골조 생성 → 코어벽의 MVLEM 요소 변환 → 맞닿는 부재의 접합부 자동 추출 → 다이어프램 구성 → 사용자 접합 편집 반영(자유도 묶음 변경·신규 접합 등록, 같은 위치 모든 층 일괄).
- 아웃풋(다음 탭으로 전달): 사용자 편집까지 반영된 골조 해석 모델. 이 모델이 구조해석 탭의 입력이 되어 실제 해석이 수행된다.

**(향후 계획이 적용되면)**

- 합성거동 옵션: 사용자가 지정한 곳 + 단면 크기를 통일하기 위해 프로그램이 자동으로 더한 곳에 합성 단면을 반영해, 더 실제에 가까운 구조해석이 가능해진다.

## 3. 구조해석 탭

**이 탭에서 하는 일**

접합부 설계 탭에서 만든 골조 모델에 하중을 걸어 실제로 구조해석을 수행하고, 그 결과(변형·부재력·응력비)를 보여주는 단계다. 해석 엔진은 OpenSeesPy(오픈시스)를 사용한다.

**화면 구성**

- 좌측: 3D 변형형상 뷰 — 해석 결과를 색으로 입힌 와이어프레임
- 우측: 해석 결과 패널

**(1) 거는 하중 — 무엇을 작용시키는가**

- 사하중(자중, D): 모델에서 그대로 뽑아낸다. 강재 부재의 자중과 슬래브(콘크리트, 두께 150mm)의 자중을 합산한다.
- 활하중(L): 슬래브 바닥 면적에 작용하며, 슬래브가 1방향인지 2방향인지 판별해 둘레 보로 자동 분배한다. 배치 탭에서 정의한 실 용도별 활하중(KDS 41 12 00)을 슬래브별 면적가중 평균으로 적용하고, 옥상은 자동 검출해 지붕 활하중(1.0)을 적용한다.
- 횡하중: 등가정적 지진(X·Y 방향)과 풍하중(X·Y 방향).

- 부가 고정하중(SDL): 디자인 탭에서 실 용도별로 정의한 마감·천장 등 부가 고정하중을 슬래브 사하중에 더한다(면적가중). 모듈 4면 벽·벽패널 채움 자중은 변의 보에 선하중으로, 세대 내부 칸막이(내벽) 자중은 올라간 슬래브에 면적평균으로 반영한다(외부/내부 55·30 kg/m² 자동판별, 개구부 차감). (하중 정의는 디자인 탭, 받아서 푸는 것은 구조해석 탭)

**(2) 푸는 하중조합 — 5개 케이스**

아래 5개 하중조합을 각각 해석한다. (D=사하중, L=활하중, E=지진, W=풍)

- 중력 : 1.2D + 1.6L
- 지진 X : 1.2D + 1.0L + 1.0Ex
- 지진 Y : 1.2D + 1.0L + 1.0Ey
- 풍 X : 1.2D + 1.0L + 1.0Wx
- 풍 Y : 1.2D + 1.0L + 1.0Wy
- 지배조합 : 위 케이스들을 아우르는 envelope(가장 불리한 값)

해석은 기본 단면(200×200 각형강관)으로 수행하며, 최종 단면 결정은 다음 물량 탭에서 한다.

**(3) 결과 — 무엇이 나오는가**

- 변형형상: 절점 변위를 입체로 표시
- 부재별 내부력: 길이, 축력(N), 전단력(V), 휨모멘트(M)
- 응력비 컨투어: 축력비(N/Pn), 휨모멘트비(M/Mn), 조합응력비, 변위를 색으로 구분해 표시
- 우측 패널: 하중조합 선택, 컨투어 선택, 결과 요약, 부재별 내부력 표 (부재를 층·모듈·역할로 묶어 보여주고, 행을 클릭하면 3D에서 강조)

**(4) 코어벽 비선형 분석 (RC 코어 전용)**

일반 부재는 선형 등가정적 해석이지만, RC 코어벽은 MVLEM 요소라 비선형 거동을 따로 분석할 수 있다. 우측 해석 결과 패널의 버튼으로 실행한다.

- **역량곡선(pushover)**: 전체 건물을 X·Y 방향으로 점차 밀어 밑면전단-상부변위 곡선(건물이 횡력에 견디는 능력)을 구한다. 코어벽 콘크리트·철근의 비선형 항복, 축력 효과, 고층 P-Delta(2차효과)가 반영된다.
- **코어 응력 다이어그램 + 3D 면 컨투어**: 코어벽 단면의 fiber별 콘크리트·철근 응력을 막대그래프로 보고, 3D 화면에서 코어벽 면을 응력비(D/C)에 따라 색칠(상용 프로그램 느낌)해 한눈에 본다.
- **슬래브-벽체 연결부 검토**: 각 층 슬래브 격막이 코어벽으로 전달하는 힘(층별)에 대해 연결부 전단강도(콘크리트구조 모델링지침 식 8-1~8-6)를 자동 검토해 안전/위험을 표로 보여준다.
- **코어 철근 입력**: 코어슬래브를 선택하면 우측 패널에서 코어벽 철근비(경계·웹)·콘크리트/철근 강도와 슬래브 연결부 철근을 직접(또는 배근 환산으로) 입력해 위 분석에 반영한다.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 접합부 설계 탭의 골조 모델 + 하중(자중·활하중·지진·풍).
- 내부 처리: 하중 자동 산정·분배 → 하중조합별 정적 해석.
- 아웃풋(다음 탭으로 전달): 부재별 내부력(축력·전단·휨모멘트와 부재 길이). 이것만 물량 탭으로 넘어가 부재 단면을 결정하는 입력이 된다. 변형형상과 응력비는 이 탭에서 사용자가 검토하도록 보여주는 결과이며, 물량 탭으로 전달되지는 않는다. (물량 탭은 받은 내부력으로 후보 단면마다 응력비를 다시 계산한다.)

- (향후 계획) 현재 5개 하중조합 외에 KDS 41 12 00(건축물 설계하중)의 추가 하중조합 (자중 단독 1.4D, 전도 방지용 0.9D 조합, 설하중 동시 조합 등)도 지원할 예정이다.
- (향후 계획) 코어 단순화 — RC 코어 거동을 더 단순한 계산 모델로 치환해 해석을 가볍게 한다.
- (향후 계획) 결과 검증 — 프로그램의 구조해석 결과를 실제(상용 프로그램 등) 해석 결과와 비교해 정확도를 확인한다.

## 4. 단면 설계 탭

**이 탭에서 하는 일**

구조해석 결과(부재별 단면력)를 바탕으로 각 부재의 강재 단면을 자동으로 결정(수렴)하고, 필요하면 사용자가 직접 단면을 바꿀 수 있는 단계다. 여기서 정해진 단면이 물량·운송의 입력이 된다.

**화면 구성**

- 좌측: 3D 뷰 — 부재별 응력비를 5단계 색상(빨·주·초·하·파)으로 표시. 단면이 바뀌면 색이 즉시 갱신된다.
- 우측: 단면 설계 패널

**(1) 단면 자동 결정 (수렴)**

- 표준 단면 카탈로그(KS D 3568 각형강관, 75×75×3.2 ~ 400×400×16)에서 고른다. 보를 H형강으로 고른 부재는 H형강 카탈로그(KS D 3502)에서 선정한다.
- 강재 재질 SS275(KS D 3503), 설계 기준 KDS 41 31 00(건축물 강구조 설계기준) 한계상태설계(LRFD).
- 검토 항목: 축력(좌굴 포함)·휨·전단·조합(축력+휨)·처짐. (처짐 한계 — 일반 보 L/360, 캔틸레버 보 L/180)
- 각 부재의 응력비(요구/허용)를 계산해, 1.0 이하인 가장 가벼운 단면을 채택한다. 어떤 단면으로도 만족하지 못하면 가장 큰 단면을 강제로 쓰고 NG로 경고한다.
- 지배조합(5개 케이스 중 가장 가혹한 단면력) 기준으로 안전하게 설계한다.
- 탭에 처음 들어오면 기본 옵션(전체·한 단면·층분할 없음)으로 자동 수렴하고, 옵션을 바꿔 [적용(재수렴)] 버튼을 누르면 다시 계산한다. 수렴 후 "NG 0개 / 변위비 OK·NG" 같은 요약을 보여준다.

**(2) 단면 공유·구분 옵션 — 같은 단면을 어디까지 묶을지**

세 가지 축으로 고른다.

- 공유 범위: 건물 전체 한 단면 / 같은 크기 타입끼리 / 완전히 동일한 타입끼리
- 부재 구분: 전부 한 단면 / 기둥·보 두 그룹 / 기둥·천장보·바닥보 세 그룹
- 기둥 층구간 분할: 기둥을 높이에 따라 몇 구간으로 나눠 다른 단면을 쓸지 (1=분할 없음)

그룹의 단면은 그룹 안에서 가장 불리한(최대 응력비) 부재를 기준으로 정한다. 고른 선택을 자연어로 요약("건물 전체에서 기둥과 보 단위로 통일, 기둥은 2구간 분할")해 보여준다.

**(3) 수동 단면 변경**

자동 결과가 마음에 안 들면 기둥·천장보·바닥보별 콤보박스로 구체적 단면을 직접 지정할 수 있다(또는 "(자동)" 유지). 바꾸면 즉시 적용되어 좌측 응력비 색과 물량이 다시 계산된다. 대상은 선택한 컴포넌트 하나 또는 같은 타입 전체다.

**(4) 타입 목록 + 컴포넌트 3D**

수렴 결과를 타입별로 정리해(타입명·채택 단면·최대 응력비·OK/NG) 목록으로 보여준다. 한 타입을 고르면 좌측 응력비 색이 그 타입으로 강조되고, 우측에 그 타입 대표 부재의 3D 형상(강재 색별)이 표시된다.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 구조해석 결과(부재별 단면력) + 표준 단면 카탈로그 + 설계 기준 + 사용자의 단면 옵션·수동 변경.
- 내부 처리: 응력 검토 → 가장 가벼운 합격 단면 선택 → 옵션별 그룹 통일 → 수동 변경 반영.
- 아웃풋(다음 탭으로 전달): 부재별 확정 단면. 이 단면이 물량 탭(중량·본수 산출)과 운송 탭(무게·치수)의 입력이 된다.

## 5. 물량 탭

**이 탭에서 하는 일**

단면 설계 탭에서 확정된 단면을 바탕으로 물량(강재 중량·본수·길이, 콘크리트 부피)을 산출하고, 자재 단가를 곱해 재료비를 계산하는 단계다.

**화면 구성**

- 중앙: 물량 3D 도식 — 부재를 타입별로 보여주며, 타입을 클릭하면 우측 표의 해당 행이 선택된다.
- 우측: 물량산출 패널

**(1) 물량 산출 대상**

- 강재: 톤·본수·길이 (단면과 길이가 같으면 한 종류로 집계, 합계 행 포함). 각형강관/H형강은 강종별로 나눠 집계한다.
- 슬래브·바닥패널: 콘크리트 부피 + 철근 비율
- 벽패널: 강재 프레임만 / RC 코어는 산출에서 제외

우측 패널에는 타입별 강재 본수표, 전체 강재 본수표(층별 합계), 슬래브·매립재료 수량 표가 표시된다.

**(2) 자재비 (재료비)**

산출된 물량에 자재 단가를 곱해 재료비를 산출·표시한다. 단가는 별도 단가 DB(json, 공인 자료 출처를 함께 기록)에서 읽어 오며, 사용자가 코드를 건드리지 않고 갱신할 수 있다.

- 강재 = 강재 중량 × 각형강관/H형강 단가(원/ton)
- 슬래브 = 데크 면적 × 데크플레이트 단가(원/㎡) + 콘크리트 부피 × 레미콘 단가(원/㎥). 철근은 데크 단가에 포함되어 별도로 계산하지 않는다.
- RC 코어 콘크리트·철근은 자재비에서 제외한다.

강재 본수표에 금액 열이 추가되고, 그 아래에 항목별 물량·단가·금액과 합계를 보여주는 자재비 총액표가 표시된다. 노무비·경비·공기 비용은 공정표·종합 단계에서 합산한다.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 단면 설계 탭의 부재별 단면 + 배치 치수 + 단가 DB.
- 내부 처리: 단면·길이별 집계 → 물량 합산 → 단가 적용.
- 아웃풋(다음 탭으로 전달): 물량(강재 중량·본수, 콘크리트 부피) + 자재비. 이 결과가 운송 탭(중량·치수)과 종합 탭(자재비·물량 요약)의 입력이 된다.

- (향후 계획) 산출 방법 검증 — 물량 산출 방식이 맞는지(정합성) 점검·보완한다.

## 6. 운송 탭

**이 탭에서 하는 일**

설계된 건물을 실제 트럭으로 현장까지 어떻게 나를지 계획하는 단계다. 각 부재(모듈·패널)의 무게·치수를 산정하고, 도로 법규 한도 안에서 트럭에 나눠 실어 회차 수와 운임을 계산한다.

**처리 흐름 — 8단계**

상단에 진행 상태를 8단계 인디케이터로 보여준다.

1. 해석 : 구조해석 결과를 가져온다
2. 단면 : 물량 탭에서 결정된 부재 단면을 가져온다
3. 분할 : 운송 단위(모듈/패널)로 나눈다
4. 분류 : 부재를 종류별로 분류하고, 비내력벽을 자동 판별한다
5. 변환 : 운송용 객체로 바꾸며 무게·치수를 산정한다 (좌표 자동 정렬 — 긴 쪽을 길이, 짧은 쪽을 폭으로 자동 회전. 단순 wall 은 벽 길이/높이 의미 보존 위해 제외)
6. 패킹 : Best-Fit 자유 배치로 트럭에 나눠 실으며 도로 한도 초과를 검사한다 (다중 시드 54 후보 + VND 국소 탐색)
7. 운임 : 회차별·총 운임을 산정한다
8. 도식 : 적재 모습을 Three.js 기반 입체 3D 도식으로 시각화한다

**화면 구성 (3 단 분할)**

운송 탭은 *좌·중·우 3 단 분할* 로 구성:

- **좌측 입력 패널** (접기 토글 가능): 트럭 카탈로그 관리 버튼 · 상태 표시 · 옵션 (운임 방식/단가/캔틸레버/실행 버튼) · 참고자료
- **중앙 3D 적재 도식** (Three.js + OrbitControls + CSS2DRenderer): 트럭 + 적재 화물의 실제 형상 입체 표시. 어두운 배경 + 그림자 + 차종별 캐빈·바퀴.
- **우측 결과 패널**: 결과 요약 5카드 · 결과 서브탭 (회차표/적재율/경제성) · 회차별 트럭 변경 표 · 진단 패널

상단의 *◀ 입력 패널 접기* 버튼으로 좌측을 collapse 가능. 좌·우 splitter 핸들 드래그로 폭 수동 조절도 가능.

**(1) 옵션 — 무엇을 입력하는가**

운송 거리(편도), 운임 방식·단가, 비내력벽 단위중량은 프로젝트 설정에서 받아 온다. 운임은 항상 왕복(편도×2) 기준으로 계산한다. 이 탭에서는 다음을 다룬다.

- 캔틸레버 처리: 항상 부모 화물에 기하 종속(같은 회차 운송)으로 일원화 (2026-05-27 옵션 제거). 배치 단계에서 모듈·바닥패널에 종속된 캔틸레버보·캔틸레버슬래브는 부모와 분리되지 않고 같은 트럭에 같이 실린다.
- 비내력벽 자동판별: 벽이 외부면인지 내부면인지를 패널 기준으로 자동 판단해, 프로젝트 설정의 면별 단위중량(외부 55 / 내부 30 kg/m²)을 적용한다. (외부/내부를 가르며 면을 훑는 격자 크기는 프로그램 내부 고정값)
- 자동 재계산 ON/OFF + [운송 계산 실행] 버튼

적재 간격(수직 갭 · 수평 갭 · 트럭 양끝 여유 · 폭 여유)은 사용자 입력이 아니라 내장 고정값(차례로 100 / 100 / 200 / 200 mm)으로 둔다. 수직 갭은 적층 패널 위아래, 수평 갭은 한 줄 패널 옆, 양끝 여유는 트럭 앞뒤 결박 공간이다. 폭 여유 200은 화물이 트럭 폭보다 양쪽으로 각 200mm 튀어나와도 허용한다는 뜻(예: 3000mm 트럭에 3400mm 패널)으로, 폭 허용은 "트럭 폭 + 양쪽 200"과 현장 폭 제한 중 작은 값이다(모듈·패널 모두). "광폭검토 필요" 표시는 폐지했고, 폭 양쪽 200 튀어나옴은 도식에도 그대로 그려진다.

운임은 세 방식 중 하나로 낸다. ① 요금표 방식: 편도 거리를 넣으면 트럭 톤수에 맞는 내장 요금표(왕복거리 기준)에서 회차당 요금을 불러와 합산한다. ② 트레일러별 km당 단가 방식: 차종별 원/km를 직접 넣어 "단가 × 왕복거리 × 회차"로 합산한다. ③ 트레일러별 1회 고정비 방식: 차종별 1회 운송비(거리 무관)를 직접 넣어 회차마다 그 종류의 고정비를 더한다(저상·광폭·A-frame 종류별 입력 + 일괄 적용 버튼). (시간단가·주행시간 방식은 쓰지 않는다.)

도로 등급 선택 입력창은 제거하고, 대신 프로젝트 설정에서 "현장 운송 제한"(무게 · 폭 · 높이)을 직접 받는다. 무게는 차체 자체 무게 + 화물 무게를 합한 총중량이 이 한도를 넘지 않아야 하고(트럭 적재능력과는 별개 검사), 폭은 화물 폭, 높이는 지면에서 화물 꼭대기까지의 총높이(차량 적재면 높이 포함) 기준이다. 길이는 현장 제한을 두지 않고 트럭 적재함 길이로만 본다. 각 항목은 "해당없음"을 선택하면 그 항목 제한을 적용하지 않는다(프리패스). 프로젝트 설정에서 값을 바꾸고 확인을 누르면 운송 탭 표시가 즉시 갱신된다(탭 전환 불필요). 운송 탭의 읽기전용 공통값(운송 거리 · 운임 · 단위중량 · 현장 제한)은 옵션 패널에 회색으로 표시한다.

**(2) 무게·치수 산정 → 트럭 패킹**

- 모듈 무게 = 강재 프레임(기둥·보 + 중간기둥·중간보) + 슬래브 + 비내력벽 합산
- 패널 무게 = 강재 프레임(각형강관 또는 H형강 — 디자인에서 고른 단면 그대로 반영) + 콘크리트(두께는 현재 고정값)
- **신규 패커 (2026-05-26 ~ 27)**: 기존 FFD 단일 그리디 → *Best-Fit 자유 배치 + 다중 시드 54 후보 + VND 5 종 국소 탐색 + 무게중심 시각 보정* 으로 전면 교체. 검증세트 기준 평균 비용 절감 +35 % 달성 (회귀 0 건).
- 화물 자세 차원: 벽 패널을 *눕힘 (LYING)* / *세움 (STANDING, A-frame 트럭 전용)* 두 자세로 평가해 더 효율적인 적재 선택.
- 모듈 4.5 m 합산: *각 모듈 길이 ≤ 4.5 m* 인 두 모듈은 한 트럭에 옆으로 나란히 합산 적재 (3 개 이상 금지).
- 종속 floor (L자·ㄷ자·3면·4면 + 부분벽): 안쪽 슬롯 자동 적층 + 옆자리 자유 배치 둘 다 평가 → 비용 최저 안 채택.
- 비용 모드 3 종 (회차당 1회 고정비 / 트럭종류별 1회 고정비 / 거리 × km단가) 동일 패커 위에서 모두 동작. 모드 변경에 따라 트럭 종류 선택 비율이 자동 조정.
- 트럭 카탈로그(저상·광폭·A-frame 등)에 맞춰 회차를 나누고, 트럭·현장 제한을 초과하는 항목은 운송 불가로 표시한다(사유는 "가장 적합한 후보 트럭"의 구체 위반 수치 — 예: "총중량 초과(현장): 차체 14000 + 화물 18000 = 32000kg > 한도 25000kg").

**(3) 결과 — 무엇이 나오는가**

- 요약 5카드: 모듈 회차 / 패널 회차 / 총 회차 / 평균 적재량(중량 기준) / 전체 운송 거리(모든 회차 합)
- 회차표: 회차별 트럭과 실린 부재 (행 더블클릭 = 3D 부재 강조 / 행 단일 클릭 = 3D 도식 해당 트럭 강조 + 카메라 평행이동).
- 적재율 차트 / 경제성 표 (운임 명세)
- **3D 적재 도식 (메인 화면)**: Three.js 기반 입체 도식. 화물을 단순 박스가 아닌 **실제 부재 단위** 로 그린다(2026-05-27, Phase 3·3-fix). 모듈은 기둥 4·하부보 4·상부보 4·슬래브·4면 벽채움 + 종속된 캔틸레버·중간보·중간기둥까지 모두 분리되어 색별로 표시되고, 종속 floor 의 wall_segments 도 실제 위치에 위로 솟는 직육면체로 표현. 회전·앵커 정합 — 부모의 회전(0/90/180/270°)·앵커(0~3) 가 다르더라도 종속 부재가 정확히 같이 따라간다. 차종별 캐빈·바퀴 + 차종 라벨. 시점 프리셋 (Iso/Top/Side/Front/Fit) + OrbitControls 마우스 회전·이동·줌. 어두운 시네마틱 배경 + 그림자.
- **동일 결과 회차 그룹화**: 트럭 종류·치수 + 화물 종류·자세가 *완전 동일* 한 회차들은 *폭 방향 (사이드뷰 화면 깊이) 으로 겹쳐* 자동 배치. 라벨은 그룹별 1 개로 통합 ("#2~4 · 저상25t · 3대 동일" 식).
- **양방향 동기화**: 회차표 ↔ 경제성표 ↔ 3D 트럭 클릭이 모두 같은 hub 통과 — 어디서 클릭해도 *세 영역 모두 동기 강조*. 강조 시 선택 외 회차들은 반투명, 선택 회차만 또렷 + 빨간 outline.
- **카메라 평행이동**: 회차 클릭 시 그 트럭이 화면 *밖* 일 때만 부드럽게 (350 ms easeOutCubic) X·Z 평행이동. *화면 안* 이면 카메라 그대로 + 강조만 변경.
- 회차별 트럭 변경 표: 회차마다 트럭을 강제 변경하면 현장 제한 기준으로 다시 검사 → 적용/거부 결과를 진단 패널에 한 줄로 표시(예: "✓ 회차 #2 트럭 변경: '저상24t' → '광폭28t'").
- 진단 패널: 운송 불가 사유(구체 수치) + 종속 부재 요약(예: "캔틸레버 3개 → 부모 모듈에 흡수"). 코어/코어슬래브는 운송 대상이 아니므로 표기하지 않는다.
- 참고자료 버튼: 운송 차량·운임 기준 등 근거 자료를 보여준다.
- **검증 보고서**: `transport/benchmarks/run_validation.py` 가 5 사이즈 픽스처 × 3 비용 모드 × {기존 FFD, 신규} 비교 → `modular_3d/운송 검증 보고서.md` 자동 생성. 합격 기준 (평균 절감 ≥ 5 %, 회귀 0 건) 자동 검토.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 물량 탭의 부재별 단면·무게 + 디자인의 치수 + 프로젝트 설정(운송 거리 · 운임 방식·단가 · 비내력벽 단위중량 · 현장 운송 제한) + 이 탭의 옵션(캔틸레버 처리 등).
- 내부 처리: 무게·치수 산정 → 좌표 자동 정렬 → 다중 시드 패킹 → VND 국소 탐색 → 무게중심 시각 보정 → 운임 계산.
- 아웃풋(다음 탭으로 전달): 모듈 회차·패널 회차·총 회차, 평균 적재량(중량 기준), 전체 운송 거리, 그리고 총 운송비. 이 결과가 종합 탭의 입력이 된다.

**향후 계획**

- 다른 탭의 3D 렌더링도 Three.js 기반으로 통일 (현재는 운송 탭만 Three.js, 다른 탭은 vispy).
- 회차 자동 최적화는 *Best-Fit + 다중 시드 + VND* 으로 이미 구현됨 (2026-05-26).
- 적재 3D 뷰는 *Three.js 로 완성* (2026-05-26~27).
- 벽체 패널 세워 운송도 신규 패커에 반영됨 (A-frame 트럭에 STANDING 자세 적재).
- 운임 콤보 변경 후 *재계산 없이* 3D 오버레이 비용 자동 갱신은 추후 보강.

## 7. 공정표 탭

**(이전 이름) "공기 및 접합부"** — 2026-05-27 *공정표* 로 변경. 변수명도 `_tab_schedule` 로 통일.

**이 탭에서 하는 일**

앞 단계에서 만든 모듈 구성과 접합 정보를 바탕으로, 건물을 짓는 데 걸리는 공사 기간(공기)을 단계별로 산정하고, 노무비·경비도 같이 산출해 공정표로 보여준다. 팀원 프로그램(Song-Jung-Hun/modular-schedule)의 HTML 공정표 도구를 그대로 임베드해 메인 프로그램과 연동한다.

**구현 — 팀원 HTML 임베드**

- 본 탭은 `modular_3d/schedule/모듈러주택_공정표.html` 을 QWebEngineView 로 임베드한다. HTML 단일 파일 안에 입력 폼·계산 로직(JS)·간트·경제성 표가 모두 들어있다.
- 메인 프로그램과의 연동은 두 방향:
  1) **자동주입 (Python → JS)**: 탭 진입 시 `schedule_adapter.build_scene_data()` 가 우리 배치·프로젝트 설정에서 summary + components + module_types + project(지역·착공일)을 추출해 JS 의 `importScene()` 으로 주입.
  2) **결과 푸시 (JS → Python)**: JS 의 `calc()` 가 결과를 만든 직후 QWebChannel 의 `scheduleBridge.on_schedule_calculated(payload)` 를 호출해 Python 측 캐시에 저장. 종합 탭이 이 캐시를 가져다 쓴다.

**(1) 인풋 — 어디서 오고, 무엇을 입력하는가**

자동 주입되는 값(우리 데이터로 결정 — 화면에서 입력 칸 자체를 감추고 표시도 안 함)과 사용자가 직접 입력하는 값을 명확히 분리했다(2026-05-27, Phase H·I).

**자동주입(우리 데이터)**:
- 세대층 수 / 층당 모듈 수 / 1층 바닥면적 / 코어 한 층 바닥면적
- 모듈당 수직접합 수(꼭지점 기둥 = 4개/모듈) / 층당 수평접합부 수(인접 모듈쌍 자동 카운트 — 수직3층모듈은 관통 층마다 옆 모듈과의 접합을 셈)
- 모듈 타입별 폭·길이·개수(이름·폭·길이·개수는 잠금, 중량만 사용자 보정 허용)
- 지역(가동율 자동) — 프로젝트 설정의 도시 라벨에서 추출
- 착공일 — 프로젝트 설정

**사용자 직접 입력(운영 파라미터)**:
- 지하층 수 (0~3층)
- 크레인 종류·대수, 최하층/기준층 양중속도(유닛/일)
- 수직접합 / 수평접합 1개당 소요일 (0 이하 입력 차단)
- 코어 선행 일수 (모듈 착수 오프셋)
- 유가 (경유 단가, 원/ℓ)

화면에서 "회색 칸 = 메인 프로그램에서 결정 — 이곳에서 수정 불가" 안내문이 상단에 표시된다. 자동주입 항목의 입력 칸은 통째로 제거되고 결과 표시 박스만 남는다(예: 지역·착공일은 회색 라벨로만 표시).

**(2) 내부 처리 — 어떻게 공기를 산정하는가**

- 토공사·기초공사: 켄텍 대학원숙소 실적의 면적 비례 계수(토공 0.0414일/m², 기초 RC 0.0203일/m²) 와 지하 깊이 계수를 곱한 뒤 지역 가동율로 달력 환산.
- 1층·필로티 골조: 광양 기가타운 실적 비례(0.0255일/m²).
- 코어 골조 (코어병행형): 거푸집 면적(바닥×1.465) × 0.00809일/m² ÷ 가동율 × 총층수.
- 모듈 설치: 크레인 대수 × 최하층/기준층 속도(유닛/일) 로 층당 설치일을 정한 뒤, **수직접합은 양중에 합치고 수평접합은 양중과 동시(병행) 진행** → 한 층 시간 = max(양중+수직, 수평). 코어 선행 후 모듈 시작 + 그 층 코어 완료 후 그 층 모듈 설치(코어 게이팅).
- 지붕 트러스·패널·방수, 베이스플레이트, 마감, 부대공사: 켄텍·OTKCRK·LH 지침의 실적 계수를 우리 규모(층당 모듈수·세대수)에 비례.
- 노무비 = 켄텍 man-day 계수 × 물량 × 시중노임(2026.1.1) / 경비 = 토공(굴착기) + 크레인(이동식 톤수별) 시간당 손료·연료·운전원.
- 일정 환산: 지역 가동율(기상청 ASOS 2021~2025 5년 실측) 기반 달력일 = ceil(실작업일 ÷ 가동율).

**(3) 결과 — 무엇이 나오는가**

- 공기 산정표(서브탭): 공종별 실작업일·비작업일·총기간·착수·완료·근거.
- 바차트(서브탭): 30일 단위 간트. 크리티컬 패스는 빨강, 일반 공종 파랑, 접합(병행) 주황.
- 경제성 표: 공종별 노무비·경비·합계 + 작업조 구성 모달.
- 마일스톤 리스트.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 우리 배치·프로젝트 설정(자동주입) + 사용자 운영 파라미터(직접 입력) + 팀원 HTML 의 내장 단가 DB(시중노임 2026 · 기계경비 산출표 2025 · 표준품셈).
- 내부 처리: 면적·모듈수·크레인·접합속도로 공종별 작업일 → 가동율로 달력 환산 → 노무비·경비 산출.
- 아웃풋(다음 탭으로 전달): 총 공기(달력일) · 코어 기간 · 모듈 설치 기간 · 공종별 task 배열 + laborSum(노무비 합계) · equipSum(경비 합계). QWebChannel 로 Python 캐시에 푸시 → 종합 탭이 사용.

## 8. 종합 탭

**(이전 이름) "최종평가" → "평가"** — 현재 탭 표시 이름은 *종합* 이다. 변수명 `_tab_evaluation`.

**이 탭에서 하는 일**

하나의 설계안이 디자인 → 접합부 설계 → 구조해석 → 물량 → 운송 → 공정표 단계를 모두 거친 뒤, 그 결과를 한 화면에 모아 종합 보고서를 보여주는 마지막 단계다. 사용자 입력은 없고, 앞 탭들의 결과를 자동으로 끌어모아 표·카드 형태로 렌더링한다.

**세대 개념 제거 (2026-05-27)** — 우리 프로그램은 아파트 설계용이므로 1모듈≠1세대다. 한 세대가 여러 모듈로 구성되는 일이 흔해 세대수를 정확히 알 방법이 없다. 따라서 평가 화면에서 "세대수·층당 세대수" 표시를 모두 제거하고 모듈 단위로만 다룬다.

**화면 구성 — 단일 스크롤 페이지**

상단 우측 모서리에 "💾 평가 결과 저장" 버튼 1개. 본체는 위에서 아래로 A~F 6 영역.

**A. 건물 개요** — 헤드라인 카드 5개 가로 (총 층수 / 지하층 / 총 모듈 수 / 1층 footprint(㎡) / 연면적(㎡))

**B. 부재 구성** — 모듈 타입별 표(타입·폭·길이·면적·개수) + 한 줄 요약(바닥패널·벽패널·내벽·코어슬래브 / 캔틸레버보·캔틸레버슬래브·중간보·중간기둥 개수)

**C. 강재·콘크리트 물량 + 자재비** — 그룹별 채택 단면 한 줄 라벨 + 강재 본수표(단면·길이·본수·총길이·총중량) + 슬래브 정보 라벨(면적·부피·두께) + 자재비 한 줄(강재·데크·콘크리트·합계). **정책 선택(1종/2종/3종)은 물량 탭의 `_current_policy` 를 그대로 표시** — 종합 탭에서 다시 토글하지 않는다(이중 입력 방지).

**D. 운송 요약 (카드 4개)** — 총 회차 / 평균 적재(t, 적재율 % 병기) / 운송 거리(km) / 총 운송비(원)

**E. 공기 요약** — 카드 3개(총 공기·코어 기간·모듈 설치) + 공정표 표(공종명·기간·착수·완료). 풀 간트는 공정표 탭에 있으므로 종합 탭은 *표 형식* 으로 간결화.

**F. 종합 비용 (카드 5개)** — 자재비 · 운송비 · 노무비 · 경비 · **공사비(=합계, 빨간색 강조)**. "공사비" 는 별도 산식이 아니라 위 4개의 합 라벨이다.

**데이터 출처 — 이중 입력 없음**

| 영역 | 출처 |
|---|---|
| A·B 헤드라인·부재 구성 | scene 의 components (배치 데이터) + ProjectSettings.basement_floors |
| C 물량·자재비 | `analysis_panel._quantity_reports[current_policy]` + `compute_material_cost` (물량 탭과 같은 로직) |
| D 운송 | `self._last_transport_pack` 의 Trip.cargo_weight 평균 + `transport_panel._last_eco.total_cost_krw` + ProjectSettings.distance_km × 회차 × 2 |
| E 공기 | 공정표 탭이 QWebChannel 로 푸시한 payload (총공기·코어·모듈설치·tasks·laborSum·equipSum) |
| F 종합 | C·D·E 합산 |

**미실행 탭 정책** — 각 영역마다 입력이 None 이면 그 영역만 회색 안내("물량 탭에서 단면 산정·자재비를 먼저 실행하세요" 등) 처리하고 나머지는 정상 렌더. 자동 트리거는 하지 않는다 — 사용자가 해당 탭에 들어가 직접 실행.

**케이스 저장 — `.case.json`**

우측 상단 저장 버튼 → QFileDialog → 사용자가 위치·이름 선택 → 완전 스냅샷 저장.

- 형식: `{ kind: "modular_case_v1", saved_at, name, scene, project_settings, results: { evaluation } }`
- 직렬화 범위 — scene 전체 + ProjectSettings 전부 + 평가 화면 표시 데이터(어댑터 산출 dict). 다른 탭의 원본 객체(DesignResult·PackResult)는 직렬화가 까다로워 평가 화면 표시값으로 저장하고, "이 안으로 마감 작업 이어가기" 가 필요하면 scene 만 다시 불러와 앞 탭들을 재계산한다.
- 디자인 파일(.json)과 확장자로 구분.
- 한 탭에 *슬롯이나 케이스 리스트는 두지 않는다* — 비교 탭에서 저장한 파일 여러 개를 직접 불러오는 방식.

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 앞 단계(디자인~공정표)의 모든 결과 + 단가 DB(자재 단가는 물량 탭 경유, 노무·경비는 공정표 탭 경유).
- 내부 처리: 어댑터(`evaluation_adapter.build_evaluation_data`)가 6개 영역 dict 를 만들고, 패널(`EvaluationPanel.apply_data`)이 영역별로 렌더.
- 아웃풋: 화면에 종합 보고서 표시 + .case.json 파일(저장 버튼 시).

## 9. 비교 탭

**이 탭에서 하는 일**

종합 탭에서 저장한 `.case.json` 설계안 파일을 최대 3개까지 불러와 나란히 비교하는 단계다. 여러 안 중 어떤 설계안으로 진행할지 결정하도록 돕는다. (이전에는 상단 메뉴의 기능으로 계획했으나, 실제로는 독립 탭으로 구현되었다.)

**화면 구성**

- 상단: A·B·C 세 칸. 빈 칸은 "파일 가져오기" 버튼, 채워진 칸은 파일명 + 제거 버튼.
- 중앙: 비교 표 — 행은 지표(연면적·강재 본수·자재비·공기·총 비용 등), 열은 케이스 A/B/C. 지표는 카테고리별로 묶여 표시된다.
- 우측: 가로 막대 차트 3개 (공기 / 비용 / 평면 효율).

**정리 — 이 탭의 인풋과 아웃풋**

- 인풋: 종합 탭에서 저장한 `.case.json` 파일 (최대 3개).
- 아웃풋: 세 안을 한눈에 비교하는 표와 차트(화면 표시 전용).

## 상단 메뉴 줄 — 전역 기능

설계안 하나에 매이지 않고 사업 전체에 공통으로 쓰이는 기능을, 탭 줄 위의 메뉴 줄에 모아 둔다. (사업 공통 조건 설정)

**(1) 프로젝트 설정**

여러 설계안을 비교하려면 모든 안에서 똑같이 고정돼야 하는 공통 조건이 있다. 이런 항목은 케이스마다 달라지면 안 되므로, 각 탭의 입력 자리에서 빼내어 메뉴 줄의 "프로젝트 설정" 창에서 한곳에 입력한다.

여기서 입력하는 공통 설정:

- 운송: 편도 거리 · 운임 방식(① 요금표 자동 / ② 트레일러별 km당 단가) · 트레일러별 km당 단가 (운임은 항상 왕복 기준)
- 지역 선택 → 비작업일 기준(별표1 기초공사용, 별표2 골조공사용) — 지역을 고르면 두 값이 자동으로 채워진다
- 착공일
- 비내력벽 단위중량(외부 55 / 내부 30 kg/m²)

트럭 카탈로그 관리(운송 탭에서 쓰는 저상·광폭 등 트럭 목록 추가·수정·삭제)도 설계안과 무관한 공통 기능이므로 이 안에 함께 둔다.

(현재 구현 상태) 메뉴 줄의 "프로젝트 설정" 항목을 누르면 위 항목을 입력하는 창이 뜬다. 운송 관련 공통값은 운송 탭에 읽기전용으로 연결돼, 운송 탭에 들어갈 때마다 프로젝트 설정 값으로 갱신된다(수정은 프로젝트 설정에서만). 입력값은 현재 세션 동안만 유지된다.

**향후 계획**

- 입력값을 파일로 저장해 프로그램을 다시 켜도 유지되게 한다(케이스 저장·비교와 함께 도입).
- 공정표 탭의 운영 파라미터(크레인·접합속도·코어선행일·유가·지하층) 도 ProjectSettings 로 옮겨 한곳에서 관리 (2차 계획).

(설계안 비교는 이제 별도 "비교 탭"(9번)에서 한다 — 위 9절 참조.)
