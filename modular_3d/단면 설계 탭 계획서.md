# 단면 설계 탭 신설 계획서 (2026-05-31)

## 0. 한 줄 요약
구조해석 탭과 물량 탭 *사이*에 **단면 설계** 탭을 신설한다. 좌측은 응력비 색을 입힌
와이어프레임(공유 3D), 우측은 단면 설계 옵션 + 선택한 타입 1개의 컴포넌트 3D(정의 탭 색
메쉬 스타일). 사용자가 옵션/수동 단면을 바꾸고 **적용**을 누르면 단면을 *수렴*시킨다
(단면 선정 → 새 강성으로 재해석 → 재선정 반복). 확정된 단면이 물량·구조해석의 단일 출처가
된다.

## 1. 사용자 확정 사항 (대화 기록 기반)

### 1-1. 위치·이름
- 새 탭 = **단면 설계**, 위치 = **구조해석 ↔ 물량 사이**.
- 물량 탭 이름·역할 유지(물량 산출). (옛 배치설계 md의 "물량→부재설계 개명" 계획은
  *폐기* — 단면 설계가 별도 탭으로 빠지므로 물량은 그대로 둔다.)

### 1-2. 좌측 3D
- **와이어프레임 + 지배조합 응력비 색**(구조해석/물량의 ratio 색 표현 경로 재사용).
- 색은 기존 5단계(viewer.show_member_ratio_bands / _ratio_to_5band)를 그대로 쓴다 —
  파랑(<0.30)/하늘(<0.60)/초록(≤0.85)/주황(≤1.0)/**빨강(>1.0)=NG**. 즉 **NG 부재는
  빨간 선으로 이미 표시됨** → 별도 색 추가 없이 재사용.
- 단면이 바뀌어도 **중심선(절점)·접합·와이어프레임은 안 건드린다.** 단면 물성(A·I)만 갱신.
  → 단면 변화에 따른 중심축 이동은 해석에서 **무시**(사용자 수용한 단순화).

### 1-3. 우측 패널
- **위: 단면 설계 옵션** + **적용 버튼**(옵션/수동 변경은 버튼을 눌러야 재수렴).
- **아래: 타입 목록**(모듈A-1-1, A-1-2 …) 에서 **하나 선택** → 그 아래 **3D 하나**가
  *그 타입만* 표시. 동시에 여러 개를 띄우지 않음(웹뷰 1개로 경량).
- 컴포넌트 3D = **정의 탭 스타일 색 메쉬**(기둥 빨강 / 바닥보 파랑 / 천장보 하늘). 종속
  부재(캔틸레버보 등)도 같이 그린다.
- 셀에 라벨 + 3D + **단면 치수 · 응력비 · OK/NG** 텍스트 표기.
- 선택을 바꾸거나, 단면이 바뀌거나, 적용을 누르면 이 3D가 **갱신**된다.

### 1-4. 단면 분류 = 렌더링 색이 정답
강재 부재는 색 기준으로 **3종**으로만 모인다(modular_designer.html 색, mesh_builder.py 확인):
| 클래스 | 색 | 포함 부재 |
|---|---|---|
| 기둥 | 0xCC3333(빨강) | 모듈 기둥, 벽패널 기둥 |
| 바닥보 | 0x2266CC(파랑) | 모듈 바닥보, 바닥패널 테두리보, 벽패널 하부 러너 |
| 천장보 | 0x5599DD(하늘) | 모듈 천장보, 벽패널 상부 러너, **캔틸레버보**(코드상 천장보 색) |
- 캔틸레버보·패널 부재가 색으로 자동 귀속 → **고아 부재 없음, 단변/장변 구분 불필요.**
- **슬래브·비내력벽·창호는 단면 설계·재해석 대상 제외**(슬래브=콘크리트 두께 고정, 벽·창호=비내력).

### 1-5. 옵션 — 2축 분리(자유 다중선택 ❌)
의견 모드 결론: 옵션은 직교하는 두 축의 조합. 입도·수동편집 단위는 **동일**(둘 다 색 기준 3종).

**스코프 축(공간 범위, 택1)**
1. 전체에서 통일
2. 같은 타입끼리 통일 (모듈A-1 등 base 타입 단위)
3. 같은 타입에서 실배치가 다른 경우 나눠서 통일

**입도 축(부재 묶음, 색 기준)**
- 전부 한 단면 / 기둥·보(천장+바닥 묶음) 2분 / 기둥·천장보·바닥보 3분
- 보조 토글: **기둥은 층 구간별로 분할**(기존 split_columns_by_floor 활용)

**응력비 임계값: 제거.** ("통일 + NG 안 나는 최소 단면"이면 지배 부재가 자동으로 1.0
바로 아래에 앉아 하한값이 무의미 — 사용자 동의로 옵션에서 뺀다.)

**최종 단면 그룹 = (입도로 나뉜 색 클래스) × (스코프로 나뉜 컴포넌트 묶음) 교차 한 칸당 단면 1개.**

### 1-6. 수동 편집(좌측 3D에서 선택)
- 편집 단위 = 컴포넌트의 **{기둥 / 천장보 / 바닥보}** (1-5 입도와 동일, 색 기준).
- 캔틸레버보는 **연결된 보의 연장선** → 그 대상 보(천장보)와 **똑같이** 처리(따라감).
- **수동 변경은 잠금(보존).** 이후 옵션 재실행·수렴 재계산에서도 잠긴 부재는 단면 고정,
  나머지만 다시 설계. 잠긴 부재가 NG면 **NG로 표시만** 한다.

### 1-7. 수렴(진짜 반복) — 단면 설계 탭 내부에서만
**[P0 정정 — 2026-05-31] 현재는 강성이 단면을 따라가지 않는다.**
ops_builder._section_props 는 일반 강재(SHS/H)에 대해 부재 치수를 *무시*하고 **고정 공칭
단면**(SHS_200x200x8 / 공칭 H200×200)을 반환한다. 또 설계(select_section_for_group)가
고른 단면을 부재(section_w/h/t)에 *써넣는 경로가 없다*. 그래서 현재 단면을 바꿔도 재해석
결과가 동일 → 수렴이 1회에 자명 종료된다. **따라서 P1 에서 다음을 반드시 포함해야 수렴이
의미를 가진다:**
- (A) `_section_props` 가 일반 강재일 때 **부재의 현재 배정 단면**으로 A·Iy·Iz·J 계산
  (SHSSection.from_dimensions / _shs_section_props, H는 배정 H단면). 카탈로그가 물성 제공.
- (B) 수렴 루프가 그룹 선정 단면을 **부재에 써넣음**(section_w/h/t + H면 section ref).
- (C) **하위호환** — 아직 설계 안 된 부재는 공칭(200×200×8)에 머무름 → 단면 설계 전 기존
  구조해석/물량 결과 불변. (topology 기본 단면이 공칭과 같으면 자동 일치.)

위 (A)~(C) 가 깔리면, 단면을 부재에 써넣고 모델 재빌드 → 재해석하면 힘이 재분배된다(수렴 성립).
1. 현재 스코프·입도로 부재 그룹화(잠긴 부재 제외).
2. 각 그룹: **지배조합(envelope) 단면력** 기준 카탈로그에서 **NG 안 나는 최소 단면** 선정.
3. 선정 단면을 부재에 반영 → OpsModel 재빌드 → **solve_all_cases 재해석**.
4. 새 단면력으로 2로 복귀. **단면이 더 이상 안 바뀌면 종료.**
- **최대 10회.** 두 값 사이 진동 시 **더 큰(안전측) 단면 채택** 후 종료.
- **단면 형식(각형강관 SHS / H형강)은 이번엔 그대로 유지**(앞 단계에서 사용자가 정한 형식).
  추후 이 탭에서 사용자가 형식까지 직접 바꾸는 기능은 별도 추가.
- 설계 기준 = **지배조합**(어느 조합에서도 NG 안 나게). 좌측 와이어프레임 응력비 색도 동일 기준.

### 1-8. 물량은 재해석 불필요(단일 출처)
- 단면 설계 탭이 단면의 **유일 출처**. 물량 탭은 확정 단면을 받아 **물량만** 산출하고
  해석을 다시 돌리지 않는다.
- 현재 물량 흐름(controls_f6: design_all_policies_envelope + split_columns_by_floor 로
  정책 1종/2종/3종 열거)을 **단면 설계 탭 결과 소비로 대체**(정책 열거 폐기).

### 1-9. 우측 컴포넌트 3D — 외곽 고정, 안쪽 성장
- 모듈/패널의 **외곽 치수는 불변**(모듈끼리 맞물려 쌓여야 하므로). 단면이 커지면 바깥으로
  안 나가고 **안쪽으로만** 파고든다. 기둥=모서리 바깥면 고정, 보=가장자리 바깥면 고정.
- 이건 **그림(우측 3D 시각화) 한정** — 해석 축·접합은 1-2대로 불변.
- 캔틸레버보 = 연장 대상 보와 똑같이 처리(천장 레벨 윗면 기준으로 동일하게 키움).

### 1-10. 타입 -1-1 (단면 변형 단계) 체계
- 현재 type_naming 은 'A-1'(외형 크기 A + 실배치/구성 시그니처 -1)까지. 코드 주석에 이미
  "3차 상세(A-1-1, 단면 설계 결과 반영)는 별도로 덧붙임" 명시 → 확장 지점 예약됨.
- 규칙: 같은 base 타입(모듈A-1) 안에서 **현재 단면 배정이 다르면** 마지막 자리 -1/-2 로
  더 쪼갠다(모듈A-1-1, A-1-2). 단면이 같아지면 **다시 합친다**. (배정으로부터 동적 파생.)
- **파생 로직은 단면 설계 탭 안에서 처음부터 사용**한다(현 단면 배정으로 그때그때 -1-1 계산
  → 우측 타입 목록·갤러리 라벨에 사용). P1~P5 동안 이 -1-1 은 탭 내부 한정.
- 이 -1-1 라벨을 **물량·구조해석 트리로 전파**하는 것만 **별도 후속 페이즈(P6)** 로 분리.
  type_naming 변경은 프로그램 전반에 영향 → 영향 범위 사전 분석 후 진행.

## 3. 빌드 순서 (페이즈) — 위험·의존성 기반 확정

### 순서 결정 원칙
1. **최고 위험을 GUI 없이 먼저** — 수렴 엔진(재해석 반복)이 핵심이자 최고 위험인데
   *헤드리스 단위검증이 가능*하다(GUI 무관). 사용자 실행은 직접 수행 원칙이므로 GUI 왕복을
   줄이려면 코어를 먼저 확정한다.
2. **저위험·재사용 좌측 → 고위험 우측** — 좌측 색은 기존 5단계 ratio 색 *재사용*(저위험,
   즉시 가시). 우측 컴포넌트 3D 는 메쉬 앵커(외곽 고정 안쪽 성장) *변경*이라 고위험 →
   코어·탭·옵션이 선 후.
3. **회귀 위험 큰 통합·전파는 맨 뒤** — 물량 정책 열거 제거, type_naming 전파는 단면 결과가
   신뢰될 때 마지막에. 앞 단계가 깨지지 않게.

### 페이즈

  가 매 케이스 build_ops_model 재빌드 + prebuilt_am 재사용). **단 강성이 단면 미반영(고정
  공칭)이고 설계 단면 write-back 경로 없음**을 발견 → 1-7 (A)~(C) 를 P1 범위에 추가.
