# 접합부 변경 기능 계획서

사용자가 **컴포넌트 간 접합부**를 직접 제거·변경·추가하고 저장하는 기능. 노션 2.2.2-1
("사용자가 접합부를 변경하는 로직 + 한 층 편집 시 같은 위치 다른 층 자동 적용").
컨텍스트 압축 대비 — 다음 세션이 이 문서만 읽고 이어서 작업할 수 있도록 상세 기록.

> **작업 순서 (사용자 확정)**
> ① 기존 접합 제거 / 변경(핀↔강접) → ② 신규 접합 추가 → ③ 저장 → ④ 불러오기 시
>   "저장본 / 새 자동계산" 선택.

---

## 0. 범위 (확정 사양)

- **대상: 컴포넌트 간 접합만.** 모듈 내부 보-기둥 접합 등은 변경 대상이 아님(자동 유지).
  - 해당 접합: 모듈↔모듈(수평 인접 R01 / 수직 적층 R02), 바닥패널↔기둥(R03~R06),
    캔틸레버↔모듈, 코어 관련(R09 등) — 즉 `joint_rules` 가 만드는 컴포넌트 간 결합 전부.
- **접합의 의미 = 결합의 성질 + 존재 둘 다.**
  - **제거**: 그 결합을 완전히 없앤다(두 노드 분리, equalDOF 미등록).
  - **변경**: 핀(힌지) ↔ 강접(rigid) 성질 전환만. (대상 부재를 바꾸는 건 "추가"로 처리.)
  - **추가**: 두 점(노드)을 골라 새 결합 생성. **400mm 이내 + 축정렬(x·y·z 중 한 축만 다름)**.
    기본 핀, 사용자가 강접 선택 가능.
- **단위: 개별 결합점(노드쌍) 하나하나.** ("두 컴포넌트 사이 전체"가 아니라 결합점 단위.)
- **선택: 3D 가장 가까운 접합 자동 선택.** 구조해석 탭 부재 픽킹 로직 재사용.
- **다층 자동 적용**: 임의 층에서 편집하면 **같은 평면 위치(xy)의 모든 층** 접합에 동일 적용.
  "모듈 하나 배치하면 위로 쭉 생기는 것"과 같은 방식. **상대가 없는 층은 자동 건너뜀.**
- **제거로 구조 불안정**(떠다니는 부재) 가능 → **경고만 띄우고 허용**.
- **저장**: 디자인(scene) 파일에 함께(부재/씬에 부속).
- **사용자 변경 우선**: 자동 규칙(joint_rules)보다 오버라이드가 최종.
- **불러오기 시**: 접합부 조정 탭 진입할 때 "저장된 접합 결과를 쓸지 / 새로 자동계산할지"
  선택. 새로 계산 선택 시 joint_rules 자동 로직 발동(저장본 무시·갱신).

## 1. 현재 시스템 분석 (코드 근거)

### 1.1 접합 표현 — OpenSees equalDOF
- 모든 컴포넌트 간 접합은 `ops.equalDOF(master, slave, *dofs)` 로 표현.
- **기본 dofs=(1,2,3)** = 이동 3방향만 구속, 회전(4,5,6) 자유 = **핀(힌지)**.
  (`analysis/joint_rules.py` 의 모든 R0x 함수 기본값 `dofs=(1,2,3)`.)
- **강접 = dofs=(1,2,3,4,5,6).**
- spec 기록: `om.spec.equal_dofs` 에 `EqualDofRec(master, slave, dofs, rule_id)` append.
  - rule_id 예: `RULE_ID_MOD_MOD_V`(수직), 수평/패널 룰 각자 id.
- **매 해석 시 재계산** — 저장되지 않음. build_ops_model 의 결합 단계에서 R01~R09 호출.

### 1.2 자동 생성 규칙 — analysis/joint_rules.py (1999줄)
- R01 모듈↔모듈 수평 인접(점-점 / 점-모서리), R02 수직 적층, R03~R06 바닥패널-기둥,
  R09 코어 등. 각 룰이 노드쌍을 찾아 equalDOF + EqualDofRec.
- 거리 임계: `_GAP_MAX=225`, `_VSTACK_MAX=225` 등.

### 1.3 노드 ↔ 컴포넌트 역추적
- `am.nodes[nid].source_comp_id`, `am.comp_to_nodes[cid]` → 노드가 어느 컴포넌트 소속인지.
- 노드 좌표: `ops_model.node_tags[nid]` (또는 `am.nodes[nid].coord`).

### 1.4 3D 픽킹 (재사용 대상)
- `render/viewer.pick_ops_member_at(qt_pos, ops_model, am, threshold)`:
  scene transform + perspective divide 로 부재 양끝 화면 투영 → 점-선분 2D 거리 최소 부재.
- **접합점(노드) 픽킹**도 동일 방식으로 신설: 후보 노드들을 화면 투영 → 점-점 거리 최소.
  (접합에 관여하는 노드만 후보로.)

### 1.5 접합부 조정 탭 (현재 더미)
- `ui/joint_edit_panel.py` JointEditPanel — 접합 편집 토글 비활성, 다이어프램·rule 범례 시각화만.
- F6 ops 뷰에서 접합이 rule_id 색선으로 표시됨(viewer.OPS_RULE_ID_COLOR).

## 2. 데이터 모델 — JointOverride

### 2.1 위치 정체성 (다층 복제의 핵심)
접합은 두 노드 사이. 다층 복제를 위해 **층(z)에 무관한 평면 위치 키**로 식별한다.
- 수평 인접·수직 적층 접합 모두 같은 (x, y) 가 모든 층에서 반복됨("위로 쭉").
- 따라서 한 접합 오버라이드를 **두 끝점의 (x, y) + 두 컴포넌트 그룹 식별**로 키잡으면,
  z(층) 무관하게 같은 xy 의 모든 층 접합에 자동 적용된다.
- **[중요] 다층 그룹은 모든 층이 같은 `group_id` 를 공유**한다(create_multi_floor_group
  이 1~N층 복제본에 같은 gid 부여). 따라서 두 컴포넌트 그룹 쌍 (gid_A, gid_B) + xy 만으로
  "그 두 그룹이 만나는 모든 층"이 자동으로 한 키에 묶인다 — 이것이 "임의 한 층에서 편집
  → 모든 층 적용(모듈 배치하면 위로 쭉)"의 구현 근거. 층(floor_index)은 키에서 제외한다.

### 2.2 JointOverride dataclass (신규, model/joint_override.py)
```
필드(개념):
  kind         : 'remove' | 'rigid' | 'pin' | 'add'
                 - remove: 기존 접합 제거
                 - rigid : 기존 접합을 강접으로 (dofs 1~6)
                 - pin   : 기존 접합을 핀으로 되돌림(강접 취소)
                 - add   : 신규 접합(두 점)
  a_xy, b_xy   : 두 끝점 평면 좌표(mm). 층 무관 매칭 키.
  a_group, b_group : 두 끝점이 속한 컴포넌트 group_id (보조 식별 — 같은 xy 다른 그룹 구분).
  z_rel        : (add 전용) 두 점의 z 차(축정렬). 또는 수평이면 0.
  add_dofs     : (add 전용) (1,2,3) 핀 / (1,2,3,4,5,6) 강접.
직렬화: to_dict / from_dict. scene_io 가 scene 과 함께 저장(별도 'joint_overrides' 키).
```
> 식별은 xy 좌표 반올림(예: 1mm) 매칭. 부동소수 안전 위해 tol(예: ±50mm) 비교.

### 2.3 Scene 보관
- `Scene.joint_overrides: List[JointOverride]` 신설 (rooms 와 같은 패턴, undo 스택 별개).
- scene_io.scene_to_state_dict / state_dict_to_scene 에 `joint_overrides` 직렬화 추가.

## 3. 해석 반영 (오버라이드 적용)

build_ops_model 의 결합 단계에서:
1. 평소대로 joint_rules R01~R09 가 자동 접합(EqualDofRec + equalDOF) 생성.
2. **그 다음 `apply_joint_overrides(om, scene)` 호출** — scene.joint_overrides 를 순회하며:
   - `remove`: 매칭되는 EqualDofRec(들)을 spec 에서 빼고, **그 equalDOF 를 모델에서 제외**.
     (이미 ops.equalDOF 가 등록됐으면 빌드 순서를 바꿔: override 를 먼저 읽어 "제외 집합"을
      만들고 joint_rules 가 그 노드쌍을 건너뛰게 하거나, override 적용을 빌드 재구성 단계로.)
   - `rigid`: 매칭 EqualDofRec 의 dofs 를 (1..6) 으로 교체.
   - `pin`: dofs 를 (1,2,3) 으로.
   - `add`: 두 점에 대응하는 노드를 찾아 새 equalDOF(add_dofs) + EqualDofRec 등록.
3. 매칭은 노드쌍의 xy(±tol) + z 레벨로. **모든 층**에 같은 xy 면 전부 적용(다층 자동).

> **빌드 순서 주의(함정)**: ops.equalDOF 는 한 번 등록하면 빼기 어렵다. 따라서 권장 구조는
> "joint_rules 가 노드쌍 후보를 모으는 단계"와 "실제 equalDOF 등록 단계"를 분리하고,
> override(remove/rigid/pin/add)를 등록 직전에 반영하는 것. 1단계 구현 시 build_ops_model
> 흐름을 먼저 정밀 분석할 것.

## 4. 단계별 구현 계획

### 1단계 — 기존 접합 제거 / 변경 (핀↔강접) ✅ 완료 (2026-05-25)
- (a) ✅ 접합 후보 수집: `viewer.pick_ops_joint_at` 가 `om.spec.equal_dofs` 중
  **컴포넌트 간** 결합만 후보로. 같은 컴포넌트 내부 보조(코어 사영점, 두 끝
  source_comp_id 동일·0 아님)는 제외. 모듈 내부 보-기둥은 equalDOF 가 아니라 후보 X.
- (b) ✅ 3D 픽킹: `pick_ops_joint_at` — 두 노드를 잇는 선분에 대한 점-선분 2D 거리
  최소(부재 픽킹 `pick_ops_member_at` 과 동일한 scene transform + perspective divide).
- (c) ✅ 선택 접합 표시: `viewer.highlight_ops_joint`(노란 선+끝점 마커) +
  `JointEditPanel` 우측 패널(현재 성질 핀/강접 + [제거][핀][강접][자동 복귀]).
- (d) ✅ 동작: `JointEditPanel.joint_change_requested` → `main_3d._on_joint_change` →
  `scene.set_joint_override` → `_run_joint_edit_preview(force=True)` 재빌드.
  **해석 반영**: `build_ops_model` 이 `om.joint_overrides` 부착 → `joint_rules` 의
  등록 게이트 `_resolve_override_dofs` 가 등록 직전 remove(skip)/rigid/pin(dofs 교체).
  **다층 자동**: 게이트가 xy(±50mm) 매칭 → 같은 평면 위치 모든 층 자동 적용(z 무시).
  **solve 반영**: `ops_solver.solve_all_cases` 도 `build_ops_model` 5회 호출 →
  실제 구조해석·물량에 자동 반영(별도 배선 불필요).
- (e) △ 제거로 불안정(부유 노드/mechanism) 가능 → **허용**(차단 안 함). 명시적
  특이강성 경고 다이얼로그는 solve 단계(구조해석 탭)에 위임 — 1단계 핵심(제거/변경
  동작·반영)은 완료. 접합 탭 프리뷰는 solve 미실행이라 빌드만으로는 경고 발생 X.

### 2단계 — 신규 접합 추가 ✅ 완료 (2026-05-25)
- (a) ✅ "접합 추가" 모드: `JointEditPanel._add_toggle`(편집 모드와 배타) →
  3D 점1 클릭 → 점2 클릭. `viewer.pick_ops_node_at`(노드 점-점 픽킹) +
  `main_3d._on_joint_add_pick`. 첫 점은 초록 마커(`highlight_ops_node`)로 표시.
- (b) ✅ 검증 `main_3d._validate_add`: 다른 컴포넌트(source_comp_id) + 400mm 이내 +
  축정렬(x·y·z 중 한 축만 >50mm). 위반 시 QMessageBox 안내 후 거부.
- (c) ✅ 성질: `_add_rigid_chk`(기본 해제=핀, 체크=강접) → `JointOverride(kind='add',
  z_a/z_b/add_dofs)`. **해석 적용**: `joint_rules.apply_added_joints(om)` 가
  build_ops_model 에서 자동 룰 직후 호출 — 두 점의 노드를 om.node_tags 에서 찾아
  dz_rel(=z_b−z_a) 유지하며 **같은 평면 위치 모든 층에 신규 equalDOF 복제**("위로 쭉").
  slave 중복 시 swap/skip, 노드쌍 중복은 seen_pairs 로 차단. rule_id='USER_ADD'.
  Scene.set_joint_override 가 같은 두 점 add 중복 제거.

### 3단계 — 저장 ✅ 완료 (1단계에서 선반영)

  `define_tab._load_scene_into_workspace`)가 `new_scene.joint_overrides` 를
  메인 scene 으로 복사하지 않던 누락을 4단계에서 함께 수정.

### 4단계 — 불러오기 시 선택 ✅ 완료 (2026-05-25)
- 불러오기 두 경로가 `joint_overrides` 복사 + `scene._joint_overrides_pending_choice`

- 접합부 조정 탭 진입 시 `main_3d._maybe_prompt_joint_choice`: 저장본이 있고 플래그가
  서 있으면 다이얼로그 "저장된 접합 사용 / 새로 자동 계산"(프리뷰 전에). 후자 선택 시
  `clear_joint_overrides()` → joint_rules 자동만. 결정 후 플래그 내림(재로드까지 1회).

## 5. 다층 자동 적용 로직

- 오버라이드 매칭은 **z 무시, xy(±tol) + 그룹 식별**로. 한 접합 오버라이드가 같은 xy 의 모든
  층 노드쌍에 적용됨 → 자동으로 "위로 쭉".
- 상대가 없는 층(그 xy 에 접합 자체가 없는 층)은 매칭 실패 → 자연 skip.

  못 빼므로 "등록 직전 반영"이 정답(후처리 불가). override 비면 즉시 원래 dofs 반환.
- ✅ **tol = 50mm** (`joint_override.MATCH_TOL_MM`). 노드 격자(3000mm+) 대비 충분히
  작아 인접 접합 오매칭 없음. 통합 테스트로 다층 매칭 검증.
- ✅ **"컴포넌트 간" 판정**: `pick_ops_joint_at` 가 `ca!=0 and cb!=0 and ca==cb` 면
  내부 보조로 제외. 코어 사영점 보조 결합(R09 core_proj, n1↔Q_nid)은 게이트 미적용
  (둘 다 코어 cid → 후보 X). 사영점이 source_comp_id=0 이면 후보 포함(안전).

### 잠재 이슈 (2~4단계에서 재검토)
- **같은 xy 에 수직 접합 2종 겹침**(모듈↔모듈 R02 + 패널↔모듈 R03 이 같은 코너 위치):
  xy 쌍 매칭이라 둘 다 휩쓸릴 수 있음. a_group/b_group 보조 식별은 저장만 하고
  매칭엔 미사용. 실제 발생 빈도·영향 확인 후 필요 시 group 매칭 추가.
- **재빌드 시 split 사영점 tag 안정성**: deterministic 가정. 어긋나면 강조선만 살짝
  빗나감(치명 X). 노드는 override 와 무관하게 생성되므로 master/slave tag 는 안정.
