작성 시점: 2026-05-30 (탐색 단계 완료, 결정 확정 후)

## 0. 확정된 결정 맥락 (질문으로 구체화한 내용)

수정방향 문서를 그대로 옮기지 않고, 대화로 확정한 결정을 먼저 못 박는다.

1. **모듈 정의 탭 병합 — 보류**
   - 탐색 결과: 모듈 정의 탭은 "배치 탭과 겉모습만 닮은 별개 작업공간"이 아니라,
     **건물(다층 장면)과 완전히 분리된 1개 층짜리 독립 캔버스**다.
     자체 장면·뷰어·컨트롤러를 가지며 단일층 모드로 동작하고, 여기서 만든 컴포넌트를
     라이브러리에 저장하면 배치 탭이 "가져오기"로 불러와 다층 건물에 올린다.
   - 다층 건물 장면 한가운데서 새 모듈을 만들면 "다른 부재와 안 섞인 깨끗한 정의"를
     만들기 어렵다는 구조적 문제가 있어, **이번 계획에서는 병합하지 않는다.**
   - 따라서 수정방향 1번(탭 병합)은 **이번 범위에서 제외**한다.
   - 단, 우측패널 5번(정의 라이브러리 → 컴포넌트 라이브러리 *이름 변경*)은 탭 병합과
     무관한 단순 제목 변경이므로 정의 탭 라이브러리 패널 제목만 바꿔 **포함**한다(Phase E5).

2. **63번째 줄 이후(물량탭 부재설계 + 고민사항) — 전부 제외**
   - 수정방향 문서 63~86줄(부재설계 선택옵션, 재계산/중심축/와이어프레임 고민사항,
     앞·뒤 진행 방향)은 **이번 작업 대상이 아니다.**

3. **상세 설계 — 단일 모드로 통합 (확정)**
   - 현재 "실·벽 배치 모드"와 "개구부 모드"는 별개의 상호배타 토글이다.
   - 변경 후: **"상세 설계" 토글 하나**만 두고, 그 모드 안에서 실 지정·벽·개구부
     버튼이 활성화되어 동작한다. "개구부 모드" 토글은 제거한다.

4. **타입 분류 판정 기준 (확정)**
   - **"크기가 같다" = 외형 치수(가로·세로·높이)가 같다.** 내부 부재 구성은 달라도 된다.
     비교 허용오차는 **5mm**.
   - **"실배치까지 같다" = 모든 조건이 같다(외형치수 + 실 배치 + 그 외 전부 동일).**
     이 경우 위치가 달라도 같은 번호로 통합한다. (구체 비교 필드는 Phase D 참조.)

5. **공통 UI 변경은 모듈 정의 탭에도 적용 (확정)**
   - 탭 병합은 보류하지만, **왼쪽 패널 버튼 명칭·구성 변경과 우측 속성 패널 변경,
     층수 컨트롤 이동은 모듈 정의 탭에도 동일하게 반영**한다.
   - 두 탭이 같은 패널 클래스를 공유하므로 클래스 수정은 자연히 양쪽에 적용된다.
     단 콜백·시그널 연결은 탭마다 따로이므로 양쪽 모두 점검한다.
   - 층수 컨트롤은 정의 탭에서 단일층이라 **숨김 상태를 유지**하되, 위치는 우측으로 함께 옮긴다.

## 1. 작업 범위

### 포함 (수정방향 2번 ~ 45번 영역, 단 탭 병합/우측5 제외)
- (A) 왼쪽 패널 개편 — 버튼 명칭·제거·상세설계 단일모드 통합, RC 코어 슬래브 자동 재생성
- (B) 3D 화면 — z축 단면(평면 절단) 슬라이더 신설, 바닥 그리드 제거, 부재 역할별 색상 적용
- (C) 2D 화면 — 배경 흰색, 부재 색 3D와 통일, 수직모듈 표현 통일, 컴포넌트 라벨 정비
- (D) 타입 분류 체계 재정의 — `모듈A-1-1` 방식 (가장 영향이 큼)
- (E) 우측 패널 — 층수 조절 이동, "활성 부재" 제거, ID 미표기 + 크기 표기, 타입 표기 적용, 라이브러리 제목 변경
- (F) 타입 표기 적용 — 2D 라벨 / 부재별 내부력 트리 / 물량 응력비 트리에 `모듈A-1` 반영

### 제외
- 모듈 정의 탭 병합 (수정방향 1번) — 단, 라이브러리 *이름 변경*은 단순 제목이라 포함(Phase E5)
- 물량탭 부재설계 및 고민사항 (수정방향 63~86줄)

## 2. 현재 코드 구조 (탐색으로 확인한 사실)

| 영역 | 현재 위치 | 현재 동작 |

| 메인 탭 | `ui/main_3d.py` | 7탭. `TAB_DESIGN`(배치 설계)이 본 작업 주무대 |
| 왼쪽 팔레트 | `ui/palette_panel.py` | 1~9 부재 버튼 + 선택해제(Esc) + RC코어슬래브재생성 + 실·벽 배치 모드(토글) + 실 그리기 + 벽 배치(내벽) + 개구부 모드(토글) + 개구부 추가. 실 모드 ↔ 개구부 모드는 **상호배타** |

| 층수 컨트롤 | `ui/alignment/alignment_view.py` 상단(2D 패널 안), `ui/controls/controls_f5.py` 와 연결 | 2D 화면 위쪽 SpinBox. 정의 탭은 숨김 |
| 3D 그리드 | `render/viewer_three_template.html` (GridHelper 1줄) | 바닥 격자 |
| 3D 색상 | `render/mesh_builder.py` 색상 상수 | 강재·콘크리트·벽 **전부 회색 계열, 역할 구분 없음** |
| 2D 라벨 | `ui/alignment/alignment_view.py` ("타입#번호" 형식) | 층마다 겹쳐 그림 |
| 타입 분류(표시) | `ui/analysis_panel.py` + `_utils/format.py`(`alpha_label`) + `ui/controls/controls_f6.py`(comp_labels 생성) | **xy 위치만**으로 소문자 a/b/c, "1층 a모듈" 식. 크기 무관. `_comp_meta`를 **부재별 내부력 트리 + 물량 응력비 트리가 공유**. **표시 라벨 전용** |
| 단면 설계·집계(계산) | `analysis/section_design.py`, `analysis/quantity_takeoff.py` | 부재 **역할 카테고리**(기둥/보/캔틸…) → 그룹 → 그룹별 채택 단면 → 물량·중량. 통일 정책(1·2·3종)이 그룹화 정밀도 결정. **타입 분류와 무관한 별개 축** |
| 라이브러리 가져오기 | `ui/main_3d.py` `_on_design_type_select` → `_import_definition_start` | 배치 탭에서 정의를 고스트로 불러와 배치 |

**핵심 사실**: 타입 분류(표시 라벨)와 단면 설계·집계(계산)는 **이미 별개의 축**이다.
- 표시 축: `_comp_meta`를 구조해석 트리·물량 트리가 공유 → 새 분류를 단일 소스로 만들어 두 트리에 같은 라벨을 흘려보낸다.
- 계산 축: 역할 카테고리 그룹화 → 단면·물량. **새 분류와 무관하므로 건드리지 않는다.**
- A-1-1(단면 세분화)만 계산 결과(부재별 채택 단면)를 *읽어서* 표시 라벨을 더 잘게 나눈다.

## 3. 페이즈 분할

독립적인 화면/패널 작업을 먼저(저위험), 전체에 파급되는 타입 분류를 중심에, 표기 적용을 마지막에 둔다. 각 페이즈 끝에 회귀(기존 테스트 + 골든마스터) 통과를 확인한다.

### Phase A — 왼쪽 패널 개편 (`ui/palette_panel.py`, 호출처)
대상: `palette_panel.py`, `ui/main_3d.py`(배치 탭 콜백), `ui/define_tab.py`(공유 콜백)
- A1. "선택 해제 (Esc)" 버튼 제거 (ESC 키 동작은 유지).
- A2. "RC 코어 슬래브 재생성" 버튼 제거 → 자동 재생성으로 대체(Phase A4).
- A3. 명칭 정정:
  - `[3] 구조벽` → `[3] 벽 패널`
  - `[8] 수직 3층 모듈` → `[8] 수직 모듈(3층)`
  - "실·벽 배치 모드" → "상세 설계"
  - "실 그리기" → "실 지정"
  - "벽 배치 (내벽)" → "벽"
- A4. **상세 설계 단일 모드 통합**: "개구부 모드" 토글 제거. "상세 설계" 토글 ON 시
  실 지정·벽·개구부 버튼을 활성화. 상호배타 토글 로직(`_on_room_mode_toggled`/
  `_on_opening_mode_toggled`) 통합·정리.
- A5. "개구부 추가" → "개구부"로 이름 변경 + **벽 버튼 바로 아래로 위치 이동.**
- A6. RC 코어 슬래브 **자동 재생성**: 코어벽 동작이 **완료될 때마다** 재생성한다.
  (배치 완료 / 이동 완료 / 복사 / 회전 / 층변경 확정 등 동작이 끝나는 시점.)
  드래그 중 매 프레임이 아니라 동작 종료 시점에 1회 호출.

### Phase B — 3D 화면 (`render/viewer_three_template.html`, `render/mesh_builder.py`, 뷰어)
- B1. 바닥 그리드 제거 (GridHelper 삭제).
- B2. **지정한 6가지에만 색상 적용**: 기둥 / 바닥보 / 천장보 / 슬래브 /
  비내력 벽체 / 창호(외부·내부 구분, **외부벽에 개구부가 있는 경우만**).
  이 6가지에 대해서만 `modular_designer.html`의 색상값을 그대로 가져와 적용한다.
  (그 외 부재나 'role 일반화' 같은 추가 색 분기는 하지 않는다.)
  현재 mesh는 부재 종류별 빌드 함수가 이미 나뉘어 있으므로, 해당 6가지의
  색 상수만 html 값으로 교체하면 된다.
- B3. **z축 단면(평면 절단) 슬라이더 신설**: 3D 화면 하단에 슬라이더.
  three.js clipping plane으로 특정 z 높이에서 수평으로 잘라 평면을 보이게 함.

### Phase C — 2D 화면 (`ui/alignment/alignment_view.py`, three.js 2D 템플릿)
- C1. 배경 흰색으로 변경.
- C2. 부재 색을 3D와 통일 (Phase B2 팔레트 공유).
- C3. 수직모듈 표현을 일반 모듈과 통일.
- C4. 컴포넌트 라벨 정비 — **1개 층 정보만** 표기, 위치는 **컴포넌트 중심**,
  실 지정 시 **라벨 겹침 방지**. 표기 형식은 Phase F에서 `모듈A-1`로.

### Phase D — 타입 분류 체계 재정의 ★ 핵심
대상: 신규 분류 모듈(단일 소스) + `_utils/format.py` + `ui/controls/controls_f6.py` + `ui/analysis_panel.py`

**전제 — 데이터 흐름 분석 결과 (구조해석·물량 추적)**
- 구조해석·물량의 **단면 설계/집계**는 *부재 역할 카테고리* 축이다:
  부재 → 카테고리(기둥/보/캔틸 등) → 그룹(`member_to_group`) → 그룹별 채택 단면(`sections_by_group`)
  → 물량·중량·운송. 통일 정책(1·2·3종)이 그룹화 정밀도를 정한다. **모듈A-1 분류와 무관.**
- 모듈A-1 같은 컴포넌트 분류는 *표시 라벨* 축(`_comp_meta`)이며, 부재별 내부력 트리와
  물량 응력비 트리가 **같은 데이터를 공유**해 위계만 그린다. 계산에는 쓰이지 않는다.
- 따라서 본 페이즈는 **표시 라벨 단일 소스**만 교체하면 되고, 단면 설계·물량 집계·운송
  결과에는 손대지 않는다(별개 축이라 파급 없음).
- D1. **분류 규칙(확정 기준)**:
  - 대상은 **종속되지 않는 독립 부재**만: 모듈 / 바닥패널 / 벽패널 / 수직 모듈(3층).
  - 1차(글자, 크기): 외형 치수가 다르면 `모듈A`, `모듈B` …
    **치수 비교 허용오차 = 5mm**(차이가 5mm 이내면 같은 크기로 본다).
  - 2차(번호, 위치): 같은 크기에서 위치가 다르면 `A-1`, `A-2` …
    단, **xy 좌표가 같고 층만 다르면 같은 번호**.
    **실배치까지 동일하면(아래 판정) 위치가 달라도 같은 번호로 통합.**
  - 3차(상세, 단면): 구조해석 후 단면이 달라지면 `A-1-1`, `A-1-2` … (물량 단계부터 사용).

  **"실배치까지 동일" 판정 (확정 — 비교 필드)**
  - 실(Room)은 부재에 직접 묶이지 않고 월드 좌표 폴리곤으로 정의되므로,
    각 모듈을 **로컬 좌표(모듈 기준점 평행이동 + 회전 정규화)**로 맞춘 뒤 비교한다.
  - 두 모듈이 다음을 모두 만족하면 "동일"로 보고 같은 번호로 통합:
    ① 소속 실들의 집합이 같다 — 각 실의 (정규화 폴리곤, 용도, 하중 지정값) 일치(순서 무관).
    ② 모듈에 종속된 내부 부재 집합이 같다 — 내벽·개구부·캔틸·중간보 등의
       (타입, 로컬 위치, 치수) 일치(순서 무관).
  - 좌표·치수 비교에는 1차와 같은 5mm 허용오차를 적용한다.
- D2. **단일 소스 함수**로 컴포넌트 → 라벨/그룹키를 산출(부재별 내부력 트리·물량 트리·우측 패널·2D 라벨 공용).
  - 입력: 장면(외형치수·위치·실배치) + (3차에 한해) 단면 설계 결과(부재별 채택 단면).
  - A-1-1은 단면 설계 결과를 *입력으로 읽기만* 하고, 단면 설계·물량 집계 로직은 건드리지 않는다.
- D3. 부재별 내부력 트리 위계 변경: 현재 "a모듈 / 1층 a모듈 / 역할 / 부재"를

## 4. 예상 문제 / 위험

1. **타입 분류 — 표시 축과 계산 축이 분리됨(분석으로 확인)**
   - 구조해석·물량의 단면 설계·집계는 *역할 카테고리* 축(`member_to_group` → `sections_by_group`),
     모듈A-1 분류는 *표시 라벨* 축(`_comp_meta`)으로 **이미 별개**다.
   - 새 분류를 **표시 라벨 단일 소스**로 만들면, 두 트리(내부력·응력비)의 라벨 일치만 보장하면 되고
     단면 설계·물량·운송 계산엔 파급이 없다. (애초에 이 통합을 위해 분류 체계를 새로 정의하는 것.)
   - 실제 주의점은 *분류 판정 정밀도*에 한정된다:
     · 외형 치수 비교 허용오차(mm 정수 반올림 등) 정의.
     · "실배치까지 동일" 비교에 포함할 데이터 필드 확정.
     · 수직 3층 모듈의 층 펼침 특수 처리와 호환 유지.

2. **색상 — 지정 6가지만, 테마 대비 점검**
   - 가져오는 대상은 기둥·바닥보·천장보·슬래브·비내력 벽체·창호(외부/내부, 외부벽 개구부만)
     **6가지뿐**이다. 그 외로 확장하지 않는다.
   - `modular_designer.html`은 어두운 테마(배경 #0d1117) 기준 색이라, 2D 흰 배경에서
     일부 밝은 색의 대비가 약할 수 있음 → 추출 후 가독성만 점검(필요 시 미세 조정).

3. **z 단면 슬라이더**
   - three.js clipping plane은 재질별 `clippingPlanes`/`renderer.localClippingEnabled` 설정 필요.
     기존 메쉬 생성 경로 전반에 적용해야 누락 없이 잘림.

4. **상세 설계 단일 모드 통합**
   - 기존 상호배타 토글 동기화 메서드(`set_room_mode`, `clear_special_modes`)의 호출처가
     배치 탭·정의 탭·컨트롤러에 흩어져 있음 → 통합 시 모든 호출처 점검.

5. **RC 코어 슬래브 자동 재생성**
   - 트리거는 코어벽 동작이 **완료되는 시점**(배치 완료/이동 완료/복사/회전/층변경 확정).
     드래그 중 매 프레임이 아니라 동작이 끝날 때 1회만 재생성한다.

6. **층수 컨트롤 이동(E1) — 단순 위젯 이동임(분석으로 정정)**
   - 층수 입력(라벨+스핀박스+단위)은 2D 패널 상단 row의 위젯일 뿐이고,
     값 변경 핸들러와 외부 API(현재 층수 읽기·외부 설정·표시 토글)가 이미 분리돼 있다.
   - 위젯을 우측 패널 위쪽으로 옮기고 **시그널만 다시 연결**하면 된다. 재생성 로직은 손대지 않는다.
   - 저장·불러오기 버튼을 2D 상단에 둘지 함께 옮길지만 정하면 됨(미해결 항목).

7. **탭 병합 보류의 잔여 영향**
   - 우측 속성 패널은 배치 탭·정의 탭이 공유하므로, Phase E 변경이 **정의 탭에도 동시 적용**됨(의도된 부수효과인지 확인 필요).
