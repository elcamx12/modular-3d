# 디자인 탭 2분리 계획서

"디자인 탭을 ① 모듈 정의 탭 + ② 배치 설계 탭으로 분리"하는 작업(노션 2.1)의
전체 계획 + **현재 구현 상태 핸드오프 문서**. 단계별로 이 문서를 기준으로 작업한다.
(컨텍스트 압축 대비 — 다음 세션이 이 문서만 읽고 이어서 작업할 수 있도록 상세히 기록.)

> **전체 진행 상태 (2026-05-24 기준)**
> - ✅ 1단계 탭 분리 + 정의 라이브러리(파일 영구 저장) / 정의 탭 단일층 고정
> - ✅ 2단계 실(폴리곤) 배치 + 부재식 조작(M/C/R/V/Z)

> - ✅ **사용자 내벽 배치** — `ComponentType.INTERIOR_WALL`(채움 판 1장, 두께 100,

## 0. 전체 그림 / 설계 원칙

- **모듈 정의 탭(①, 탭 index 0 "모듈 정의")**: 컴포넌트(모듈/패널/수직모듈)를 루트로,
  종속부재(중간보·중간기둥·캔틸레버보·캔틸레버슬래브)와 개구부·실까지(✅ 구현) 묶은
  하나의 단위를 만들어 **라이브러리(DB)에 저장**하는 곳. (벽은 모듈에 자동 4면 — A 참조.)
- **배치 설계 탭(②, 탭 index 1 "배치 설계", 기존 디자인 탭)**: 기존 부재 배치 +
  정의 탭에서 저장한 컴포넌트를 가져와 아파트를 설계. 실·벽·개구부 신규 기능도 사용.
- **격리 원칙**: 정의 탭은 배치 탭과 **별도 작업공간**(자체 Controller·Scene·Viewer·캔버스).
  기존 클래스/함수를 그대로 재사용해 동작을 최대한 동일하게.
- **저장 포맷**: 디자인 저장과 동일한 씬 직렬화(`io/scene_io.py`)를 공유.
  정의는 json 파일(DB)로 영구 저장(완료).

## A. 현재까지 구현된 것 (파일·함수 지도)

### A-1. 데이터 모델 — `model/definition_library.py`
- `ComponentDefinition` (dataclass): `name`, `state`(=scene_to_state_dict 결과 dict),
  `root_type`(루트 부재 comp_type 값 문자열, 예 'module'), `component_count`, `type_summary`.
  - `.to_scene()` → `(Scene, n_floors)` 복원.
- `DefinitionLibrary(path=None)` (dataclass):
  - `_items: {이름→ComponentDefinition}`. `path` 주면 **영구 저장 모드**.
  - `__post_init__`: path 있으면 `_load()`.
  - `add_from_scene(name, scene, n_floors=3)`: 직렬화 → `_detect_root_type`(제약 검사) →
    저장 + `save()`. 제약 위반 시 `ValueError`.
  - `get`, `list_names`(정렬), `remove`(+save), `__len__`.
  - `save()`: path 에 json 저장(디렉토리 자동 생성). 형식: `{version, definitions:[{name,
    root_type, component_count, type_summary, state}]}`.
  - `_load()`: json 읽어 `_items` 복원(없거나 손상 시 무시).
- `_detect_root_type(state)`: **저장 제약(강제)** 의 핵심.
  - roots = `parent_id==0` 부재들. roots 가 **모두 같은 group_id 한 묶음**이어야 함
    (단일 모듈/패널+종속들, 또는 단일 부재). 아니면 ValueError.
  - 반환 = roots[0].comp_type (정의의 루트 타입 → 1~9 매핑용).
  - **함정**: 멀티플로어. 모듈 1개를 N층으로 두면 같은 group_id 의 루트 부재 N개가
    생기는데, 같은 group_id 라 "한 묶음"으로 인정된다(저장 OK). 그래서 부재 개수가
    아니라 **group_id 기준**으로 판정한다.
- `_summarize(state)`: (부재수, 타입요약 문자열) 계산.
- 저장 위치(런타임): `<my_project>/definition_library/definitions.json`.

### A-2. 씬 직렬화 — `io/scene_io.py`
- `scene_to_state_dict(scene, n_floors) -> dict`: 파일 없이 메모리 dict 직렬화.
- `state_dict_to_scene(data) -> (Scene, n_floors)`: dict → Scene 복원(+ID 재배선·구버전 추정).
- 기존 `save_scene`/`load_scene` 는 위 두 함수에 **위임**(동작 동일, 단일 직렬화 경로).

### A-3. 모듈 정의 탭 — `ui/define_tab.py` (`DefineTab` 위젯)
- `DefineTab(status_mgr, library, parent=None)`: 상태바·라이브러리만 메인과 공유.
  자체 `_scene`(Scene), `_viewer`(Viewer3D), `_canvas_widget`, `_dim_panel`,
  `_props`(DesignPropertiesPanel), `_controller`(Controller(analysis_panel=None)),
  `_f5_panel`(AlignmentDockPanel), `_palette`(PalettePanel) 를 내부 인스턴스로 생성.
- 레이아웃: 좌 팔레트 + 중앙(자체 3D|2D QSplitter) + 우(속성 + 라이브러리 패널) + 하단 치수.
- 라이브러리 패널: `_lib_list`(QListWidget) + `_lib_name`(QLineEdit) + [저장][불러오기][새로][삭제].
  - `_refresh_lib_list()`: 목록 갱신 + `_lib_row_names`(행→이름) 매핑. __init__ 끝에서 1회 호출
    (시작 시 파일에서 불러온 정의 표시).
  - `_on_lib_save`: 이름+현재 scene → `library.add_from_scene`. 제약 위반(ValueError) 시 경고.
  - `_on_lib_load`: 선택 정의 → `_load_scene_into_workspace`(아래).
  - `_on_lib_new`: `_clear_workspace`.
  - `_on_lib_delete`: `library.remove`.
  - `_clear_workspace()` / `_load_scene_into_workspace(new_scene, n_floors)`:
    `controls_f5._f5_load_scene` 과 **동일 패턴**(scene/viewer/snap 비우고 재등록).
- `eventFilter`(자체 캔버스): 키→2D 캔버스 라우팅, 3D 좌클릭 비활성 등 — 배치 탭 로직과 동일.
- `on_enter()`: main 이 정의 탭 진입 시 호출 → 캔버스 포커스.

### A-4. main_3d 연결 — `ui/main_3d.py`
- 탭 인덱스 상수: `TAB_DEFINE=0, TAB_DESIGN=1, TAB_JOINT_EDIT=2, TAB_ANALYSIS=3,
  TAB_QUANTITY=4, TAB_TRANSPORT=5, TAB_JOINT_AIR=6, TAB_FINAL=7`. **main_3d 내부에서만 참조**
  (외부 import 없음 → 시프트 안전). addTab 순서도 이 순서와 일치해야 함.
- `self._definition_library = DefinitionLibrary(path=<my_project>/definition_library/definitions.json)`.
- `self._define_tab = DefineTab(self._status_mgr, self._definition_library)`, 탭 맨 앞에 추가
  ('모듈 정의'). 기존 디자인 탭은 '배치 설계'로 라벨 변경.
- 시작 화면: `setCurrentIndex(TAB_DESIGN)`(익숙한 배치 설계로 시작).
- `_on_tab_changed`: `TAB_DEFINE` 분기 추가(공유 위젯 reparent 불필요 — 자체 인스턴스라서.
  공유 dim/변형 위젯 숨기고 `_define_tab.on_enter()` 후 return).
- **배치 탭 1~9 인터셉트**: `self._controller._type_select_intercept = self._on_design_type_select`.
  - `_on_design_type_select(comp_type) -> bool`: 해당 root_type 의 저장 정의가 있으면
    QInputDialog 로 `['(새로 만들기)']+정의목록` 선택. 없으면 False(바로 새로). 취소→True,
    새로→False, 가져오기→안내 메시지 후 True(현재 실제 배치 미구현).
- AI 최적배치 제거에 따라 **props↔F5 층수 양방향 연동 배선 제거**(아래 A-6 참조).

### A-5. 인터셉트 funnel — `ui/controls_f5.py`
- `Controller._f5_on_type_key(comp_type)` 맨 앞에 훅 추가:
  `getattr(self,'_type_select_intercept',None)` 호출 → True 면 즉시 return(새로 흐름 생략).
- 이 함수는 **버튼(handle_palette_select→_f5_on_type_key)·키(1~9)** 둘 다의 funnel →
  훅 한 곳으로 버튼·키 모두 프롬프트 1회. 정의 탭 컨트롤러엔 훅 미주입(프롬프트 안 뜸).
- 종속 부재(4~7)는 DEPENDENCY_PICK 로 빠져 이 함수를 안 거침(애초에 루트가 될 수 없어 무관).

### A-6. AI 최적배치 제거 — `ui/design_props_panel.py`
- AI 최적배치 입력 폼(코어 수·세대수·베이·층수·면적·탐색버튼) 전부 삭제.

- 그에 따라 main_3d·define_tab 의 "props↔F5 층수 연동" 배선도 제거.
- **층수의 단일 컨트롤 = F5 패널(2D 캔버스 상단) SpinBox**. 그 `floors_changed` 는

## B. 단계별 계획 (진행 상태)

> **단계 번호는 기능 묶음 기준이며 실제 작업 순서와 다를 수 있다.** 4단계 일부(공유
> 라이브러리·저장제약·1~9 프롬프트)는 "1~9 새로/가져오기" 요청에 묶여 먼저 끝났다.
>
> **✅ 완료(2026-05-24): 정의 탭 단일층 1세트 고정.** 정의 = '건물 층 복제 없는 1개
> 인스턴스'. 정의 탭 컨트롤러에 `single_floor_mode` 도입 — 배치 시 3층분으로 만든 뒤
> `floor_index>0` 부재를 즉시 제거(모든 타입에서 floor_index==0 이 1층 1세트, 수직3층
> 모듈도 1개 인스턴스가 floor 0). 층수 입력 컨트롤 숨김 + 층수변경 복제 비활성, 저장은
> `n_floors=1`. (controls_f5 `_collapse_to_single_floor`/가드, alignment_view
> `set_floors_control_visible`, define_tab `single_floor_mode=True`.)
>
> **✅ 완료(2026-05-24): 2단계 실(폴리곤) 배치 — 그리기+데이터+2D/3D 시각화.**
