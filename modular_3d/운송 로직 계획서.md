## 0. 목적

전체 화물(모듈 + 모든 종류 패널)의 총 운송비가 최소가 되도록 회차를 분배한다.
운송비 정의 = 사용자가 프로젝트 설정에서 선택한 비용 모드 (3 가지):
1. 회차당 1회 고정비 (트럭 종류 무관 동일 단가)
2. 트럭 종류별 1회 고정비 (저상 60·광폭 70·A-frame 80 만원 기본)
3. 거리 × km단가 (트럭별 단가 가능)

## 1. 문제 성격 (왜 이렇게 푸는가)

다차원 보재형 빈 패킹 + 가변 비용 빈 선택의 결합 → **NP-hard**. 정확 해법(ILP·분기한정)은 화물 수 증가 시 비현실적. 산업 표준 처방을 따른다:

1. 여러 그리디 규칙으로 다수의 후보 해 생성
2. 각 후보 해를 국소 탐색으로 개선
3. 모든 후보 중 비용 최저 안 채택

기존 코드는 1번이 단일 규칙(무게 내림차순 FFD), 2번 없음. 운 나쁘면 비효율 회차가 굳음.

가중치 학습(머신러닝)은 *이상 정답* (라벨)이 없어 불가 — 대신 가중치 자체를 시드 차원에 포함해 *여러 조합을 비교 후 최저 선택* 한다 (§ 4).

## 4. 다중 시드 — 가중치 6 × 그리디 전략 4 + 무작위 30 = 54 후보

### 4.1 그리디 전략 4종 (차원 직교 — 정렬 + 분리 + 트럭선정 정책의 *서로 다른 종류* 를 한 통에)

| 이름 | 종류 | 동작 |
|---|---|---|
| `weight_desc` | 화물 정렬 | `-p.weight` 내림차순 |
| `volume_desc` | 화물 정렬 | `-(length × width × thickness)` 내림차순 |
| `dependent_first` | 화물 분리 정책 | 종속 패널 묶음을 정렬 키 *앞에* 두고 단순 패널은 그 뒤에 (둘 다 무게 내림차순) |
| `cost_efficiency` | 트럭 선정 정책 | 트럭 후보를 *원/kg 최저* 순으로 우선; 화물 정렬은 무게 내림차순 |

명칭 정정 사유: "정렬 기준 4 종"으로 묶이면 코드에서 4 개를 같은 함수 시그니처로 만들기 어려움. 정렬 / 분리 / 트럭선정 *세 종류* 가 섞여 있어 — Phase 1 의사코드에서 `GreedyStrategy` 인터페이스로 통일 (각 전략이 `(items, trucks) -> 정렬된_items, 트럭_점수_함수`를 반환).

### 4.2 가중치 6 조합 (α, β, γ — 길이/무게/높이)
```
weight_sets = [
  (1.0, 1.0, 1.0),  # 균형
  (2.0, 1.0, 1.0),  # 길이 강조
  (1.0, 2.0, 1.0),  # 무게 강조
  (1.0, 1.0, 2.0),  # 높이 강조
  (1.5, 1.5, 0.5),  # 길이·무게 동시 강조
  (0.5, 0.5, 2.0),  # 높이 단독 강조
]
```

### 4.3 무작위 시드
```
random_seeds = [기본시드 + i for i in range(30)]  # 기본시드는 코드 상수, 사용자 변경 가능
```
각 무작위 시드 i: `random.Random(seed_i)` 로 화물 셔플 → 그리디 패킹 → **후보 해 1 개 산출**. 30 개 시드 = **30 개 독립 후보**. 무작위 30 개 각각이 § 4.4 의 54 후보 중 하나이며, VND 도 30 개 각각에 별도 적용.

### 4.4 총 후보 수
그리디 전략 4 × 가중치 6 = **24 결정론 시드** + 무작위 30 = **54 후보**. 각 후보 독립 (병렬화 여지).

## 5. 단일 패킹 절차 (한 시드 = 한 번)

### 5.1 자원 추적 (트럭당)
```
잔여 화물 한도 = _effective_cargo_limit(truck, site) − 누적 화물 무게
잔여 바닥 길이 = (truck.max_length − 2 × edge_clearance) − ∑(바닥 패널 길이 + gap)
폭 검사값    = truck.max_width + 2 × side_overhang_mm
단별 잔여 높이 = (truck.max_height − vehicle_height_offset) − ∑(단별 max 두께)
```

### 5.2 자리 후보 3 자리
한 화물(자세 결정 후)에 대해 모든 트럭 × 3 자리를 시도:
- ① FLOOR — 트럭 유효 길이 빈 공간에 옆으로
- ② STACK — 같은 바닥 위 단 (단별 max 두께 합산, **위 단 length ≤ 아래 단 length 그리고 width ≤ 아래 단 width** 기하 제약). **LYING 자세만 STACK 가능** — STANDING 은 적층 후보에서 제외
- ③ DEP_INNER — 종속 패널 벽 안쪽 빈 슬롯 (기하 제약 미적용). **LYING 자세만 DEP_INNER 가능**

### 5.3 자세 차원
단순 wall 패널은 두 자세 모두 자리 평가에 넣어 비교. 결과 점수 좋은 자세·자리 채택. A-frame 트럭은 STANDING 호환만.

**STANDING 패널의 자리 제약**:
- ② STACK: 불가 — 세워진 패널 위에 적층 불가능
- ③ DEP_INNER: 불가 — 슬롯은 LYING 전제 공간
- ① FLOOR: A-frame 트럭에 *옆으로 나란히* 세움 적재만 (FLOOR 자리의 *세움 방식 변형*)

### 5.4 자리 평가 식 (Best Fit)
```
score = α × Δ길이_활용률 + β × Δ무게_활용률 + γ × Δ높이_활용률
```
가장 *높은* 점수 = 가장 빡빡하게 채우는 자리.

### 5.5 안전 4중 검사 (모든 자리 시도 시 강제)
**G 통일 시그니처**:
```
can_place(
  item: Module | Panel,
  posture: Posture,
  slot: PlacementSlot,
  truck_state: TruckState,  # 트럭 자체 + 잔여 자원 캡슐화
  site: SiteLimit,
  sp: SpacingParams,
) -> CheckResult
```
TruckState 가 `truck` 과 누적 자원을 함께 들고 있어 함수 인자에 두 개 안 받음 (역참조 명확).

검사 항목:
- ① 길이: 누적 + 새 길이 + gap ≤ 유효 길이
- ② 폭: 패널 폭(자세 반영) ≤ 폭 검사값, 그리고 현장 폭 제한
- ③ 높이: 단별 두께 합(자세 반영) ≤ 내공, 그리고 현장 높이 제한
- ④ 무게: 누적 + 새 무게 ≤ 실효 화물 한도

### 5.6 새 트럭 추가 시 트럭 선정
단일 패널 1장 기준이 아니라 **남은 모든 화물 통계**로:
```
score(truck) = (트럭 1회 고정비) / (그 트럭에 들어갈 *예상* 화물 무게)
예상 화물 무게 = 남은 화물을 무게 내림차순으로 시뮬레이션 적재한 합
```
점수 *낮은* 트럭(원/kg 최저) 우선.

**I "남은 화물" 정의**: *아직 어느 트럭에도 배치 안 된* 화물 (현 그리디 패킹 시점 기준). 이미 다른 회차에 배치 완료된 화물은 제외.

### 5.7 모듈 처리 — 4.5 m 합산 적재 (Q20)
기본: 1 트럭 = 1 모듈.
**예외**: 두 모듈 *각각의 길이 ≤ 4.5 m* 일 때 한 트럭에 **옆으로 나란히** 2 개까지 합산. (3 개 이상은 금지 — 결박 안전 + 단순화)
**H 명시 — 모듈끼리 적층 금지** (무게가 커서 위에 모듈 올리는 건 결박·안정성 문제). 두 모듈은 트럭 길이방향으로 *나란히* 배치만.
폭·높이는 트럭 한도 안에서 자유. 안전 4중 검사 동일 적용.

## 6. 국소 탐색 — VND (Variable Neighborhood Descent) 5종 수술

수술 종류를 작은 것 → 큰 것 순으로 적용. 큰 수술에서 개선되면 다시 1번부터 복귀.

```
1. Transfer (얕음) — 회차 A의 화물 한 장을 B로 이동
2. Swap (중간)    — A의 한 장 ↔ B의 한 장
3. Posture Toggle — 벽 패널 한 장의 자세를 뒤집고 재배치 (항상 ON 고정)
4. Merge (깊음)   — 두 회차 화물 합산이 한 트럭에 들어가면 합치고 회차 1 절감
5. Truck Downgrade — 회차 트럭을 더 싼 트럭으로 교체 가능한가
```

**J 보강 — 모듈 수술 시 4.5 m 합산 검사 강제**:
Transfer/Swap/Merge 가 *모듈*에 적용될 때, 결과 회차의 모듈 개수가 2 가 되려면 *둘 다 길이 ≤ 4.5 m* 검사 통과 필수. 3 개 이상은 거부. 안전 4중 검사 + 합산 검사 둘 다.

**K 보강 — Posture Toggle 시 좌표 z 갱신**:
자세 토글(LYING → STANDING 또는 그 역)이 발동되면 화물의 점유 차원이 바뀜:
- LYING: 점유 (length × width × thickness)
- STANDING: 점유 (length × thickness × width) — width 가 높이방향으로

따라서 Placement.truck_xyz 의 z 좌표 + 단별 잔여 높이 모두 재계산 책임이 Posture Toggle 수술에 있음. 재배치 단계에서 새 자세로 자리 평가 다시.

### 6.1 종료 조건 비교 측정 (Q14, 사용자 결정 — 모든 시드 둘 다)
**54 시드 × 2 종료 조건 = 108 패스를 *모두* 돌린다.**
초기 단계는 로직 우수성 판단용 데이터 수집이 1차 목표이므로 시간 2배 부담 감수.
- **무한 반복** — 더 이상 개선 없음까지 (정확)
- **500회 상한** — 상한 도달 시 종료 (빠름)

각 시드마다 두 결과를 산출하고, 최종 채택은 *무한 결과 중 최저 비용*. 500회 결과는 비교 데이터로만 MD 보고서에 누적.

MD 보고서 출력:
- 픽스처별 1 줄: `최종(무한 베스트) 비용 X·시간 Yms / 500회 베스트 X'·Y'ms / 차이 ΔZ%`
- 시드별 표 1 개: 54 행 × {시드, 무한 비용·시간, 500 회 비용·시간} (디버그용)

## 7. Lower Bound 가지치기

패킹 시작 전 이론 하한.

### 7.1 회차수 하한 (모듈 합산 반영)

```
# 패널 부분
panel_weight_lb = ⌈Σ 패널 무게 / max(실효 화물 한도)⌉
panel_length_lb = ⌈Σ 패널 점유 길이 / max(트럭 유효 길이)⌉
panel_trip_lb   = max(panel_weight_lb, panel_length_lb)

# 모듈 부분 — 4.5 m 합산 반영
N_module        = 전체 모듈 수
N_module_small  = 길이 ≤ 4.5 m 모듈 수
module_trip_lb  = (N_module − N_module_small) + ⌈N_module_small / 2⌉
                 # 4.5m 초과는 1트럭=1모듈, 4.5m 이하는 2개씩 묶음

회차수 하한 = panel_trip_lb + module_trip_lb
```

### 7.2 비용 하한 — 모드별

```
모드 1 (회차당 1회 고정비, 트럭 무관):
    비용 하한 = 회차수 하한 × 단가

모드 2 (트럭종류별 1회 고정비):
    비용 하한 = 회차수 하한 × min(트럭별 1회 고정비)
              # 사용자가 프로젝트 설정에서 변경한 *현재값*을 사용
              # 기본값 예시: min(저상 60, 광폭 70, A-frame 80) = 60 만원

모드 3 (거리 × km단가):
    비용 하한 = 회차수 하한 × 왕복거리 × min(트럭별 km단가)
```

후보 해 비용 ≤ 비용 하한 → 나머지 시드 + VND 즉시 스킵.

### 7.3 효과 정직 명시
- 폭·높이·기하 제약 때문에 진짜 최적 > 단순 하한인 경우 다수
- *시간 단축은 **0~40 % (데이터 의존)***

## 8. 무게중심 최종 시각 보정 (Q9·Q17·Q18)

### 8.1 적용 시점
**모든 회차 완성 후, 회차별 1회씩.** (자리 결정 단계에는 영향 없음.)

### 8.2 자유도
**같은 단·같은 자리 내에서만 x·y 슬라이드.** (단 간 교환 X — 적층 기하 제약과 *큰 부재 아래* 규칙이 본 로직에 이미 들어 있어 그것으로 충분.)

### 8.3 평가 식 — 길이 + 폭 둘 다
```
회차 무게중심 (xC, yC) = (Σ wᵢ xᵢ / Σ wᵢ, Σ wᵢ yᵢ / Σ wᵢ)
원점 = 트럭 적재함 중심
보정 목표 = minimize √(xC² + yC²)
```

### 8.4 종속 패널 정확 무게중심 (Q8 b)
근사 X. 정확 분리.

**L 보강 — 동음이의 변수 분리**:
- `panel.length` (Y 방향 패널 길이, mm)
- `panel.width` (X 방향 패널 폭, mm)
- `seg.length_mm` (변 위의 세그먼트 자체 길이, mm)
- `seg.thickness_mm` (벽 두께, mm)
- `seg.start_offset_mm` (변 시작점부터의 오프셋, mm)

식:
```
바닥 무게 w_floor = (둘레 보 자중) + extra_weight_kg
바닥 중심 (xF, yF) = (panel.width / 2, panel.length / 2)  # 패널 로컬좌표

각 wall_segment s 에 대해:
  w_s = (세그먼트 보 자중) + (세그먼트 기둥 자중 × 2)
  (xs, ys) = 세그먼트 중심 좌표:
    - side 0 (하변, Y=0):
        (s.start_offset_mm + s.length_mm / 2, s.thickness_mm / 2)
    - side 1 (우변, X=panel.width):
        (panel.width − s.thickness_mm / 2, s.start_offset_mm + s.length_mm / 2)
    - side 2 (상변, Y=panel.length):
        (s.start_offset_mm + s.length_mm / 2, panel.length − s.thickness_mm / 2)
    - side 3 (좌변, X=0):
        (s.thickness_mm / 2, s.start_offset_mm + s.length_mm / 2)

패널 무게중심 (xCOG, yCOG) = Σ(wᵢ × posᵢ) / Σwᵢ
```
이 패널 무게중심을 트럭 좌표계(트럭 적재함 중심 원점)로 변환해 회차 무게중심에 누적.

### 8.5 보정 알고리즘
회차 내 각 단/자리에서 패널의 *현 위치*를 시작점으로 x·y 방향 **10 mm 격자**로 이동을 시도해 회차 무게중심 거리가 최소가 되는 위치 채택 (각 단·자리 안에서 안전 4중 검사 통과 범위 내).

10 mm 격자는 사용자 결정값 — 시각 보정 용도이므로 mm 단위 정밀도까지 갈 필요 없고, 격자가 작을수록 보정 시간이 ∝ 1/단위² 로 증가.

### 12.1 자세 혼적 회차의 UI 표시 정책
panels_per_row / n_layers 는 *눕힘 패널 기준*만 카운트. 세움 패널은 별도로 `standing_count` 와 `has_mixed_posture` 로 표시.

## 14. 한계 (정직 명시)

- 이론적 최적성 보장 없음. 산업 휴리스틱 표준 — 진짜 최적의 95~99 %
- 운송 시간 / 휴식 / 도로 시간대 제약 미반영 — 프로젝트 범위 밖
- 모듈 3 개 이상 합산 금지 — 결박 안전 + 단순화
- 모듈끼리 적층 금지 — 무게·안전성
- 가중치 머신러닝 불가 (이상 정답 데이터 없음) → 시드 차원 탐색으로 대체
- Lower Bound 가지치기 효과는 데이터 의존 (0~40 %)
- VND 무한 vs 500 회 비교를 모든 시드 둘 다 측정 (D 결정) → 시간 부담 약 2 배. 초기 데이터 수집 후 한쪽으로 고정해 시간 절감 가능
- 자세 토글 수술이 항상 ON — 데이터에 따라 비용 절감 0 일 수도 있음. 그래도 시간 비용은 매번 발생
