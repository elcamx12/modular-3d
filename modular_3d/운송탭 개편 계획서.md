# 운송탭 개편 계획서

작성일: 2026-05-31
대상: `modular_3d` — 운송(Transport) 탭의 좌측 입력 패널 제거 + 우측 결과 패널 재구성
      + 모듈 페어링 길이 한도 확대 + 진단 알림창화 + 실행 버튼 3D 오버레이화

---

## §0. 목표 한 줄 요약

운송탭의 **좌측 입력 패널을 통째로 제거**하고 필요한 입력만 **우측으로 흡수**한다.
모듈 2개 동시 운송 페어링 한도를 **4.5m → 6m** 로 넓히고, 실행 버튼을 **중앙 3D 뷰
우상단 오버레이**로 옮긴다. 우측 결과 패널은 **총 운임 카드 추가 / 회차표 컬럼 정리 /
적재율→화물중량·최대화물중량 / 운임 컬럼 추가** 로 다듬고, **진단 누적 영역은 제거**하고
**정말 문제가 있을 때만 자동으로 뜨는 알림창**으로 대체한다.

## §1. 사용자 확정 사항 (대화 종합)

### 1-1. 모듈 페어링 한도 확대
- 두 모듈을 한 트럭에 옆자리 합산하는 조건이 현재 **둘 다 길이 ≤ 4.5m**.
  → **둘 다 길이 ≤ 6.0m** 로 확대. (트럭 길이 한도 초과 여부는 별도 검사가 유지되므로 안전.)

### 1-2. 좌측 패널 제거 + 우측 흡수
좌측 패널(① 상태 / ② 옵션 / ⑦ 참고자료 / 카탈로그 버튼)을 **통째로 제거**하고,
아래 규칙대로 처리한다.

| 좌측 항목 | 처리 |
|---|---|
| 트럭 카탈로그 관리 버튼 | **제거** (프로젝트 설정에 동일 기능 존재) |
| ① 상태 (정책 라벨 + 8단계 파이프라인 인디케이터) | **제거** |
| 운송 옵션(거리·운임방식·km단가·단위중량) | **우측으로 이동** (그대로) |
| 비내력벽 자동판별 ON/OFF 체크박스 | **UI 제거**, 내부적으로 **항상 ON** 고정 |
| 내부/외부 단위중량 | **우측으로 이동** (운임/물성 입력이라 유지) |
| 격자 크기 입력 | **UI 제거**, 내부 기본값(100mm) 고정 |
| FloorPanel 도 인접 장애물로 포함 체크박스 | **UI 제거**, 내부적으로 **항상 체크(True)** 고정 |
| 자동 재계산 체크박스 | **UI 제거** + 관련 디바운스/와이어링 코드 정리 |
| 디버그 저장 버튼 | **버튼 제거 + 내부 트레이스 저장 코드까지 삭제** |
| ⑦ 참고자료 버튼 | **우측 패널 최하단으로 이동** |
| ▷ 운송 계산 실행 버튼 | **중앙 3D 뷰 우상단 오버레이로 이동** |

### 1-3. 실행 버튼 위치 (사용자 확정)
- 운송탭은 자체적으로 **3단 분할(좌 입력 / 중앙 3D WebEngineView / 우 결과)** 구조다.
  좌측을 제거하면 **2단(중앙 3D + 우 결과)** 이 된다.
- 실행 버튼은 **중앙 3D 뷰 위에 떠 있는 오버레이 버튼**(우상단 모서리)으로 둔다.
  운송탭에서만 보이며, 3D 뷰 위에 absolute 배치 + resize 시 우상단 추종.

### 1-4. 우측 결과 패널 재구성
- **③ 결과 요약**: 기존 5카드(모듈 회차/패널 회차/총 회차/평균 적재율/총 거리)에
  **총 운임** 카드 추가.
- **회차표**(④ 서브탭) 컬럼 정리:
  - 현재: `회차 / 차량 / 종류 / 아이템 / 화물(kg) / GVW(kg) / 적재율(%)`
  - 변경: `차량 / 아이템 / 화물중량/최대화물중량 / GVW(kg) / 운임`
    - **회차 컬럼 제거** — 표 좌측 행 번호(1·2·3·4 vertical header)와 중복.
    - **종류 컬럼 제거** — 아이템 이름에 이미 종류가 드러나 의미 없음.
    - **적재율(%) → 화물중량/최대화물중량** — 한 칸에 `12,300 / 18,000 kg` 형식.
      별도 화물(kg) 칸은 통합되어 제거, GVW(kg)는 유지.
    - **운임 컬럼 추가** — 회차별 운임(경제성 데이터에서 trip_no 매칭).
- **⑤ 회차별 트럭 변경(override) 표**: 유지(언급 없음). 단 override 표 내부의 "회차" 헤더는
  검토 대상(이 표는 변경 대상 회차를 명시해야 하므로 회차 번호 유지가 타당 — 회차표와 별개).
- **경제성 서브탭 / 적재율 서브탭**: 유지(언급 없음).

### 1-5. 진단 → 알림창 (사용자 확정)
- **⑧ 진단(누적) 영역 통째 제거** (QTextEdit + 전체 지우기 버튼 + 누적 append 로직).
- 대신 **운송 계산이 끝난 뒤 "정말 문제가 있을 때만" 자동으로 알림창(QMessageBox)** 을 띄운다.
  - **표시 대상(진짜 문제)**: ❌ 운송 불가(blocked, 사유 포함) + ⚠ 경고(diagnostics.warnings).
  - **제외 대상(정보성)**: ℹ "캔틸레버 N개 → 부모 모듈에 흡수", "OO N개 운송 대상 제외",
    코어 숨김 등 **모든 정보성 줄**. 이런 게 없으면 알림창 자체를 띄우지 않음.
  - 문제가 하나도 없으면 **아무 창도 뜨지 않음**.

## §3. 변경 설계

### 3-A. 모듈 페어링 6m (transport 패커)
- **상수 추출 후 교체(구현 정정)**: `transport/models.py` 에 `MODULE_PAIR_MAX_LEN_MM = 6000.0`
  신설하고, 아래 페어링 비교식을 이 상수로 교체(중복 하드코딩 제거).
  - ⚠ 당초 계획은 `limits.py` 였으나, 직접 확인 결과 `limits.py` 는 *운송 가능성 검사기*
    (can_carry)로 이미 사용 중인 모듈이고 패커들이 import 하지 않는다. 세 패커가 모두 이미
    `from .models import ...` 하므로 **models.py(최하위 모듈)에 두면 import 추가 없이 일관**.
  - `packer_core.py` L285·L287(evaluate_slot), L429·L431(evaluate_slot v1), L1027(_merge_small_modules).
  - `packer_meta.py` L140(N_small 비용 하한).
  - `packer_local_search.py` L169·L347(Transfer/Swap/Merge 제약).
  - 주석(L269/L1010/L1246/L1469, packer.py L899 등)도 4.5m→6m 으로 갱신.
- **트럭/도로 4.5m 는 불변(조사 확정)**: trucks.json 의 `max_height: 4500`(4곳), references 도로높이
  4.5m, 테스트 픽스처의 4500/4.5 는 페어링과 무관 → **건드리지 않음**.
- **일관성 확인됨**: evaluate_slot(배치 시 검사) / _merge_small_modules(후처리 페어링) /
  packer_local_search(국소탐색) / packer_meta(비용 하한)가 모두 같은 임계를 공유 → 상수 한 곳
  교체로 모순 없음. V2 캐시 경로(packer.py L899)도 evaluate_slot 을 거치므로 자동 반영.
- ⚠ **트럭 길이 제약으로 실효 페어링 제한(사용자 인지 필요)**: 6m 모듈 2개 = 12m + 간격이라,
  현재 trucks.json 의 적재길이가 12m 인 저상·A-frame 에는 간격 때문에 안 들어가고 **광폭(18m)
  트럭에서만** 실제로 묶일 가능성이 크다. 동작은 `packer_safety.can_place()`(길이·중량 한도
  자동 검사, packer_safety.py L295~310·L348~374)가 막아주므로 **안전**하나, 한도 확대로
  페어링이 크게 늘지는 않을 수 있음. (트럭 적재길이를 키우려면 trucks.json 별도 조정 — 이번
  범위 아님.)
- 검증: py_compile + 6m 2개가 광폭에 묶이는지/6m 초과 안 묶이는지 + 운송 import 회귀.

#### (다) on_policy_sync 데이터 로직 보존(중대)

## §4. 물량탭 개편과의 충돌 분석 (사용자 요청 핵심)

물량탭 개편은 **다른 세션에서 진행 중**이며 계획서(`물량탭 개편 계획서.md`)가 존재한다.
양 계획서를 한 줄 단위로 대조한 결과:

### 4-1. 파일별 교차 매트릭스
| 파일 | 운송탭 개편 | 물량탭 개편 | 충돌 |
|---|---|---|---|
| `ui/transport_panel.py` | 좌측제거·우측재구성·회차표·진단 | **건드리지 않음** | **없음** |
| `transport/packer_core.py` | 4500→6000 | **건드리지 않음**(패킹 미사용) | **없음** |
| `transport/packer_meta.py` | 4500→6000 | 건드리지 않음 | **없음** |
| `transport/packer_local_search.py` | 4500→6000 | 건드리지 않음 | **없음** |
| `transport/loaded_3d_three.py` | **건드리지 않음** | 신규 함수 추가(`serialize_quantity_for_three` 등) + `hide_truck` 분기 | **없음** |
| `transport/adapter.py` | 건드리지 않음 | **읽기 전용** | **없음** |
| `ui/main_3d.py` | `_build_transport_tab_layout` + TAB_TRANSPORT 분기 | `_build_quantity_tab` + TAB_QUANTITY 분기 | **의미 충돌 없음** (서로 다른 메서드/분기) |
| `ui/analysis_panel.py` | 건드리지 않음 | `_classify_role_ko` 추출 등 | **없음** |

### 4-2. 결론
- 두 작업은 **데이터·기능상 거의 독립**. 운송탭 개편의 주력 파일(transport_panel.py, packer_*)은
  물량탭이 전혀 건드리지 않고, 물량탭의 주력(loaded_3d_three.py 신규함수·adapter·analysis·quantity)을
  운송탭이 건드리지 않는다.
- **유일한 공유 파일은 `ui/main_3d.py`**. 그러나 운송탭은 `_build_transport_tab_layout`/
  `TAB_TRANSPORT(=6)` 분기, 물량탭은 `_build_quantity_tab`/`TAB_QUANTITY` 분기로 **서로 다른
  지점**을 수정한다. **의미 충돌 없음.** 다만 같은 파일이라 **동시 저장 시 텍스트(머지) 충돌** 가능.
  - **대응**: main_3d.py 편집은 양 세션이 시간상 겹치지 않게 조율하거나, 한쪽 완료 후 다른 쪽이
    최신본을 다시 읽고 편집한다. (운송탭 작업의 main_3d 변경은 §3-C 한 메서드에 국한 → 범위 작음.)
- **운송 3D 시각화(loaded_3d_three.py)** 는 물량탭이 `hide_truck` 분기를 추가하지만 운송 경로
  (hide_truck 미설정)는 불변 유지가 물량탭 계획서의 전제(§6). 운송탭 개편은 이 파일을 안 건드리므로
  영향 없음. **운송 회차표/도식 동작이 물량탭 변경으로 깨지지 않는지**는 물량탭 Phase 2/5 회귀
  항목에 이미 포함되어 있음.
