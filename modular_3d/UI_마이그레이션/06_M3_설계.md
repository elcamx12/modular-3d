# M3 — 2D 시점 three.js 뷰 설계

작성: 2026-05-28
대상: 모듈정의·배치설계 탭의 *우측 2D 영역* (현재 `AlignmentDockPanel.canvas`,
vispy `QLabel + QPainter` 기반) 에 *읽기 전용* three.js 평면 뷰를 추가.
방식: Strangler — 기존 vispy 2D 옆에 새 three.js 뷰를 *세로 분할* 마운트.

---

## 핵심 결정 사항

### 1. 좌표계·카메라

- AlignmentCanvas 의 *world 좌표 (mm)* 를 그대로 사용. 단위·축 변환 없음.
- three.js 카메라 = `OrthographicCamera` — 위에서 내려다보는 평면 시점.
- camera.up = `(0, 1, 0)` — vispy 의 `_world_to_screen` 이 `y` 를 화면 위로 매핑하는 컨벤션과 일치.
- 카메라 위치 z = +100000 (멀리), `lookAt(cx, cy, 0)`.
- `left/right/top/bottom` 은 `_zoom`·`_pan_x`·`_pan_y` 와 동기화 — vispy 의 *zoom·pan 값 그대로 전달* 받아 OrthographicCamera viewport 재계산.

### 2. 데이터 push 방식 — sync_callback 후크

- AlignmentCanvas 본체에 *단 한 줄 후크* `_three_sync_callback` 신설 (default None).
- AlignmentCanvas.paintEvent (또는 update() 직후) 에서 후크 호출 → 외부에 dump.
- 후크 미설정이면 no-op — 회귀 0.
- AlignmentDockPanelThree 가 self.sync(state) 메서드로 후크 등록.

### 3. dump 형식 — `_collect_paint_state()` 신설

AlignmentCanvas 에 상태 dump 메서드 추가 (paint 흐름과 같은 데이터 제공):

```python
def _collect_paint_state(self) -> dict:
    """three.js 측에 push 할 paint 상태 전체."""
    return {
        'viewport': {'zoom': self._zoom, 'pan_x': self._pan_x, 'pan_y': self._pan_y,
                     'width': self.width(), 'height': self.height()},
        'layer': self._layer,
        'state': self._state,
        'selected_id': self._selected_id,
        'hover_id': self._hover_id,
        'direction': self._direction,
        'reference_edge': self._reference_edge,
        'edit_mode': self._edit_mode,
        'f5_in_preview': self._f5_in_preview,
        'f5_pending_dep_type': ...,
        # 부재 사각형 데이터 (역할별)
        'components': [
            {'id': cid, 'comp_type': ..., 'rects': [...], 'group_id': ...,
             'merged_partner_ids': [...], 'misaligned': bool, ...}
            for cid in visible_ids
        ],
        # 실 데이터
        'rooms': [{'id': rid, 'polygon': [[x,y],...], 'room_type': ...}, ...],
        # 미리보기 상태들
        'room_preview': {...} or None,
        'op_preview': {...} or None,
        'import_preview': {...} or None,
        'f5_snap_point': [x, y] or None,
        'room_snap_point': [x, y] or None,
        'room_draw': {'active': bool, 'points': [...], 'cursor': [x,y]},
        ...
    }
```

JSON 직렬화 가능 dict. three.js JS 측 `window.applyPaintState(state)` 함수가 받아 *전체 다시 그림*.

### 4. 매 paint 마다 전체 redraw — 단순성 우선

각 update() 마다 *모든 부재/실 메쉬를 dispose 후 새로 생성*. 부재 수 100+ 일 때 성능 측정 필요 (M3-c 단계).

최적화 옵션 (필요 시 도입):
- 컴포넌트 dict 비교 후 변경분만 갱신
- InstancedMesh 사용

### 5. AlignmentDockPanelThree 어댑터

- `QWidget` 으로 — 내부에 `AlignmentCanvasThree` (QWebEngineView) 보유
- `sync(state: dict)` 메서드 — JS 측 `applyPaintState(state)` 호출
- AlignmentDockPanel 옆에 *세로 분할 마운트* (M2 의 Strangler 패턴과 같음)

### 6. AlignmentCanvas 본체 최소 침습

추가하는 것:
- 인스턴스 변수 `self._three_sync_callback = None` (init)
- paintEvent 끝에 `if self._three_sync_callback: self._three_sync_callback(self._collect_paint_state())`
- 메서드 `_collect_paint_state()`

기존 paintEvent 본문 *전혀 안 건드림*. _world_to_screen 도 그대로.

## 위험·한계

1. **성능** — 매 paint 마다 전체 redraw 라 부재 100+ 일 때 느릴 수 있음. 측정 후 최적화.
2. **글자·텍스트** — three.js 의 텍스트는 sprite 또는 CSS2DRenderer 사용. 한글 폰트 처리 까다로움. M3-c 에서 도움말·거리 표시 시 검토.
3. **격자** — vispy 는 100mm 그리드를 그리지 않음 (AlignmentCanvas paintEvent 가 직접 격자 안 그림). 두 뷰 일관성 위해 *three.js 도 격자 없이* 시작. 사용자 요청 있으면 추가.
4. **반시계 90도 회전** — M2 의 카메라 보정과 같은 이슈가 OrthographicCamera 에도 있을 가능성. M3-b 마운트 후 사용자 spot-check 1차에서 확인.
