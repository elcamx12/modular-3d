# 화면 구조 명세 (M0 산출물)

작성: 2026-05-28
대상: 모듈정의 탭 + 배치설계 탭 (마이그레이션 대상 핵심)
참고: 다른 탭(접합부 설계·해석·물량·공정표·평가·운송)도 main 창에 함께 있으나
본 마이그레이션 대상은 위 2개 탭의 *좌 3D / 우 2D 분할 화면* 뿐.

## 전체 메인 창 — 탭 구성

`ui/main_3d.py` `MainWindow`. 상단 `QTabWidget` 으로 다음 탭이 순차 배치:

| 인덱스 | 탭 이름 | 클래스 / 빌더 | 마이그레이션 대상? |
|---|---|---|---|
| 0 | 모듈 정의 | `DefineTab` (`ui/define_tab.py`) | **예** |
| 1 | 배치 설계 | `MainWindow._build_design_tab()` | **예** |
| 2 | 접합부 설계 | `MainWindow._build_joint_tab()` | 아니오 |
| 3 | 구조 해석 | `MainWindow._build_analysis_tab()` | 아니오 |
| 4 | 물량 | `MainWindow._build_quantity_tab()` | 아니오 |
| 5 | 공정표 | `SchedulePanel` (QWebEngineView) | 이미 three.js |
| 6 | 평가 | `EvaluationPanel` | 아니오 |
| 7 | 운송 | `TransportTab` (QWebEngineView) | 이미 three.js |

탭 전환 트리거: `MainWindow._on_tab_changed(idx)` — 공유 위젯(2D 캔버스 등) reparent + 어댑터 호출.

## 모듈 정의 탭 — 위젯 트리

`DefineTab(QWidget)`. 자체 Scene·Viewer·Controller 보유 (배치 탭과 완전 독립).

```
DefineTab (QHBoxLayout, spacing=2)
├── PalettePanel  [좌] 폭 220px
│   ├── 모듈 타입 버튼 1~9
│   ├── "실 모드" 토글
│   ├── "실 그리기" 버튼
│   ├── "개구부 모드" 토글
│   ├── "개구부 추가" 버튼
│   ├── "벽 배치" 버튼
│   └── "코어 슬래브 재생성" 버튼
├── 중앙 (QVBoxLayout)
│   ├── QSplitter (Horizontal, 비율 7:3, 초기 700:300, 접힘 금지)
│   │   ├── Viewer3D.canvas_widget  [좌 3D] vispy SceneCanvas + CustomCamera
│   │   └── AlignmentDockPanel       [우 2D] vispy 기반 canvas (시점만 평면)
│   │       ├── 상단 SpinBox (n_floors) ※ 정의 탭은 숨김
│   │       ├── canvas (AlignmentCanvas)
│   │       └── 저장/불러오기 버튼
│   └── DimensionInputPanel  [하] 치수 입력 영역
└── 우 (QVBoxLayout)
    ├── DesignPropertiesPanel  폭 320px (실 선택 시 숨김)
    │   ├── 활성 타입 표시
    │   ├── 선택 부재 단면 타입 (각형강관 / H형강)
    │   └── 선택 부재 치수 표시
    ├── RoomPropertiesPanel  (실 선택 시만 표시)
    │   ├── 실 종류 (실 분류)
    │   ├── 적재하중
    │   ├── 마감하중
    │   └── 삭제 버튼
    └── QGroupBox "정의 라이브러리" (stretch=1)
        ├── QListWidget (정의 목록)
        ├── QLineEdit (이름 입력)
        ├── 저장 / 불러오기 / 새로 / 삭제 버튼 4개
        └── "건물 파일에서 불러오기" 버튼
```

### 모듈 정의 탭 특수성
- `controller.single_floor_mode = True` — 정의는 항상 1층 1세트
- 2D 캔버스 상단 층수 SpinBox 숨김 (`set_floors_control_visible(False)`)
- 3D 캔버스 좌클릭 *의도적 비활성* — 부재 선택·배치는 2D 캔버스에서만
- 3D 캔버스 키 입력 → 2D 캔버스로 라우팅 (`self._f5_panel.canvas.keyPressEvent(event)`)

## 배치 설계 탭 — 위젯 트리

`MainWindow._build_design_tab()` 가 빌드. 정의 탭과 매우 유사하나 *층수 자유* + *최적배치 제거* 후 단순화.

```
배치 설계 탭 (QHBoxLayout)
├── PalettePanel  [좌] 폭 220px  (정의 탭과 동일 구성)
├── 중앙 (QVBoxLayout)
│   ├── QSplitter "_design_center_split" (Horizontal, 7:3)
│   │   ├── _design_left_pane  [좌 3D]  Viewer3D 위젯 마운트 대상
│   │   └── _design_right_pane [우 2D]  AlignmentDockPanel.canvas 마운트 대상
│   └── DimensionInputPanel  [하]
└── 우 (QVBoxLayout)  폭 320px
    ├── DesignPropertiesPanel
    └── RoomPropertiesPanel  (실 선택 시 표시)
```

### 배치 탭 특수성
- Viewer3D / Controller / Scene 은 *MainWindow 인스턴스의 self._viewer / self._controller / self._scene* — 공유 위젯
- 2D 캔버스(`self._f5_panel`)도 MainWindow 보유. 탭 전환 시 `_on_tab_changed` 가 panes 로 reparent
- 정책: 타입 선택 시 *이미 정의된 정의가 있으면* "새로 만들기 / 가져오기" 프롬프트 — `_on_design_type_select` 인터셉트
- 층수는 2D 캔버스 상단 SpinBox 가 단일 컨트롤

## 공유 위젯 — 정의 탭 ↔ 배치 탭 경계

정의 탭은 *자체 인스턴스* 를 가짐. 배치 탭은 *MainWindow 인스턴스* 를 씀. 공유는 다음만:

- `status_mgr` (상태바 매니저)
- `definition_library` (정의 라이브러리 — 정의 탭이 저장, 배치 탭이 사용)

즉 정의 탭 변경이 배치 탭 3D 에 즉시 반영되지 *않음*. 두 탭은 *독립 작업공간*. 이게 마이그레이션 시 *두 탭 각자 따로 three.js 뷰를 가져야 한다* 는 뜻 — 자원 두 배지만 격리는 강함.

## 화면 분할 비율·접힘 정책

| 항목 | 값 |
|---|---|
| 중앙 QSplitter 방향 | `Qt.Horizontal` |
| 좌(3D) / 우(2D) stretchFactor | 7 / 3 |
| 초기 크기 | 700px / 300px |
| `setChildrenCollapsible` | False (양쪽 다 숨김 금지) |
| 사용자 드래그 핸들 | 활성 (자유 조정 가능) |

three.js 마이그레이션 시 *위/아래 Strangler 분할* 추가:
```
[기존 중앙 영역]
├── 위 (vispy)   기존 Splitter (3D | 2D)
└── 아래 (three.js) 새 Splitter (3D | 2D)
```
세로 QSplitter 로 비율 1:1 시작, 사용자가 조정 가능. 모든 시나리오 검증 후 위쪽(vispy) 제거.

## 이벤트 흐름 — 모든 마우스·키 입력의 길

```
[사용자 입력]
   ↓
[Qt 캔버스 위젯] (Viewer3D.get_native_widget() / AlignmentCanvas)
   ↓
[eventFilter / keyPressEvent / mousePressEvent ...]
   ↓                                 ↓
[자체 처리 (카메라 회전·줌)]    [Controller.on_qt_mouse_press / on_qt_mouse_move / on_qt_key_press]
                                     ↓
                                [모드별 분기 (component/room/opening)]
                                     ↓
                                [Scene 변경 + Viewer 갱신 + Snap 갱신]
                                     ↓
                                [시그널 emit → 패널 갱신]
```

**three.js 마이그레이션 시 보존해야 하는 단단한 경계**:
1. `Controller.on_qt_mouse_press(button, pos)` 시그니처 — *유지*
2. `Controller.on_qt_mouse_move(pos)` — *유지*
3. `Controller.on_qt_key_press(text, qt_key)` — *유지*
4. `Scene.components / rooms` 모델 변경 결과 — *완전 동일* (골든 마스터 비교 기준)

JS 측은 마우스/키 이벤트를 받아 *동일 시그니처로* QWebChannel 호출만 하면 됨. 모델·시그널 흐름은 손대지 않음.

## vispy → three.js 마이그레이션 대상 컴포넌트 목록

| 영역 | 현재 (vispy) | three.js 대응 |
|---|---|---|
| 메인 3D 캔버스 | `render/viewer.py` `Viewer3D` | 새 `Viewer3DThree` (운송탭 자산 재사용) |
| 카메라 (회전·줌·팬) | `CustomCamera(scene.TurntableCamera)` | `OrbitControls` 커스텀 |
| 2D 평면 캔버스 | `ui/alignment/alignment_view.py` `AlignmentCanvas` | 새 `AlignmentCanvasThree` (OrthographicCamera) |
| 부재 메쉬 | `render/mesh_builder.py` `build_component_mesh()` | JS 측 메쉬 빌더 |
| 실 색면 | `render/room_mesh.py` | JS 측 실 메쉬 |
| 스냅 가이드 | `render/snap.py` | JS 측 라인 오버레이 |
| 개구부 표시 | `render/opening_mesh.py` | JS 측 개구부 표현 |

이벤트 시스템·컨트롤러·모델은 *전부 그대로 둠*.
