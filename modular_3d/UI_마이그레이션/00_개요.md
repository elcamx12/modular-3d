# UI 마이그레이션 계획 — vispy → three.js

작성: 2026-05-28
대상: 모듈정의 탭 + 배치설계 탭 (좌 3D / 우 2D 분할 중앙 화면)
목표: 발표용 시각 디자인 개선 + 향후 웹 배포 토대.
완성 기준: 부재 길이·위치·회전·앵커·갭이 마이그레이션 전후 *완전히 동일* (자동 회귀 통과) + 사용자 시각·체험 spot-check 통과.

---

## 핵심 원칙

1. **국부 수정이 아니다 — 아키텍처 변경이다.** Python in-process(vispy) → JS 별 프로세스(three.js). 상호작용 한 줄마다 양방향 브리지가 새로 정의돼야 한다.
2. **기능 보전 우선.** 비효율적이거나 이상해 보여도 의도가 있을 수 있으므로 보전. 동작과 결과가 동일하면 내부 구현은 옮겨도 되지만, *외부에서 관찰되는 동작* 은 절대 바꾸지 않는다.
3. **Strangler Fig (병행 운영).** 작업 기간 동안 *위*에 기존 vispy, *아래*에 새 three.js 뷰를 동시 마운트. 사용자가 양쪽 비교 가능. 모든 시나리오 검증 후에만 vispy 제거.
4. **검증 분담.**
   - AI 영역 — 부재 좌표·길이·회전·앵커·갭·joint·정책 변경 등 *모델 데이터* 회귀. 골든 마스터 JSON 비교로 자동화.
   - 사용자 영역 — 픽킹 1픽셀 정확도, 스냅 가이드 시각, 카메라 회전 중심 느낌, 드래그 부드러움 등 *체험* 영역. 체크리스트 따라 spot-check.
5. **모든 단계는 회귀 0 유지.** 한 단계 끝날 때마다 기존 vispy 동작 회귀 없음 확인 + 새 three.js 단독 검증.

## 현재 코드 사실 (정찰 결과)

### 분할 화면 구조
- 디자인(배치설계) 탭: 좌 팔레트(180~220px) + 중앙(좌 3D | 우 2D 가로분할, 7:3) + 우 속성(320px) + 하단 치수 입력
- 모듈정의 탭: `DefineTab` 클래스 — 자체 Scene·Viewer·Controller 보유 (배치 탭과 완전 분리). 상태바 매니저 + 정의 라이브러리만 공유.
- 좌 3D: `render/viewer.py` 의 `CustomCamera(scene.TurntableCamera)` + `scene.SceneCanvas`
- 우 2D: `ui/alignment/` 의 `AlignmentDockPanel.canvas` — *vispy 기반 (시점만 2D)* 으로 추정. UI-M0 단계에서 확정 필요.

### vispy 사용처 (전부 마이그레이션 대상)
- `render/viewer.py` — 메인 3D 뷰어, 카메라
- `render/snap.py` — 스냅 투영 (vispy scene transform 사용)
- `render/room_mesh.py` — 실 메쉬 렌더
- `ui/main_3d.py` — 캔버스 위젯·이벤트 필터
- `ui/controls_geom.py`, `ui/controls/__init__.py` — 마우스/키 컨트롤
- `ui/alignment/alignment_helpers.py` — 2D 뷰 헬퍼
- `analysis/room_loads.py` — 해석 영역에서 일부 사용

### 운송탭 자산 재사용 가능
- `transport/loaded_3d_three.py` (1345줄) — 이미 three.js + QWebEngineView + 클릭/드래그 상호작용 구현됨. *메쉬 빌더·브리지 패턴 그대로 재사용*. 가장 큰 자산.

### 골든 마스터 자료
- `종설/scene.json`, `scene0-1.json`, `scene1.json` ~ `scene5.json`, `scene_merge_test.json` 등 8개 + 사용자 신규 분량
- scene.json 구조: 부재 단위 완전 명세 (id, comp_type, position, rotation, dimensions, anchor, group_id, floor_index, sub_index, anchor_edge_id, mid_beam_level, merge_with_panel, merged_fp_id, merged_wall_ids, parent_id, joint_records)

## 단계별 계획 (Task M0 ~ M8)

| 단계 | 내용 | 영역 | 위험 |
|---|---|---|---|
| M0 | 인벤토리 확장 + 시나리오 카탈로그 | AI + 사용자 | 낮음 |
| M1 | 골든 마스터 회귀 시나리오 구축 | AI + 사용자 | 낮음 |
| M2 | three.js 표시 전용 뷰 신설 (읽기) | AI | 중간 |
| M3 | 2D 시점 three.js 뷰 추가 | AI | 중간 |
| M4 | 상호작용 브리지 — 픽킹·선택 | AI | 높음 |
| M5 | 상호작용 브리지 — 드래그·키·스냅 | AI | 매우 높음 |
| M6 | 편집 모드 전체 이관 | AI | 매우 높음 |
| M7 | 사용자 시각·체험 검증 | 사용자 | 검증 |
| M8 | vispy 제거·정리 | AI | 낮음 (M7 통과 후) |

각 단계 끝마다:
1. 자동 회귀 (골든 마스터 비교) 전 시나리오 통과
2. 사용자 spot-check (체크리스트 양식 따라)
3. 둘 다 OK 면 다음 단계

## 사용자 결정 사항 (확정)

1. 발표 일정 무관 — 무조건 성공 (시간 충분히 들임).
2. 자동화 테스트 + 사용자 검증 분담 OK — *모델 데이터는 AI 자동 보증, 시각·체험은 사용자 spot-check*.
3. Qt 메인창 + QWebEngineView 임베드 (현재 운송탭과 동일 패턴).
4. Strangler Fig (위 vispy / 아래 three.js 병행) OK.
5. 사용자 검증 체크리스트는 *고민 없이 따라할 수 있을 정도로 매우 상세* 하게 작성.
6. UI 마이그레이션 자료는 *별도 폴더* (현재 폴더). 기존 인벤토리에 끼워넣지 않음.
7. 웹 배포 (접합부 설계·구조해석·물량 영역 마이그레이션) 는 본 작업 완료 후 별도 단계.
