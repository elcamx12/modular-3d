# M4 — 상호작용 브리지 (클릭 픽킹·선택·하이라이트) 설계

작성: 2026-05-28
대상: 2D three.js 뷰가 *마우스 입력의 주체* 가 되어, 클릭·호버를 직접 받아
기존 선택·하이라이트 로직(Python AlignmentCanvas)에 연결.

---

## 배경 — 사용자 통찰 (끊김의 근본 원인)

- M2 의 3D three.js 는 *자체 OrbitControls* 로 마우스를 직접 받음 → 60fps 부드러움.
- M3 의 2D three.js 는 *vispy 입력에 의존* — vispy 가 paint 할 때만 동기화됨.
  vispy paint → Python dump → JSON 전송 경로의 비용 때문에 끊김.
- **입력 주체가 다른 게 끊김의 본질.** M4 에서 three.js 2D 가 입력 주체가 되면
  근본 해결로 이어진다.

---

## 핵심 결정

### 1. three.js 2D 가 마우스 입력의 주체

three.js 캔버스에 직접 마우스 리스너 (mousedown/move/up/click/wheel) 부착:
- **팬·줌** → three.js *자체 카메라 조작* (OrthographicCamera frustum/position 직접 변경).
  vispy viewport 동기화에 의존 안 함 → 60fps 부드러움.
- **클릭** → OrthographicCamera 로 화면→world 좌표 unproject → `bridge.on_2d_click(wx, wy, button)` → Python.
- **호버 (move)** → world 좌표 → `bridge.on_2d_move(wx, wy)` → Python (REFERENCE 상태 등).

### 2. 기존 선택 로직 100% 재사용 — Python 이 world 좌표로 처리

three.js 는 *world 좌표만* Python 에 전달. Python `AlignmentCanvas` 가 그 좌표로
기존 `_hit_test_component` / 선택 / 상태 전이를 수행. 즉 *선택 알고리즘은 한 줄도
새로 안 짠다* — three.js 는 입력 좌표만 넘기는 얇은 통로.

신설 메서드 (AlignmentCanvas):
```python
def handle_world_click(self, wx, wy, button):
    """three.js 2D 클릭 — screen 대신 world 좌표를 직접 받아 기존 로직 수행.
    기존 mousePressEvent 의 좌표 변환 부분만 우회하고 동일 분기 재사용."""
```

### 3. 양방향 동기화 흐름

```
[three.js 2D 클릭]
   → bridge.on_2d_click(wx, wy, button)   (QWebChannel, JS→Python)
   → AlignmentDockPanelThree 가 vispy AlignmentCanvas.handle_world_click 호출
   → AlignmentCanvas 가 선택/상태 변경 + selection_changed 등 시그널 emit
   → 우측 속성 패널 갱신 (기존 흐름)
   → AlignmentCanvas.update() → paintEvent → _three_sync_callback → three.js 갱신
      (M3 의 표시 경로 — 선택 하이라이트가 three.js 에도 반영)
```

즉 *입력은 three.js, 처리는 Python(기존), 표시는 양쪽*. vispy 캔버스도 같은 모델을
보므로 동시에 갱신됨 (Strangler 비교 유지).

### 4. 카메라 독립 — vispy 와 시점 따로

three.js 2D 가 자체 팬·줌하면 vispy 2D 와 *시점이 따로 놀 수 있다*. 단점이지만:
- 끊김 해결이 우선 (사용자 결정).
- 비교 검증 시 시점 다른 건 큰 문제 아님 (부재 위치·관계는 동일).
- 선택·하이라이트 등 *내용* 은 동기화되므로 비교 가능.

옵션: "vispy 시점 따라가기" 버튼/토글을 둘 수도 있으나 M4 범위 외.

### 5. bridge 인터페이스 (QWebChannel)

`_AlignmentThreeBridge` (이미 있음) 에 슬롯 추가:
- `on_2d_click(wx: float, wy: float, button: int)` — 클릭
- `on_2d_move(wx: float, wy: float)` — 호버
- `on_2d_key(key: int, text: str)` — 키 (M5 에서 사용)

button: 0=left, 1=right, 2=middle (JS event.button 규약과 매핑).

### 6. AlignmentDockPanelThree 가 bridge ↔ vispy canvas 연결

bridge 가 받은 좌표를 `_attached_canvas` (vispy AlignmentCanvas) 의
`handle_world_click` / `handle_world_move` 로 위임.

## 위험·한계

1. **카메라 독립** — vispy 와 시점 따로. 사용자 수용 확인됨 (끊김 우선).
2. **이중 입력 경로** — vispy 캔버스도 여전히 입력 받음. 두 경로가 같은 모델을
   변경하므로 *상태 충돌* 가능성. M4-b 에서 신중히 — three.js 클릭도 결국
   같은 AlignmentCanvas 메서드를 부르므로 단일 상태 유지.
3. **좌표 정합** — three.js unproject 결과 world 좌표가 vispy `_screen_to_world` 와
   동일한 mm 좌표인지 검증 필요 (M4-b).
4. **편집(드래그·키)** 은 M5 범위. M4 는 *클릭 선택·호버* 까지만.
