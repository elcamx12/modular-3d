# UI 마이그레이션 완료 요약 (vispy → three.js)

작성: 2026-05-28
대상: 모듈정의 탭 + 배치설계 탭
결과: 두 탭이 **three.js 단독 표시**. 모든 편집 기능 동작. 끊김 해결.

---

## 무엇이 바뀌었나

### 표시 (화면)
- 모듈정의·배치설계 탭의 좌 3D / 우 2D 가 **three.js** 로 표시.
- vispy(흰 배경 3D / 어두운 QPainter 2D)는 두 탭 화면에서 사라짐.
- 우 2D 상단의 층수·저장·불러오기 컨트롤바만 Qt 네이티브로 유지.

### 입력 (조작)
- three.js 캔버스가 **마우스·키 입력 주체**:
  - 팬·줌 → three.js 자체 카메라 (60fps, 끊김 없음)
  - 클릭·호버·키 → QWebChannel bridge → 기존 AlignmentCanvas 로직 재사용
- 선택·정렬·배치·편집 **알고리즘은 한 줄도 새로 안 짰음** — `_process_press_at`
  / `_process_move_at` / `_process_key` 로 추출해 vispy·three.js 공유.

### 데이터 (모델)
- Scene·Component·Room 등 모델 레이어 **전혀 안 바뀜**.
- 골든 마스터 9개 시나리오 diff 0 (전 단계 유지).

## vispy 는 왜 "완전 제거"가 아닌가

**중요**: vispy `Viewer3D` 인스턴스·broadcast 는 *유지* 됨. 이유:
- 접합부설계·구조해석·물량 탭이 *같은 Viewer3D 인스턴스*(공유 캔버스)를 사용.
- 디자인 탭 controller 가 그린 부재가 그 vispy 캔버스를 통해 해석·물량 탭에 표시됨.
- 따라서 `ViewerStrangler` 의 broadcast(vispy+three 동시 갱신)는 *필수*.

즉 vispy 는 **디자인·정의 탭 *표시* 에서만 제거**됐고, 데이터 차원에서는 계속 동작.
사용자 요구("모듈정의·배치설계 부분만 제거, 접합부/해석/물량 vispy 유지")와 정확히 일치.

## 알려진 한계 / 잔여 작업 (선택)

1. **카메라 독립** — three.js 2D 시점이 vispy 와 따로 움직임. vispy 표시가 사라졌으니
   사실상 무의미 (사용자 수용).
2. **ViewerStrangler broadcast 유지** — 디자인 탭에 vispy 3D 안 보여도 데이터는 계속
   그림 (접합부/해석/물량 공유 때문). 약간의 자원. *제거 불가* (공유 의존).
3. **AlignmentCanvas 잔존** — vispy QPainter 캔버스 위젯은 숨겨진 채 입력·로직·sync
   핸들러로 살아있음. 완전 분리하려면 로직을 별도 클래스로 추출해야 하나, 위험 대비
   이득 적어 현 상태 유지 권장.
4. **웹 배포** — 사용자 최초 목표. 접합부 설계·구조해석·물량 탭도 three.js 화해야
   완전한 웹 배포 가능 (현재는 디자인 탭만). 별도 대규모 작업, 본 마이그레이션 범위 밖.
5. **성능** — three.js 2D 는 콘텐츠 변경 시에만 redraw + viewport-only 경량 전송으로
   최적화됨. 부재 매우 많을 시(100+) 추가 측정 권장.
