# M8 — vispy 제거 (모듈정의·배치설계 탭 한정) 설계

작성: 2026-05-28
범위: 모듈정의·배치설계 탭에서만 vispy 표시 제거 → three.js 단독.
보존: 접합부설계·구조해석·물량 탭은 vispy 와이어프레임 그대로 유지.

## 면밀 점검 결과 (사용자 요구)

### vispy 3D (Viewer3D) 공유 구조
`main_3d` 의 `_canvas_widget` (단일 vispy 캔버스) 을 4개 탭이 reparent 공유:
- 디자인(902), 접합부(913), 해석(923), 물량(943)
→ **디자인 탭(902)만 제거**, 나머지 3탭 그대로. Viewer3D 인스턴스·broadcast 유지.

### Controller 의 vispy 전용 의존 (디자인 탭 무관 확인)
- `screen_to_world_ray` / `get_scene_transform` — 3D 마우스 picking. 디자인 탭은
  eventFilter 가 3D 좌클릭·마우스무브를 무시하므로 *호출 안 됨*. 접합부/해석/물량만 씀.
- `is_ops_view_active` — ops 뷰 (해석 탭). 디자인 탭 무관.
→ 디자인/정의 탭에서 vispy 카메라 picking 미사용 — 제거 안전.

### three.js sync 트리거 의존 (핵심 위험)
- 현재 three.js 2D 갱신은 vispy `AlignmentCanvas.paintEvent` 끝의 후크에 의존(M3).
- vispy 2D 표시를 제거하면 paintEvent 가 안 불려 → three.js 멈춤.
- **해결**: sync 트리거를 `paintEvent` → `update()` 오버라이드로 이전. update() 는
  위젯 표시 여부와 무관하게 호출되므로, AlignmentCanvas 가 화면에 없어도 동작.
  (update 42곳 호출 → 오버라이드 1곳으로 전부 커버. throttle 이 전송 흡수.)

### AlignmentCanvas 는 vispy 아님 (QPainter)
2D AlignmentCanvas 는 QLabel+QPainter. vispy 아님. 다만:
- *입력·모델 로직* (`_process_press_at`/`_process_move_at`/`_process_key`) 은 three.js
  가 호출하므로 **인스턴스 유지 필수** (headless 로직 핸들러).
- *화면 표시* (QPainter paintEvent) + *위젯 마운트* 만 제거.

## 위험 / 주의

1. **AlignmentCanvas headless** — 위젯 마운트 안 해도 width/height 가 0/기본일 수 있음.
   `_world_to_screen`→`_screen_to_world` 왕복은 항등이라 클릭 정확. viewport dump 의
   width/height 는 three.js 자체 카메라(M4)라 무시됨 → 안전.
2. **update() 오버라이드 빈도** — paintEvent 보다 약간 잦으나 throttle 흡수. dump 자체는
   가벼움 (사용자 확인 — 끊김은 전송 비용이었음).
3. **Viewer3D broadcast 유지** — ViewerStrangler 가 vispy+three broadcast 계속. 디자인
   탭에 vispy 안 보여도 broadcast 무해 (약간 자원). 인스턴스 제거는 본 범위 밖
   (접합부/해석/물량이 같은 Viewer3D 공유하므로 신중).
4. **정의 탭 Viewer3D** — 정의 탭은 자체 인스턴스(공유 안 함)지만, 본 단계에선
   마운트만 단일화하고 인스턴스는 유지 (안전 우선).
