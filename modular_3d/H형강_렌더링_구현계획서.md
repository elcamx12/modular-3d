- **1단계 (메인 미출력 원인 규명)** — 완료. 진단 결과 메인 3D는 이미 정상 동작.

  눕히기 좌표 remap(벽·수직3모듈)과 동일한 축 순열을 웨브 벡터에도 적용. 직렬화
  포함. 정상=(0,0,1), 수직3모듈 눕힘=(1,0,0), 벽 눕힘=(0,1,0) 검증 통과.

  Shape+ExtrudeGeometry), 보+H형강이면 박스 대신 I자를 길이방향 압출하고 웨브
  방향대로 회전. 기둥·슬래브·각형강관 보는 박스 유지.

  를 재생성할 때 새로 추가한 `section_type`·`web_d*` 를 누락 → 전부 각형강관

## 0. 목적·배경

사용자가 보 부재의 강재를 **각형강관 ↔ H형강** 으로 바꿀 수 있는 옵션은 이미 두 곳
(모듈정의 탭 우측 패널, 배치설계 탭)에 존재하고, 그 값이 데이터·구조해석·물량·운송
계산까지 전파된다. 그러나 **3D 시각화는 H형강을 그리지 못한다**. 이번 작업은
H형강을 메인 3D와 운송 3D 양쪽에서 **I자 단면 형상으로 렌더링**하는 것이다.

> 본 작업은 "당장 전체 구현"이 아니라 **단계별 구현을 위한 셋업 + 계획 확정**을
> 거쳐 진행한다. 각 단계는 독립 검증 후 다음 단계로 넘어간다.

## 2. 적용 대상 부재 (D5 구체화)

보(BeamData)를 포함하는 부재 = H형강 렌더 대상:

| 부재 타입 | 포함 보 |
|---|---|
| 모듈(MODULE) | 하부보 4, 상부보 4 |
| 바닥패널(FLOOR_PANEL) | 둘레보 4 |
| 구조벽(STRUCT_WALL) | 상·하 런너 2 |
| 캔틸레버보(CANTILEVER_BEAM) | 보 1 |
| 캔틸레버슬래브(CANTILEVER_SLAB) | 둘레보 3 |
| 중간보(MID_BEAM) | 보 1 |
| 수직3층모듈(VERTICAL_MODULE) | 층 받침보 4×3, 옥상보 4 |

보 없음(렌더 변경 없음): 내벽(INTERIOR_WALL), 중간기둥(MID_COLUMN),
RC코어(CORE), RC코어슬래브(CORE_SLAB). **기둥은 항상 각형강관**(D5 전제 — 보만).

종속 부재(캔틸·중간보)와 합체 구조벽의 H형강 여부는 이미 부모/패널 유효 타입을
따라가도록 동기화됨(기존 로직 유지).

## 3. 현재 코드 실태 진단

### 3-1. 메인 3D (정의·배치 탭)
- 메쉬 생성기에 H형강 I자 압출 함수(`build_h_section`)와 "보 단면이 h면 I자,
  아니면 각형강관 박스" 분기(`_add_beams`)가 **이미 존재**한다.
- 단면 타입 변경 핸들러(`_set_beam_section_type`)는 같은 그룹·다층 복제본에
  타입을 적용하고 부재를 재생성한 뒤 메쉬를 다시 그린다.
- **그럼에도 화면에 H형강이 나오지 않는다** → 어딘가 경로가 끊겨 있거나 메쉬가
  깨졌을 가능성. **1단계에서 실행·로그로 원인 규명**이 필요.
  의심 후보: (a) 배치 시 단면 타입이 BeamData까지 전파 안 됨, (b) `build_h_section`
  의 면/캡 정의 오류로 메쉬가 비거나 깨짐, (c) 콤보 시그널 미연결, (d) 정의 탭은
  패널 floors=1 등으로 H형강 콤보가 안 보임.

### 3-2. 운송 3D
- 운송 어댑터는 각 부재를 **축정렬 AABB 박스**(BodyPart/AttachedPart:
  x,y,z,L,W,H)로만 데이터화한다. 단면 형상·방향 정보가 전혀 없다.
- 운송 JS(`loaded_3d_three.py`)는 그 박스를 그대로 `BoxGeometry`로 그린다.
  보·기둥 구분은 색·라벨뿐, **형상은 전부 박스**.
- 단면이 200×200 정사각이므로 **박스만으로는 웨브 방향(강축/약축)을 알 수 없다**.
  → 보의 **웨브 방향 벡터**를 운송 데이터에 추가 전달하고, 운송 좌표 변환·자세
  회전(remap)을 그 벡터에도 동일 적용해야 한다.

### 3-3. 운송 좌표 변환 규칙 (참고 — D7 구현 근거)
- `_nominal_to_transport_box`: 운송 x = 배치 y, 운송 y = 배치 x, 운송 z = 배치 z.
- 자세별 추가 회전:
  - 벽 눕히기(`_remap_part_wall_lying`): 축 (x,y,z,L,W,H) → 재매핑.
  - 수직3모듈 눕히기(`_remap_part_v3_lying`): 축 재매핑.
- 이 매핑들은 **박스 축 swap**이라, 동일 규칙을 단면 방향 벡터(웨브 벡터)에도
  적용하는 평행 경로를 신설하면 자세별 방향이 자동 산출된다.

## 4. 단계별 구현 계획

### 1단계 — 메인 3D H형강 미출력 원인 규명 + 최소 수정
- 목표: 정의·배치 탭에서 보를 H형강으로 바꾸면 **I자가 실제로 보이게** 한다.
- 작업:
  1. 단면 타입 'h'가 배치/변경 시 BeamData.section_type까지 전파되는지 추적
     (배치 경로 `_f5_pending_beam_section` → generate → `_apply_beam_section_type`).
  2. `build_h_section` 출력 메쉬(정점·면·캡) 검증 — 빈/깨진 메쉬 여부.
  3. 끊긴 지점 수정.
- 검증: 모듈·바닥패널을 H형강으로 배치/변경 → 메인 3D에 I자 표시. 각형강관과
  육안 구분.

### 2단계 — 메인 3D I자 단면 정밀화 (카탈로그 스펙 반영)
- 목표: D2 확정값으로 정확한 I자.
- 작업:
  1. H형강 메쉬 생성 시 웨브 t1=8, 플랜지 t2=12 를 **카탈로그 H200×200에서 조회**
     해 사용(현재 t2는 1.5·t1 근사). 단일 진실원천: `카탈로그/h_sections.py`.
  2. 필릿 생략(D4) 유지 — 직각 I자.
  3. 보 있는 모든 부재(2장 표)에서 동일 적용 확인.
- 검증: 단면 비율(웨브 8, 플랜지 12, 200×200)이 카탈로그와 일치. 골든마스터
  회귀(시각 외 데이터 diff 0).

### 3단계 — 운송 어댑터: 단면 형상·방향 데이터 전달
- 목표: 운송 부재 데이터에 H형강 식별자 + 웨브 방향을 실어 보낸다.
- 작업:
  1. BodyPart/AttachedPart에 `section_type`('shs'|'h')과 **웨브 방향 축 정보**
     필드 추가(운송 좌표계 기준 단위벡터 또는 축 인덱스).
  2. 보의 건물 단면 로컬 프레임(길이축·웨브 연직·플랜지) 산출 후, 운송 좌표
     변환 및 자세 remap과 **동일한 축 매핑**을 방향 벡터에 적용.
  3. 직렬화(JS로 넘기는 payload)에 신규 필드 포함.
- 검증: 단위 테스트 — 정상/벽눕힘/수직3모듈눕힘 각 자세에서 웨브 방향 축이
  기대값과 일치.

### 4단계 — 운송 3D JS: I자 압출 렌더
- 목표: 운송 화면에서 보를 I자로, 강축/약축 방향대로 그린다.
- 작업:
  1. 부재가 보 + section_type='h'이면 `BoxGeometry` 대신 **I자 단면 압출**
     (Three.js `ExtrudeGeometry` 또는 동등 형상)로 생성.
  2. 3단계에서 받은 웨브 방향에 맞춰 단면을 회전 배치(D7).
  3. 색·라벨·엣지·강조(dim)·그림자 기존 동작 유지.
- 검증: 운송 화면에서 보가 I자. 눕힌 부재·수직3모듈에서 웨브 방향이 건물 단면을
  회전한 것과 일치(육안 + 방향 단위테스트).

### 5단계 — 자세별 방향 통합 검증·보정
- 목표: 모든 부재·자세 조합에서 강축/약축 일관.
- 작업: 수직3모듈 lying, 벽 lying/standing, 캔틸·중간보 등 케이스 점검 후 보정.
- 검증: 대표 운송 모델로 전 자세 육안 + 데이터 점검.

### 6단계 — 회귀·마무리
- 골든마스터 9건 diff 0(시각 변경은 데이터에 영향 없음 확인).
- 물량/운송 계산 회귀(H형강 강종 분리·중량·단가 영향 없음).
- 사용자 실행 검증.
- 주석 정리 → 본 계획서 갱신 → 변경 이력 기록(프로젝트 규칙).

## 5. 위험·유의사항

1. **메인 미출력 원인 미상** — 1단계 실행 진단 결과에 따라 작업량이 달라짐.
   원인이 데이터 전파면 소규모, 메쉬 생성 자체 결함이면 메쉬 함수 재작성.
2. **운송 방향 산출 복잡성** — 박스 축 swap과 벡터 회전의 일관성이 핵심.
   자세 remap 함수마다 벡터 평행 경로를 빠짐없이 맞춰야 함.
3. **정사각 단면의 방향 모호성** — 200×200이라 박스로는 강축 구분 불가 →
   반드시 방향 벡터 전달 필요(3단계 누락 시 4단계 무의미).
4. **성능** — I자 압출이 박스보다 정점이 많음. 부재 수 많은 모델에서 운송 JS
   부하 측정 필요(필요 시 단면 정점 최소화).
5. **회귀 안전** — 시각만 바꾸고 계산·직렬화 핵심 필드는 불변 유지. 각형강관
   경로는 손대지 않음.

## 6. 데이터 흐름 (목표)

```
[UI 콤보 'H형강']
  → comp.beam_section_type='h'
  → generate_sub_components → _apply_beam_section_type
  → BeamData.section_type='h'
  ├─[메인 3D] build_component_mesh → _add_beams → build_h_section
  │     (카탈로그 H200×200: t1=8,t2=12, 필릿 생략) → vispy+three.js I자
  └─[운송] adapter: BodyPart/AttachedPart(section_type='h', 웨브방향벡터)
        → 운송 좌표변환·자세 remap을 벡터에도 적용
        → loaded_3d_three.py: I자 압출 + 방향 회전
```
