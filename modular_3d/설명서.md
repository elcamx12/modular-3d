# modular_3d 프로그램 설명서

> 본 문서는 코드를 직접 읽지 않고도 설계 의도·아키텍처·핵심 알고리즘·변천사를 정확히 이해할 수 있도록 작성된 설명서입니다. UI 조작은 `사용법.md`, 함수·클래스·상수의 전수 목록은 `인벤토리.md` (자동생성) 를 참고하세요.

## 0. 한 줄 요약 — 프로그램의 성격

**modular_3d** 는 모듈러(공장 제작 박스 단위) 와 RC 코어로 구성된 하이브리드 중·고층 건물을 3D 캔버스에서 직관적으로 배치하고, **같은 데이터로** OpenSees 기반 구조해석(수직 자중·활하중 + 횡력 4 케이스, 총 5 케이스) → 단면 자동 설계 → 물량산출까지 일관 처리하는 졸업종설 도구입니다.

설계의 일관된 원칙은 **"보이는 것 = 계산되는 것"** — 사용자가 화면에서 본 부재·접합·강체 묶음 그대로가 해석 모델에 1:1 로 전달되도록 하는 것입니다. 이를 위해 단일 명세 객체 `ModelSpec` 과 카탈로그 단일 진실 원천(Single Source of Truth) 패턴으로 코드를 정돈했습니다.

## 1. 졸업종설 컨텍스트

본 프로그램은 졸업종설 "순수 MCTS 기반 하이브리드 모듈러 평면 최적화" 의 **구조해석 부분 도구** 입니다.

- 사용자(개발자)는 건축공학 전공, 구조 해석 프로그램 개발 담당입니다.
- MCTS 기반 평면 최적배치 알고리즘은 본 도구의 외부 영역이며, 본 도구는 사용자가 직접 배치하거나 외부 알고리즘이 도출한 배치를 시각화·해석하는 역할을 합니다.
- 추후 MCTS 통합 자리로 디자인 탭 우측에 "AI 최적배치 탐색" 버튼이 비활성 상태로 노출되어 있습니다.
- 3 주차 교수님 피드백 — "모듈 철골 + PC 철골 건식 접합부 힌트" 가 핵심 모델링 방침으로 반영되어, 컴포넌트 내부는 강접(elasticBeamColumn) 으로, 모듈 사이 인터페이스는 핀(equalDOF 1,2,3 — 병진만 묶고 회전 자유) 으로 분리 표현합니다.

### 3-B. 공통 메타데이터

모든 부재(`Component` 기본 클래스) 는 다음 필드를 공유합니다.

| 필드 | 의미 |
|---|---|
| `id` | 씬 내 고유 ID (Scene.add_component 가 발급) |
| `comp_type` | ComponentType enum |
| `position` | 앵커 포인트의 월드 좌표 (mm), shape (3,) |
| `rotation` | 0/90/180/270 도 (z 축 시계 반대) |
| `dimensions` | dict — width(X) / depth(Y) / height(Z) |
| `anchor` | 0=좌하/1=우하/2=우상/3=좌상 — 회전 전 로컬 기준 |
| `group_id` | 같은 사용자 액션으로 만들어진 부재 공유 (0=미지정) |
| `floor_index` | 층 번호 (0=1층, 1=2층, …, N=옥상) |
| `sub_index` | 같은 층 안에서 본체=0 / 종속=1+ |
| `parent_id` | 스냅된 부모 컴포넌트 — UI 인식 접합 직결 |
| `anchor_edge_id` | 부모 모서리 ID (0=하단/1=우측/2=상단/3=좌측, -1=비종속) |

| `joint_records` | 본 부재의 각 코너가 어떤 부재의 어떤 지점에 결합되는지 명시 기록 |

### 3-C. 좌표계 / 회전 / 앵커 시스템

좌표계는 **오른손 좌표계 mm 단위** 입니다. +X 가 동, +Y 가 북, +Z 가 위.

- 부재 본인의 로컬 좌표계는 항상 0~width(X), 0~depth(Y), 0~height(Z) 로 정의됩니다.
- `rotation` 은 로컬 좌표를 z 축 시계 반대로 회전시킨 양 (90 도 → 로컬 +X 가 월드 +Y 가 됨).
- `anchor` 는 회전 전 로컬 좌표계에서 "이 부재의 어느 코너가 position 좌표인가" 를 결정합니다 (0=좌하 → position 이 부재의 좌하 코너, 1=우하 → 우하 코너, …).
- 즉 같은 position·rotation 이라도 anchor 만 바꾸면 부재가 회전 중심을 바꿔 4 가지 위치로 옮겨갑니다.

회전 행렬은 단순 90° 단위라 분기 4 줄로 처리 — 부동소수 회전 누적 오차가 발생하지 않습니다.

### 3-D. 모듈 부재 생성 규칙 (예시)

모듈(`Module.generate_sub_components`) 은 dimensions + position + rotation + anchor 로부터 다음을 자동 생성합니다.

- **기둥 4** — 네 코너에 SHS 200×200×8. 길이는 z=−100 (하부보 하면) ~ z=h−100 (상부보 상면). 즉 모듈 외형 높이 h 가 그대로 기둥 길이입니다.
- **하부보 4** — z=0 (하부보 중심선). 외곽 사각의 네 변. X 방향 보 2 + Y 방향 보 2. 각 보의 시작/끝은 기둥 면(half_s=100mm) 만큼 인셋되어 코너에서 중복되지 않습니다.
- **상부보 4** — z=h−200 (단면 두께 보정). 같은 사각 구성.
- **슬래브 1** — 상면 z=100 (보 상면), 하면 z=−50, 두께 150 mm. 네 변은 보 안쪽(s=200mm) 인셋.

다른 부재도 유사한 패턴으로 자동 생성됩니다 — 핵심은 사용자가 입력하는 것은 외형 치수뿐이고, 내부 보·기둥의 정확한 좌표는 카탈로그 단면 폭과 자동 인셋 규칙으로 결정된다는 점입니다.

## 4. 다층 그룹 패턴 (F5 핵심) — model/multi_floor.py

### 4-A. 한 클릭 = 한 그룹 = N 층 분량 자동 복제

F5 (=디자인 탭 캔버스) 에서 한 번 클릭하면, F5 패널의 "층 수 (N)" 설정에 따라 자동으로 N 층 분량이 한꺼번에 생성됩니다. 같은 `group_id` 를 공유하기 때문에:

- **이동** — 그룹 통째 평행이동
- **회전 (R 키)** — 그룹 전 층 동일 자세
- **삭제** — 그룹 통째 사라짐
- **Undo (Ctrl+Z)** — `begin_group_action` / `end_group_action` 패턴으로 한 클릭이 만든 모든 add 를 'group_place' 1 액션으로 묶어 사용자 시점에서 1 회 undo 로 통째 복원

### 4-B. 부재 타입별 z 분포 공식

층-층 거리 `H = MODULE_HEIGHT_MM(3400) + MODULE_JOINT_GAP_MM(20) = 3420 mm` 가 단위입니다.

| 부재 | 개수 | k 의 범위 | z 좌표 |
|---|---|---|---|
| 모듈 | N | 0..N-1 | k·H |
| 바닥패널 | N+1 | 0..N | k·H (1F 바닥 슬래브 포함, 옥상까지) |
| 구조벽(병합) | N | 0..N-1 | k·H (FP 와 같은 평면 — 강체 합체) |
| 구조벽(비병합) | N | 0..N-1 | k·H + 200 (FP 위에 얹힘) |
| 캔틸레버보 | N | 0..N-1 | k·H + (h−200) (모듈 천장 레벨) |
| 캔틸레버슬래브 (FP 종속) | N+1 | 0..N | k·H |
| 캔틸레버슬래브 (모듈 종속) | N+1 | 0..N-1 + 옥상 | k·H, 마지막은 N·H |
| 중간보 | 2N | 0..N-1 × {바닥, 천장} | k·H 또는 k·H+(h−200) — 한 번 클릭으로 둘 다 생성 |
| 중간기둥 | N | 0..N-1 | k·H |
| RC 코어벽 | N+1 | 0..N | k·H (옥상 한 장 더 — 모듈 한 층 더 쌓은 높이까지 솟음) |
| RC 코어 슬래브 | N+1 | 0..N | k·H + h − thickness (각 층 코어벽 윗면) |

이 공식은 `multi_floor.py::_floor_z_list` 한 함수에 모여 있어 부재별 z 분포 정책이 한 곳에서 변경 가능합니다.

### 4-C. 함정 — H 와 h 의 구분

`H = h + gap = 3420` vs `h = MODULE_HEIGHT_MM = 3400`. 캔틸레버보·중간보의 천장 레벨 z 오프셋은 `(h − 단면 폭 200)` 이지 `(H − 200)` 이 아닙니다. 이전엔 H=h 가정으로 한 곳에 있던 식이 갭 도입 후 20 mm 어긋나 부모 매칭이 실패하던 버그가 있었습니다 — 함수 docstring 에 명시되어 있습니다.

### 4-D. 그룹 ID 발급

`next_group_id(scene)` 은 씬 내 가장 큰 group_id + 1 을 반환. 0 은 "그룹 미지정"(레거시) 의미. 복사 모드(C 키) 는 원본 group_id 를 보존하지 않고 항상 새 gid 를 발급해, 두 그룹이 의도와 다르게 같이 움직이지 않게 합니다.

## 5. UI 인식 접합 → 해석 모델 직결 (model/joint_recorder.py)

### 5-A. 배경 — 이전 정책의 한계

이전엔 UI 의 자동 갭·스냅과 해석 측 거리 기반 fuzzy 매칭이 서로 독립으로 동작했습니다. 결과적으로 외톨이 코너(주변 부재가 350 mm xy 허용오차 밖에 있는 경우) 같은 경계 케이스에서 매칭 실패 → 슬래브 코너가 지지점 없이 떠 있는 mechanism → 평형 손실이 발생했습니다.

### 5-B. 현재 정책 (2026-05-12, 옵션 (나))

배치/이동 직후 다음 흐름으로 접합 관계를 명시적으로 기록합니다.

1. `render/dep_snap.py` 가 사용자가 클릭한 위치에서 부모 부재·앵커 모서리·로컬 좌표를 자동으로 계산해 부재 메타에 박음 (`parent_id`, `anchor_edge_id`).
2. 배치 직후 `joint_recorder.record_joints(scene)` 가 모든 FP·캔틸레버슬래브의 4 개 바닥 코너에 대해 씬 내 모든 후보 부재(Module/StructWall/Vertical3Module) 의 기둥 코너 xy 를 비교:
   - xy 거리 ≤ `JOINT_TOL_XY` (=350 mm)
   - z 거리 ≤ `JOINT_TOL_Z` (=500 mm) — 기둥 상단 또는 하단 중 가까운 쪽
3. 가장 가까운 1 개 후보를 채택해 `joint_records` 리스트에 (corner_idx, target_comp_id, target_xy, target_z) 기록.
4. 해석 토폴로지(`topology._resolve_floor_panel_supports`) 가 거리 기반 추정 대신 본 기록을 1순위로 사용 → 평형 0.00% 달성.

같은 정책이 디자인 탭에서 부재를 이동·복사할 때마다 자동 재계산됩니다.

## 6. 카탈로그 단일 진실 원천 (카탈로그/)

### 6-A. 의도

프로젝트 진행 중 부재 단면 폭이 200 mm 였다가 추후 변경 가능성, 모듈 높이 3400 vs 다른 시나리오 3000 등 매직넘버가 여러 파일에 흩어져 있어 한 곳을 바꿔도 다른 곳에서 깜빡 잊고 안 따라가는 일이 반복됐습니다. "체육복 사이즈" 비유처럼 — 본 폴더 한 곳만 바꾸면 모든 사용처가 자동 따라가는 단일 진실 원천을 만들기 위해 신설된 폴더입니다 (한글명 카탈로그/).

## 7. ModelSpec — 보이는 것 = 계산되는 것 (analysis/model_spec.py)

### 7-A. 1 급 알갱이 7 종

OpenSees 모델의 단일 명세를 다음 7 종 dataclass 로 정의합니다.

| 레코드 | 대응 OpenSees 명령 | 필드 |
|---|---|---|
| `NodeRec` | `ops.node(id, x, y, z)` | id, 3D 좌표 |
| `BeamRec` | `ops.element('elasticBeamColumn', ...)` | i_node, j_node, A, E, G, J, Iy, Iz, transf_tag |
| `ShellRec` | `ops.element('ShellMITC4', ...)` | 4 nodes, section_tag |
| `EqualDofRec` | `ops.equalDOF(master, slave, *dofs)` | master, slave, dofs 명시 (예: [1,2,3] 또는 [1,2,6]) |
| `RigidLinkRec` | `ops.rigidLink('beam', master, slave)` | master, slave |
| `DiaphragmRec` | `ops.rigidDiaphragm(perp, master, *slaves)` | perp(평면 법선축, 보통 3=Z), master, slave 리스트 |
| `FixRec` | `ops.fix(node, *constraints)` | node, 6 DOF 마스크 (예: 1,1,1,1,1,1) |

단면·재료·변환축은 부수 정보로 부재 속성에서 자동 계산 — 1 급 알갱이가 아닙니다.

### 7-B. 두 객체 분리

- `ModelSpec` — 토폴로지·결합·고정점. 5 케이스 공유.
- `LoadSpec` — 케이스별 하중 (자중·활하중·횡력). 케이스마다 1 개씩 총 5 개.

생애주기가 다르므로(`ModelSpec` 은 한 번 만들면 5 케이스 푸는 동안 변하지 않음, `LoadSpec` 은 케이스마다 새로 만듦) 분리. 같은 모듈에 둬 import 경로는 단일.

### 7-C. 동일 순회기 = 일치 보장

`ModelSpec.iter_nodes()`, `iter_beams()`, `iter_equal_dofs()` 등 통일된 순회기로 OpenSees 등록기와 와이어프레임 표시기(`render/viewer.py::_draw_from_spec`) 가 같은 데이터를 읽습니다. 이로써 화면의 와이어프레임과 실제 계산되는 모델이 코드 구조 차원에서 일치하도록 보장됩니다. 와이어프레임에서 색상으로 노드 종류(고정/다이어프램 마스터/equalDOF 슬레이브) 도 구분 표시.

## 8. 해석 토폴로지 (analysis/topology.py)

### 8-A. 단순화 방침

직접강성법 연속보 해석을 OpenSees 로 일관 처리하기 위해 토폴로지를 다음과 같이 단순화:

- **모듈** — 8 노드 (바닥 4 + 천장 4), 12 부재 (보 8 + 기둥 4). 기둥 stub 없이 바닥보~천장보 사이 1 개로 처리.
- **컴포넌트 간 노드 자동 공유 X** — 각 컴포넌트는 독립 노드 집합을 가지고, 인터페이스 결합은 equalDOF/rigidLink 로 별도 등록.
- **패널류 완전 겹침** — 같은 평면에서 정확히 일치하면 통합. 부분 겹침은 RuntimeError 로 즉시 실패시킴 (사용자에게 모델 모순 알림).

### 8-B. 좌표 키 정수 반올림으로 노드 자동 병합

모든 좌표를 `NODE_MERGE_TOL_MM=1.0` mm 단위 정수 키로 반올림해(`_utils.round_key`) 같은 키의 노드는 1 개로 자동 병합. 이로써 부동소수 누적 오차로 인한 중복 노드 생성을 원천 방지.

### 8-C. 종속 노드 통합 (Union-find)

같은 위치(허용오차 200 mm) 의 노드들을 Union-find 로 한 노드로 합치는 `_consolidate_dependent_nodes` 가 다음 케이스를 처리합니다.

- **캔틸레버 앵커** — 캔틸레버보의 부모 닿는 끝 노드와 부모 모듈의 기둥 노드 통합. 허용오차 200 mm (단면 폭 보정).
- **벽-FP 합체** — STRUCT_WALL.merge_with_panel=True 일 때 벽 하부 노드와 같은 평면 FP 노드 통합.
- **코어 다층** — 같은 group_id 의 코어벽들이 수직으로 적층될 때, 위 코어 base 와 아래 코어 top 의 같은 xy 노드 통합. 이전엔 (i, i+1) 인접 검사로 했으나 사용자 보고 "수직으로도 따로 놀고 있음" 으로 모든 페어 검사로 확장.

### 8-D. 인터페이스 자동 검출

같은 z 레벨의 컴포넌트 경계에서 xy 위치가 일치하는 노드쌍을 자동 검출해 인터페이스 핀 링크(equalDOF 1,2,3) 등록. PC 철골 건식 접합부의 핀 거동 — 회전 자유, 병진만 묶음 — 을 표현합니다.

## 9. 직각 사영 정책 (analysis/projection.py) — 2026-05-13 신설

### 9-A. 정책 동기

이전엔 노드 매칭이 단순 거리 임계 기준이라 평면상 대각으로 놓인 부재 페어도 인접하다고 판단해 잘못 결합되는 케이스가 있었습니다. 사용자 답변에 따라 다음 정책 채택:

- **모든 부재 페어의 접합 자리는 사영(직각).** 평면상 대각 페어는 거부.
- 한 후보 노드의 좌표를 대상 부재의 면/선에 직각으로 사영해 사영점 좌표를 계산.
- 그 사영점에 새 노드 N1 을 등록 후 결합.

### 9-B. 제공 함수

| 함수 | 입력 | 출력 |
|---|---|---|
| `project_to_line(point, line_p1, line_p2)` | 점 + 직선의 두 점 | 사영점 + 사영거리 + 사영 가능 여부 |
| `project_to_plane(point, plane_origin, plane_normal)` | 점 + 평면 원점 + 법선 | 사영점 + 사영거리 + 사영 가능 여부 |
| `project_to_quad(point, quad_corners)` | 점 + 사각형 4 코너 | 사영점 + 사각형 내부 여부 + 사영거리 |
| `is_orthogonal_pair(coord_a, coord_b, tol_tangent)` | 두 좌표 | True/False (직각 페어인지) |

### 9-C. 정책 임계 — 본 모듈 상수

- `ORTHOGONAL_TOL_MM = 5.0` (Q3 답변 기준) — 직각 여부 판정 허용 접선 성분
- `PROJECTION_LIMIT_MM = 350.0` (Q4 답변 기준) — 사영 거리가 이를 넘으면 매칭 실패

### 9-D. z 축 직교성 (2026-05-13 추가)

평면(xy) 직각뿐 아니라 z 축으로도 대각 페어를 거부. 코어-모듈처럼 z 레벨이 어긋나면서 xy 도 어긋난 페어는 중간 노드 N1 을 끼워 두 단계 직각 경로로 분해 (수직 → 수평 또는 수평 → 수직 1 회씩만). 사용자 명시: "z 축 레벨이 안 달라 보이는데?" 피드백을 반영해 두 단계만 허용. N1 노드는 핀(equalDOF 1,2,3), 나머지는 6 DOF 강체 링크로 처리.

## 10. OpenSees 모델 빌드 (analysis/ops_builder.py)

### 10-A. 변환 절차 (6 단계)

화면의 부재 집합 → AnalysisModel(자체 토폴로지) → OpenSees 3D 프레임 모델로 변환:

1. **노드 생성** — 1 mm 정수 키 반올림 기반 자동 병합. ndf=6.
2. **보-기둥 요소** — 컴포넌트 내부는 강접(`elasticBeamColumn`). 단면은 기본 SHS 200×200×8 (이후 단면 자동 설계 시 그룹별 채택 단면으로 교체).
3. **인터페이스 핀 링크** — `equalDOF master slave 1 2 3` (병진만 묶고 회전 자유). PC 철골 건식 접합부 핀 거동.
4. **RC 코어 와이드컬럼** — 벽 한 장당 단일 frame element. 양 끝 노드를 다이어프램에 `equalDOF 1 2 6` (X 병진·Y 병진·Z 회전만, 평면 거동 강체). 1F 베이스는 6 DOF 완전고정.
5. **강체 다이어프램** — 각 층 z 레벨 클러스터링 → `rigidDiaphragm 3 master *slaves` (XY 평면 강체).
6. **지점** — 1F z_min 의 모든 기둥 base + 코어 base 를 `fix node 1 1 1 1 1 1` 6 DOF 완전고정.

### 10-B. 단면·재료·변환축 자동 계산

`BeamRec` 에 들어가는 A, E, G, J, Iy, Iz 는 부재의 단면 정보(SHS 200×200×8) 와 카탈로그 재료 상수(STEEL_E_MPA, STEEL_G_MPA) 에서 자동 계산. SHS 중공 단면의 J(비틀림 상수) 도 닫힌 식으로 계산해 `analysis/section_catalog.py` 의 `_shs_section_props` 가 반환.

부재 방향 변환축(geomTransf) 은 보가 X·Y 방향이면 `Linear` 표준, 기둥(Z 방향) 이면 별도 vecxz 지정.

### 10-C. 와이드컬럼 코어 모델 — Shell 폐기 이유

초기엔 RC 코어벽을 4 노드 ShellMITC4 로 모델링했으나:
- 코어벽이 모듈과 같은 평면에 있을 때 모듈 기둥과 shell 코너 노드가 어긋남 → 사영해서 강체 링크로 묶으려니 사영 누적 오차로 평형 깨짐.
- Shell 엣지 중간점 노드(m01/m12/m23/m30) 공유 처리 시 인접 shell 과 노드 공유 안 됨 → 세그멘테이션 폴트.

→ 단일 frame element + equalDOF 1,2,6 로 단순화하니 평형 0.00% 달성 (2026-05-12). 이를 "와이드컬럼 모델" 이라 부릅니다.

### 10-D. 다이어프램 마스터 노드

각 z 레벨 평면의 노드들을 모아 그 평면 중심(centroid) 가장 가까운 노드를 마스터로 선정. 나머지는 슬레이브. 마스터에 절점력으로 횡력을 가해 다이어프램 거동(평면 강체 회전·병진) 으로 분배.

## 11. 5 케이스 해석 (analysis/ops_solver.py)

같은 `ModelSpec` 토폴로지 위에 케이스별 `LoadSpec` 만 바꿔 5 번 푸는 방식. 각 케이스는 독립적인 pattern 으로 등록하고 Linear 정적 해석 후 결과 추출.

### 11-A. 수직 케이스 — D+L (1.2D + 1.6L)

1. `load_calculator.calculate_loads()` 가 각 슬래브의 1방향/2방향 거동을 자동 판별 (단변/장변 비 0.5 기준) 해 외곽 보별 등가 평균 UDL 로 누적.
2. RC 코어 column 자중 추가 (콘크리트 단위중량 × 단면적 × 길이).
3. `timeSeries Linear` + `pattern Plain` 안에 `eleLoad -ele tag -type -beamUniform wy wx wz` 로 등록.
4. 자중은 `1.2 × ρ × A × g`, 활하중은 `1.6 × 2 kN/m² × 분배폭`.

### 11-B. 지진 케이스 — KBC 2022 §0306 등가정적 (Ex / Ey)

1. 지진중량 W = ΣD (주거이므로 활하중 미포함).
2. 베이스 전단 V = Cs · W, Cs = SDS · Ie / R (KBC 식). 카탈로그 `loads.py` 의 SDS, Ie, R 값 사용.
3. 층별 분배 Fx = (wx · hx^k / Σ wi · hi^k) · V, k 는 주기 T 의 함수 (T<0.5s 면 1, T>2.5s 면 2, 사이는 선형 보간).
4. 각 층 다이어프램 마스터 노드에 X (또는 Y) 절점력으로 인가.

### 11-C. 풍 케이스 — KDS 41 12 00 단순화 (Wx / Wy)

1. 기본풍속 V = 35 m/s. 속도압 q = 0.613·V² (Pa).
2. 층별 풍하중 = q · Gust factor · 외력계수 Cf · 투영면적 A_proj.
3. 다이어프램 마스터에 절점력.

### 11-D. 평형 검증

각 케이스 결과 추출 시 베이스 반력 합 vs 적용 하중 합을 비교. 1% 초과 시 mechanism 발생 의심으로 경고 또는 중단. 현재 5 케이스 모두 0.00% 일치 (회귀 테스트 통과).

### 11-E. 회귀 테스트 — analysis/tests/_smoke_test_ops_solver.py

총 17 케이스 시나리오:
- 단일 모듈 / 수평 인접 2 / 수직 적층 2 / 2×2 평면 × 2 층 / 3×3 평면 × 3 층 / 회전 모듈 / 회전 적층 / 다른 크기 모듈 인접 / 모듈 + FP / 모듈 + 벽 / 모듈 + 캔틸레버 / 부분 FP / 오프셋 적층 / 손계산 비교 / 지진 손계산 비교 / 5 케이스 횡력 일괄 / …

테스트는 venv Python 으로 실행하며, 평형 1% 이내 + 손계산 일치 + 베이스 전단 적용 일치를 검증합니다.

## 12. 단면 자동 설계 + 강도 검토 + 물량산출

### 12-A. 강도 검토 (analysis/strength_check.py)

각 부재의 5 케이스 응력비를 계산:
- 휨 응력비 = M·c / (I·Fy)
- 전단 응력비 = V / (Aw·Fv)
- 조합 응력비 = √(휨² + 전단²)

부재별 최대 응력비를 5 케이스 중 가장 큰 값으로 산출.

### 12-B. 단면 자동 설계 (analysis/section_design.py)

응력비를 기준으로 단면을 그룹화. UI 라디오버튼으로 1 종/2 종/3 종 그룹화 정책 선택:
- **1 종** — 모든 부재 동일 단면 1 개
- **2 종** — 보 1 + 기둥 1 (총 2 단면)
- **3 종** — 외곽 보·내부 보·기둥 분리 (총 3 단면)

각 그룹의 최대 응력비 부재가 응력비 ≤ 0.8 을 만족하는 가장 작은 SHS 단면을 `steel_sections.SHS_CATALOG` 에서 자동 선정. 선정 결과를 ModelSpec 의 BeamRec 단면 정보에 반영 후 재해석.

### 12-C. 물량산출 (analysis/quantity_takeoff.py)

- 그룹별 채택 단면, 길이 합계, 본수, 단위중량, 총 중량
- 슬래브 부피 (모듈 슬래브 + FP + 코어 슬래브)
- 부재별 응력비 + 색상 5 단계 (파/하/초/주/빨, 0.2 간격)
- 부재 행 클릭 → member_selected 시그널 → 3D 뷰 강조 + 응력비 색상 모드 전환

### 12-D. 강재 본수 통합 — 분할 부재 1 본 처리 (2026-05-19)

해석 토폴로지가 한 보·기둥을 인접 부재의 결합점에 맞춰 여러 조각으로 자동 분할(`_split_hosts_for_mid_endpoints`)하면, 같은 원본 부재가 본수표에서 2~3 본으로 잘못 합산되는 문제가 있었습니다. 현재는 분할 부재가 `parent_member_id` 로 원본 부재 id 를 들고 다니고, `aggregate_steel` 이 같은 parent root 의 모든 조각을 한 본으로 합치되 길이만 합산합니다. 코어 frame element(`CAT_RC_CORE`) 와 슬래브(`_collect_slabs` 의 CoreSlab) 는 강재 집계 단계에서 명시적으로 제외되어, 우측 패널의 강재 본수표·중량표에 절대 섞이지 않습니다.

### 12-E. 부재 라벨 일관성 — 구조해석 탭 ↔ 물량 탭 (2026-05-19)

이전엔 구조해석 탭의 부재별 내부력 트리와 물량 탭의 부재별 응력비 트리가 같은 부재를 서로 다른 한글 라벨로 표시해, 사용자 입장에서 "두 트리의 '기둥' 항목이 같은 부재 집합인가?" 라는 의심이 생겼습니다. 현재는 구조해석 탭이 빌드하는 `_comp_meta`(부재 → 컴포넌트 그룹·층·역할 매핑) 캐시를 인스턴스 속성에 저장해두고, 물량 탭의 응력비 트리(`_fill_ratio_table`) 가 **같은 캐시를 그대로 가져다 씁니다**. 두 트리는 모듈 → 층 → 역할(상부보·하부보·기둥) → 부재의 4 단 계층, VERTICAL_MODULE 의 층 분리, "<xy><tname>" 라벨 양식, "(기타)" / "(미지)" 폴백 제거까지 동일하고, 잎 컬럼만 부재 내부력 ↔ 응력비/단면명/지배 항목으로 교체됩니다.

### 12-F. 기둥 층구간 분할 — DP 기반 강재 중량 최소화 (2026-05-19)

11~24 층 같은 고층에서 기둥을 한 단면으로 통일하면 상층의 경량 단면 잠재력이 낭비됩니다. 우측 패널 상단에 **"기둥 층구간: [SpinBox]  [적용]"** UI 가 추가되어, K=1 (분할 안 함) ~ 20 사이 값을 입력 후 적용을 누르면 다음이 일어납니다.

1. 현재 케이스의 envelope demand(5 케이스 절댓값 최대 + 압축 우선) 로 기둥 그룹의 부재별 demand 산출.
2. `split_columns_by_floor(am, demands, base_result, floor_of_mid, n_segments=K, catalog)` 가 DP[K][N] 점화식 `dp[k][n] = min over m in [k-1..n-1] of dp[k-1][m] + cost(m+1, n)` 로 N 개 층을 K 개 연속 구간으로 최적 분할. 비용 = `채택 단면.weight_per_m_kg × 구간 내 기둥 총길이 / 1000` + (NG 시 1e9 페널티).
3. 역추적으로 구간 경계를 얻어 기존 'columns' 그룹을 'columns_F{a}_{b}' 다중 그룹으로 교체 (`a..b` = 1-indexed 층 범위).
4. 본수표 / 채택 단면표 / 응력비 트리의 그룹 라벨이 `_group_label_ko()` 로 "기둥 (1~3층)" / "기둥 (4층)" 같은 한글로 자동 매핑.

예: 11 층 기둥 110 본을 K=3 으로 분할하면 1·3 층은 175×175×6, 2 층은 200×200×6 로 강재 중량이 한 단면 통일 대비 약 10% 감소했습니다 (회귀 검증).

### 12-G. 지배 케이스 자동 선택 (2026-05-19)

물량 탭은 하중조합 콤보의 선택값과 무관하게 항상 envelope(5 케이스 절댓값 포락) 로 단면을 설계해야 하지만, 콘솔 출력 / 라벨 표시 일관성을 위해 콤보가 자동으로 "envelope" 항목으로 점프하도록 변경했습니다. 사용자가 다른 케이스를 골라도 단면 설계 후 자동으로 envelope 표시명으로 복귀.

### 12-H. 우측 패널 자동 너비 + 글씨 잘림 해결 (2026-05-19)

물량 탭의 채택 단면표 / 본수표 / 슬래브 부피표는 헤더 폭 변경이 잦아 텍스트가 `...` 으로 잘리는 일이 잦았습니다. 세 표 모두 `QHeaderView.Stretch → ResizeToContents` 로 전환, `setStretchLastSection(False)` + `setTextElideMode(Qt.ElideNone)` + `setWordWrap(False)` + `setHorizontalScrollBarPolicy(ScrollBarAlwaysOff)` 로 강제 확장. 패널 전체는 `_fit_panel_to_quantity` 가 트리 expandAll 한 상태에서 측정 → collapseAll → expandToDepth(1) 단계로 너비를 산정하고, 헤더는 `QFontMetrics` 로 폰트 메트릭을 직접 측정해 셀 폭이 헤더보다 작으면 `setColumnWidth` 로 강제 확장합니다.

## 14. F5 컨트롤러 흐름 상세 (ui/controls_f5.py)

### 14-A. Mixin 패턴

Controller 가 inherit 하는 `F5Mixin` 으로 분리. `self._scene`, `self._viewer`, `self._snap` 등을 그대로 사용 — Mixin 자체는 인스턴스화하지 않음. 약 1300 줄의 컨트롤러 로직 중 F5 관련만 본 모듈에 집중.

### 14-B. 입력 → 배치 흐름

```
[1] 1~9 키 또는 팔레트 버튼      →   _f5_on_type_key
[2] 치수 입력 + Enter            →   _on_dimension_confirmed
[3] PREVIEW (마우스 호버)        →   _f5_on_canvas_move (고스트 갱신)
[4] R/V 키                       →   _f5_on_rotate / _f5_on_anchor
[5] 마우스 클릭                  →   _f5_on_canvas_click
[6] N 층 다층 그룹 생성          →   create_multi_floor_group
[7] 좌측 3D 동기화               →   build_component_mesh + viewer.add_component_visual
[8] 조인트 기록 재계산           →   record_joints(scene)
```

### 14-C. 자유 이동 모드 (M 키) — `_resolve_move_targets` 정책

이동 대상 결정 규칙(2026-05-12 b 단계):
- 코어벽 단독 → 자기 한 장만
- 코어 슬래브 → 슬래브 + 같은 그룹 코어벽 (벽 + 슬래브 한 묶음)
- 모듈/패널 본체 → 같은 그룹 전체 (본체 + 종속)
- 종속 부재 (캔틸레버·중간보·중간기둥) → 자기만

### 14-D. 복사 모드 (C 키)

deep copy 로 모든 부재 복제 후 새 group_id 발급. 위치는 클릭 위치 기준 delta 평행이동.

### 14-E. 그룹 단위 Undo

`scene.begin_group_action()` … 모든 add … `scene.end_group_action('group_place')` 로 한 클릭의 모든 add 를 1 액션으로 묶음. `group_move`, `group_place` 두 종류로 사용자 시점 undo 단위 보장.
