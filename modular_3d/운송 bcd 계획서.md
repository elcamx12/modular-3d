## 0단계 — 좌측 패널 재배치 (a 잔여)

**목적**: 운송 탭을 좌/우 2분할. 왼쪽=읽기전용 공통값(위) + 수동 시뮬레이션(아래), 오른쪽=상태·옵션(편집 가능분)·결과·회차표·도식·경제성.

**결정사항**
- 예쁘게 X, 기능·동작만. 배치 설계 탭의 좌측 패널 구성 방식을 참고.
- 읽기전용 묶음: 운송 거리 · 운임 방식 · 트럭종류별 km단가 · 비내력벽 내/외 단위중량 · **현장 운송 제한(총중량·폭·높이)**. (모두 프로젝트 설정에서 옴 → 회색 표시)
- 수동 시뮬레이션 영역을 왼쪽 패널 아래로 이동.

**구현 메모**
- `transport_panel._build_ui` 를 가로 스플리터(QSplitter)로 재구성. 왼쪽 위젯에 옵션의 읽기전용 위젯들 + 수동 시뮬, 오른쪽에 나머지.
- 읽기전용 위젯(거리/운임/단가/단위중량 스핀·콤보)은 그대로 두되 배치만 왼쪽으로. `_read_economics_options`/`_read_options` 가 그 위젯들을 그대로 참조하므로 위치만 바뀌어도 동작 유지.
- 주의: 위젯을 한 부모에서 다른 레이아웃으로 옮길 때 재부모(reparent) 처리. 깨지면 "읽기전용 표시는 라벨로 새로 만들고 값만 apply_project_settings 에서 갱신" 방식으로 대체.

**검증 포인트**
- 운송 탭이 좌우로 나뉘어 보이고, 왼쪽에 읽기전용 값 + 수동 시뮬이 있다.
- 운송 계산·수동 시뮬·회차표 등 모든 기능이 그대로 동작한다.

## B단계 — 적재 간격 내장 상수화 + 폭 여유 + 광폭검토 제거

**목적**: 적재 간격을 사용자 입력에서 내장 고정값으로. 폭 여유(양쪽 200) 신설. 광폭검토 표시 제거.

**결정사항 (확정)**
- 적재 간격 입력 **제거**: 운송 옵션의 간격 3칸(패널간/양끝/L자수평), 수동 시뮬 ⑤ 적재간격 영역 모두 제거.
- 내장 고정값: 수직 갭 100(적층 위아래) · 수평 갭 100(한 줄 옆) · 트럭 양끝 200(앞뒤 결박) · **폭 여유 200(양쪽 각)**.
- 폭 여유 규칙: 화물 폭 허용 = **트럭 폭 + 양쪽 200(=+400)**, 그리고 현장 폭 제한과 함께 더 작은 값. **모듈·패널 모두 적용**(광폭 모듈도 일반 저상에 양쪽 200 튀어나와 적재 가능).
- 광폭검토(폭 3000 초과 플래그) **완전 제거**: 내부 플래그·회차표 컬럼·노란 강조·시각화 표시·`Module.is_wide()` 까지.
- 도식 반영: Top/Rear 뷰에서 화물이 트럭 폭 밖으로 **튀어나오게** 그리고, 트럭 폭 경계를 점선으로 표시.

**구현 메모**
- `SpacingParams` 에 `side_overhang_mm: float = 200.0` 필드 추가(기본값). 간격 기본값(100/200/100)은 그대로.
- 폭 검사 일괄 변경: 화물 폭 ≤ `truck.max_width + 2*sp.side_overhang_mm` 로.
  - `limits.can_carry` 의 폭 검사(트럭 쪽). 단 can_carry 는 현재 SpacingParams 를 안 받음 → overhang 을 어떻게 전달할지 결정: (가) can_carry 에 overhang 인자 추가, (나) SpacingParams 를 can_carry 에 전달. → **(가) overhang 기본 200 인자 추가**가 간단.
  - `packer` 의 모든 폭 비교(`p.width <= tr.max_width`, `m.width <= tr.max_width`, `_max_floor_panels_per_truck` 등) → `tr.max_width + 2*overhang`.
- 현장 폭 제한은 화물 실제 폭과 비교(변경 없음).
- 광폭검토 제거: `CarryResult.wide_check` 필드, `Trip.wide_check`, `_render_trip_table` 의 광폭 컬럼·`wide_check` 노란 배경, `visualizer` 의 wide 관련 표기, `Module.is_wide()` 제거. (`packer` 에서 `wide_check` 채우던 코드도 정리)
- 도식 튀어나옴: `visualizer.draw_top_view`/`draw_rear_view` 에서 화물 박스 폭을 실제 폭으로 그리되 트럭 외곽(폭) 점선 유지 → 자동으로 튀어나와 보임. 트럭 폭 점선 강조 추가.
- 옵션/수동시뮬 간격 위젯 제거 + `_read_spacing`/`_sim_spacing` 을 내장 `SpacingParams()` 반환으로 단순화. `_wire_auto_recompute` 의 간격 시그널 줄도 제거.

**검증 포인트**
- 운송 옵션·수동 시뮬에 적재 간격 입력칸이 없다.
- 폭 3400 패널/모듈이 폭 3000 트럭에 적재된다(양쪽 200 튀어나옴). 현장 폭 3300이면 막힌다.
- "광폭검토 필요" 표시가 어디에도 없다.
- 도식에서 화물이 트럭 폭 밖으로 튀어나오게 그려지고 트럭 폭 점선이 보인다.
- 전체 테스트 통과(폭/광폭검토 관련 테스트는 새 규칙으로 갱신).

## C단계 — 트레일러별 "1회 고정 운송비" 운임 방식

**목적**: 운임 방식을 3종으로. "트럭 종류별 1회 고정비" 추가.

**결정사항 (확정)**
- 운임 방식 3종: ① 요금표 ② 트레일러별 km단가 ③ **트레일러별 1회 고정비(신규)**.
- 1회 고정비는 **트럭 종류별**(저상/광폭/A-frame) 입력. **거리 무관**, 회차당 그 종류 고정비를 그대로 더함. 총비용=회차별 합.
- 기본값: 저상 600,000 / 광폭 700,000 / A-frame 800,000 원 (비용 관계: 저상<광폭<A-frame 추정).
- 입력 위치: **프로젝트 설정**(운임 방식 콤보 + km단가 옆)에 종류별 1회 고정비 3칸 + **"일괄 적용" 버튼**(한 값 입력 → 3종 동일 복사).

**구현 메모**
- `economics.EconomicsOptions` 에 `fixed_per_trip` 모드 + `lowbed_fixed_krw/extendable_fixed_krw/aframe_fixed_krw` (기본 600000/700000/800000) 추가.
- `compute_trip_cost`: `cost_mode=='fixed_per_trip'` → 트럭 종류별 고정비 반환(거리 안 곱함), `rate_label="1회 고정"`, `distance_km` 은 표시용 왕복값 두되 비용 무관.
- `ProjectSettings` 에 같은 필드 추가 + 다이얼로그에 운임 방식 콤보 항목 "트레일러별 1회 고정비" + 고정비 3칸 + 일괄적용 버튼. `_load_from_settings`/`_on_accept` 배선.
- 운송 탭 읽기전용 미러: 운임 방식 콤보에 항목 추가(이미 콤보 존재), `_read_economics_options` 에 고정비 필드 매핑.
- 일괄적용 버튼: 다이얼로그 내에서 한 입력(예: 첫 칸 값)을 세 칸에 set.

**검증 포인트**
- 프로젝트 설정에서 운임 방식을 "트레일러별 1회 고정비"로 고르고 종류별 금액 입력 + 일괄적용 동작.
- 운송 계산 시 회차별 비용이 그 트럭 종류 고정비와 같고, 총비용=회차 수 합. 거리를 바꿔도 이 모드에선 총비용 불변.
- 다른 두 방식(요금표·km단가)은 기존대로 동작.

## D단계 — 운송 단면 변환 일반화 (각형강관 + H형강)

**목적/배경**: 현재 운송 단면 변환기가 **각형강관(SHS)만** 처리하도록 만들어져, 디자인에서 보를 **H형강으로 설계하면 운송 계산이 크래시**(H형강 객체엔 각형강관 속성 w/h/t 가 없음)한다. 한 프로젝트에 두 종류가 공존할 수 있으므로, 변환기를 일반화해 **둘 다 정확히** 처리한다. (= 버그 수정)

**결정사항 (확정)**
- 패널 보를 각형강관으로 "강제 통일"하지 않는다. 디자인이 정한 종류(각형강관/H형강)를 그대로 살려 무게·치수에 정확히 반영.
- 패널 두께(슬래브)는 사용자 고정값 유지(이번엔 안 건드림).

**구현 메모**
- `adapter.to_transport_section` 를 단면 종류에 따라 분기:
  - 각형강관(SHSSection): 기존대로 `section_type="SHS"`, width=w, height=h, thickness=t, flange=0, weight_per_m=weight_per_m_kg.
  - H형강(HSection): `section_type="H"`, width=B(플랜지폭), height=H(전체높이), thickness=t1(웨브), `flange_thickness=t2`, weight_per_m=weight_per_m_kg, name=name.
  - 종류 판별: `isinstance(sec, SHSSection)` / `isinstance(sec, HSection)` (양쪽 import). 운송 `Section` 모델은 이미 "H" 타입·flange_thickness 지원.
- 무게는 단위중량(kg/m)으로 계산되므로, 두 종류 모두 정확한 단위중량을 제공 → 무게 자동 정확. 치수(width/height)는 시각화에 사용.
- 단위 테스트 추가: HSection → 운송 Section 변환(타입 H, 치수·플랜지·단위중량) + H형강 보 그룹이 섞인 디자인에서 운송 변환이 크래시 없이 동작.

**검증 포인트**
- 보를 H형강으로 설계한 씬에서 운송 계산이 **오류 없이** 돌아간다(이전엔 크래시).
- 각형강관·H형강을 섞어 설계해도 각 부재 무게가 해당 단면 단위중량으로 반영된다.
- 각형강관만 쓰던 기존 디자인의 운송 결과는 변함없다(회귀).
