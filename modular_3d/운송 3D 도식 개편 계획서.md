# 운송 3D 도식 개편 계획서

- 작성: 2026-05-26
- 트리거: 운송 검증 체크리스트 점검 중 사용자가 *좌표 입력 자동 정렬* + *3D 적재 도식을 메인 화면으로 전환* 요청
- 작업 방식: 자동 모드 — 각 페이즈 시작 시 본 계획서 정독 → 코드 작성 → 단위 테스트 → 회귀 → 페이즈 종료 시 계획서와 비교·버그 가능성 자체 검증 → 다음 페이즈. 중대한 사용자 결정 필요 시에만 중단.

---

## 0. 배경

기존 운송 탭의 도식 sub-탭은 *Top + Rear 2D 평면* 만 제공. 사용자가 운송 검증 도중 두 가지 불편을 보고:

1. **좌표 입력 헷갈림** — 모듈/패널을 입력할 때 *길이 vs 폭* 의 순서가 헷갈려 사용자가 매번 *짧은 쪽이 폭, 긴 쪽이 길이* 인지 신경 써야 함. → 코드에서 자동 정렬.
2. **2D 도식의 한계** — 적재 상태를 *입체적*으로 보고 싶음 + UI 가 좁아 디버깅 어려움. → 메인 화면(center pane) 3D 로 전환.

노션 5순위(향후 계획) 와도 일치: *"3D 렌더링(HTML/Plotly 방식, vispy 아님) — 팀원 원본 visualizer 의 draw_3d_view(Plotly 3D) 가 존재 → 새로 만들지 않고 이식·각색"*.

## 2. 영향 범위 조사 결과 (Q1 의 "바꿨을 때 생길 수 있는 문제" 응답)

**적용 지점**: `transport/adapter.py` 의 `build_transport_input()` 함수 안.
- 운송 어댑터는 *원본 Scene 모델 → 운송용 TModule/TPanel 변환의 단방향 진입점*. 어댑터에서 정규화하면 운송 패키지만 영향 받음.

**영향 받는 모듈**: `transport/` 패키지 전체 (패커·시각화·캐시·운임 등) — 정규화된 좌표로 일관 동작.
**영향 받지 않는 모듈**: 캐드 (`model/`) · 배치 설계 (`ui/design_tab.py`) · 접합부 (`ui/joint_edit_panel.py`) · 구조해석 (`analysis/`) · 물량 — 원본 Scene 좌표 그대로 사용.

**주의 처리할 부작용**:

1. **종속 floor 의 `wall_segments.side` 회전 변환** — swap 시 변 인덱스도 90° 회전. 변환 규칙:
   - 원본 (0=하변, 1=우변, 2=상변, 3=좌변) 가 *length/width 축* 에 묶여있음. swap 발생하면 side 인덱스도 함께 회전.
   - 회전 방향: length ↔ width 가 바뀌면 좌표축이 90° 회전 → side 인덱스도 한 방향으로 시프트. 구현에서 *side_after = (side_before + 1) % 4* 또는 *(side_before − 1) % 4* 중 하나. 정확한 방향은 *시각적 일관성 테스트로 확정* (Phase A 단위 테스트 안에서).

2. **`partial_wall` 의 `start_offset_mm`** — wall_segment 가 부분만 채울 때 시작 오프셋. swap 시 *변의 의미* 가 바뀌므로 start_offset 도 재계산해야 함. 변 의미 변경:
   - 변 0/2 (x 방향 변) 가 변 1/3 (y 방향 변) 으로 회전 시 — 길이의 의미가 *panel.length 의 비율* 에서 *panel.width 의 비율* 로 바뀜. 그러나 *세그먼트 자체 길이 `length_mm`* 는 절대값이라 그대로 유지. `start_offset_mm` 도 절대값이라 유지.
   - 하지만 *변 길이*가 panel.length(원래) 였다가 panel.width(swap 후) 가 되므로 *`start_offset + length_mm ≤ 변 길이`* 검사가 깨질 수 있음. 어댑터에서 정규화하기 전에 *side 만 회전*하고 swap 자체 안 하면 → 좌표 일관성 유지.
   - 더 안전한 약속: **swap 발생 시 종속 floor 의 wall_segments side 매핑은 회전 변환하되, panel.length/width 도 함께 swap**. 즉 *입력이 (length=3400, width=4500)* 이고 *wall_segment side=0 (length 방향 변, 길이=3400)* 인 경우, swap 후 *(length=4500, width=3400)* + *side=1 (width 방향 변, 길이=3400 — 동일)* 로 변환. 세그먼트 자체 치수 (length_mm, start_offset_mm) 는 보존.

3. **운송 시각화 (Plotly Top/Rear 2D) 의 좌표 약속** — 기존 `draw_top_view` / `draw_rear_view` 가 *panel.length = 트럭 진행 방향* 으로 그림. 어댑터에서 항상 *length = 긴 쪽* 으로 정규화하면 일관성 자동 유지.

4. **무게 계산** — `Module.weight` / `Panel.weight` 가 (length, width) 곱으로 면적·둘레 계산. swap 해도 곱과 합이 *대칭* 이므로 무게 동일. *부작용 없음*.

5. **테스트 픽스처** — `transport/tests/transport_v2_fixtures.py` 가 생성하는 모듈/패널이 *항상 length > width* 인지 확인. 아니면 정규화 발생. 테스트에 영향 가능 — Phase A 회귀에서 점검.

## 3. 페이즈 정의

### Phase A — ✅ 좌표 자동 정렬 (어댑터, 2026-05-26 완료)

- **산출물**: `transport/adapter.py` 의 `build_transport_input()` 끝에 *정규화 헬퍼* `_normalize_dims_for_transport(item)` 호출 추가. 모듈·순수 floor·종속 floor 적용. 단순 wall 은 제외 (벽 길이/높이 물리 의미 보존 — 자체 발견 사항).
- **신규 단위 테스트** (`transport/tests/test_adapter_normalize.py`) — 16 케이스 모두 통과:
  - 모듈 swap / idempotent / 정사각형 / 단면·extra_weight 보존 — 4 케이스
  - 순수 floor swap / idempotent — 2 케이스
  - 단순 wall 제외 정책 — 2 케이스
  - 종속 floor side 회전 매핑 (0→1→2→3→0) — 4 케이스 (parametrize)
  - 세그먼트 치수 (length_mm, start_offset_mm, ...) 보존 — 1 케이스
  - 종속 floor idempotent / 4 면 모두 회전 — 2 케이스
  - 정규화 후 패커로 정상 패킹 검증 — 1 케이스
- **검증 통과**: 전체 회귀 **365 passed + 1 skipped** (기존 349 + 신규 16)
- **자체 발견·결정 사항**:
  - Q4 "모두 swap" 답변 → 단순 wall 의 *length=벽 길이, width=벽 높이* 물리 매핑 이 어댑터 코드(adapter.py:707-712)에 명시되어 있어 swap 시 *벽 길이가 세움 적재 시 위로 솟는* 의미 변경 발생. 단순 wall 만 swap 제외로 보강.
  - 일반적으로 벽 길이 > 벽 높이 (층고 3m, 벽 길이 6m+) 이라 단순 wall swap 발생 자체가 드물어 실효 영향 작음.

## 4. 페이즈 의존성

```
Phase A (좌표 정규화)
  └─ Phase B (3D 시각화 함수 신규)
       └─ Phase C (UI center pane 부착 + 2D sub-탭 제거)
            ├─ Phase D (트럭 차체 디테일)
            └─ Phase E (카메라 프리셋 + 강조 + 오버레이)
```

A 는 독립. B 는 A 전·후 무관하지만 *정규화 좌표* 가 들어와야 시각이 일관. C 는 B 의 함수 호출. D / E 는 C 위에서 보강.

## 5. 한계 / 미해결

- 팀원 원본의 `draw_3d_view` 실제 코드를 찾지 못하면 — 기존 Top/Rear 2D 코드를 *3D 로 확장*. 핵심은 *Plotly Mesh3d / Scatter3d* 활용.
- 자유 회전 + 프리셋 동시 지원은 Plotly 기본 동작 — `scene.camera` 의 `eye / center / up` 으로 프리셋, 사용자 드래그는 자유 회전 자동.
- 차량 차체 디테일은 *Phase D* 에서 결정. 기본은 *간략 박스* — 더 디테일하게 원하시면 Phase D 진입 시 사용자 추가 결정.
- 사용자 결정 보류 항목 2 개 (계획서 § 1 보류 표) 는 *기본값 적용* — 진행 후 사용자가 다르게 원하면 조정.
