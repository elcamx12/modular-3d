## 0. 결정 사항 요약 (사용자 확정)

1. **세대수·층당 세대 표시 제거** — 우리 프로그램은 아파트 설계라 1모듈 = 1세대 가정이 깨짐. 세대 개념을 평가 화면에서 노출하지 않는다.
2. **공정표 결과 연동 방식** — JS 의 calc() 결과를 QWebChannel 로 Python 에 푸시 (4.b 의 a 안).
3. **케이스 저장 UI** — 우측 상단 모서리에 작은 버튼 1개. 슬롯 미니뷰·삭제 UI 미적용. 비교 탭은 별도 파일 다이얼로그로 케이스 3개를 직접 불러와 비교하는 방식.
4. **저장 방식** — 배치 설계 탭과 같은 흐름(파일 다이얼로그). 확장자는 `.case.json` 으로 디자인 파일과 구분.
5. **저장 범위** — 완전 스냅샷: 평가 화면 표시 데이터 + scene + ProjectSettings + 모든 탭 결과. 비교 후 "이 안으로 마감 작업 이어가기" 가능해야 다중안 결정 시나리오에 의미가 있음.
6. **미실행 탭 정책** — 안내만. 사용자가 해당 탭에서 직접 실행. 자동 트리거 없음.
7. **공정 시각화** — 축소 간트 (공종별 막대). 공정표 탭에 풀 간트 있으므로 평가 탭은 더 작게.
8. **비용 분류 — 5칸** — 자재비 / 운송비 / 노무비 / 경비 / (공사비 = 합계 라벨).
9. **단위** — 원.
10. **선택 옵션 미적용** — PDF 내보내기·도넛 차트 등.
11. **단가 DB 버전 스냅샷 미적용** — 비교 탭에서 다른 경우에만 표기.
12. **탭 이름·변수명** — 라벨 "평가", 변수명 `_tab_evaluation` (외부 호환을 위해 `_tab_final` 별칭 유지).

| 우측 상단 | — | "💾 평가 결과 저장" 버튼 (작게) |

## 3. 기술적 결정

### 3-1. 공정표 결과 푸시 (QWebChannel)

공정표 HTML 의 calc() 가 결과를 만든 직후, 우리가 만든 bridge 의 `on_schedule_calculated(payload)` 슬롯을 호출하도록 calc() 끝에 한 줄 추가.

푸시 payload(JS → Python):
- 총 공사 기간 (totalDays)
- 코어 기간·모듈 설치 기간
- 공종별 task 배열(name, start, end, real, total)
- laborSum / equipSum (노무비·경비 합계)

평가 탭은 이 payload 를 받아 캐시 → 평가 탭 진입 시 표시.

### 3-2. 자재비

물량 탭의 자재비 산출 결과를 그대로 가져옴. 컨트롤러 `_design_results` 또는 analysis_panel 의 산출 attr 에서 추출 (구현 시 정확 위치 점검).

### 3-3. 운송비

운송 탭 패커 결과의 `total_cost_krw` 같은 합계 attr 에서 가져옴 (구현 시 정확 위치 점검).

### 3-4. 노무비·경비

공정표 calc() 의 `laborSum` · `equipSum` 그대로.

### 3-5. 합계(공사비) 라벨

= 자재비 + 운송비 + 노무비 + 경비. 평가 탭이 직접 합산.

### 3-6. 미실행 탭 안내

평가 탭 진입 시 다음을 점검:
- 물량: `controller._design_results` 가 None 이면 "물량 탭에서 계산을 먼저 실행하세요" 안내, C 영역 회색.
- 운송: 운송 결과 attr 이 None 이면 "운송 탭에서 [계산 실행] 을 먼저 누르세요" 안내, D 영역 회색.
- 공기: 공정표 payload 캐시 없으면 "공정표 탭에 한 번 진입해 주세요" 안내, E 영역 회색.

해당 영역만 회색 처리하고 나머지는 정상 표시 (부분 결과도 가치 있음).

### 3-7. 케이스 파일 형식 (`.case.json`)

최상위 구조:
```
{
  "kind": "modular_case_v1",
  "saved_at": ISO 8601,
  "name": "사용자 입력 케이스 이름 (선택)",
  "scene": <배치 설계 탭의 저장 양식과 동일>,
  "project_settings": {...},
  "results": {
    "design_results": {...},   # 물량
    "transport": {...},        # 운송
    "schedule": {...},         # 공정표 payload
    "evaluation_display": {...} # 평가 화면 표시값 (헤드라인·5카드 등)
  }
}
```

저장은 `QFileDialog.getSaveFileName(filter="평가 케이스 (*.case.json)")`. 디자인 파일과 확장자로 구분.

## 5. 구현 Phase

### Phase J — 평가 패널 빈 골격 + 탭 이름·변수명 정리
1. `evaluation_panel.py` 신설. QScrollArea + QVBoxLayout 안에 A~F 영역을 빈 카드로 배치.
2. main_3d 의 placeholder 자리에 EvaluationPanel 끼움. 탭 라벨·변수명·상수 정리.
3. 진입 시 우측 상단에 저장 버튼만 보이게.

### Phase K — 데이터 수집 어댑터 신설
1. `modular_3d/evaluation/evaluation_adapter.py` 신설.
2. scene + ProjectSettings + 물량 결과 + 운송 결과 + 공정표 payload 를 묶어 평가 화면 표시용 dict 반환.
3. 미실행 탭에 대한 None 처리.

### Phase L — 공정표 결과 QWebChannel 푸시
1. `ScheduleBridge` 객체 신설 (`QObject` + `pyqtSlot`).
2. schedule_panel.py 에 QWebChannel 등록.
3. 공정표 HTML 의 calc() 끝에 `bridge.on_schedule_calculated(payload)` 호출 1줄 추가.
4. main 의 컨트롤러에 schedule 결과 캐시 attr 추가.

### Phase M — 영역별 렌더링
1. A. 헤드라인 카드 5개.
2. B. 부재 구성 표.
3. C. 강재·콘크리트 물량 + 자재비.
4. D. 운송 요약 카드.
5. E. 공기 요약 카드 + 축소 간트.
6. F. 종합 비용 5카드.

### Phase N — 케이스 저장
1. 저장 버튼 wiring → QFileDialog.
2. 직렬화 함수 작성 (scene + ProjectSettings + results 묶음).
3. JSON 으로 저장. 확장자 `.case.json`.

### Phase O — 회귀 테스트
1. 평가 어댑터의 None 처리·합계 계산·헤드라인 산출 단위 테스트 3~5건.
2. 케이스 파일 직렬화·역직렬화 round-trip 테스트 1건.
