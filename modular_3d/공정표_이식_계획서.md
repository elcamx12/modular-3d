대상 탭: 기존 "공기 및 접합부" 탭 (placeholder) → **공정표** 탭으로 이름 변경 후 본 계획대로 구현

원본 저장소: 팀원분 GitHub (공동 작업물이므로 별도 출처 표기는 하지 않음)

## 0. 결정 사항 요약 (사용자 확정)

1. **이식 방식**: QWebEngineView 임베드 + 우리 어댑터가 scene.json 동등 데이터를 자동주입.
2. **순서**: (가) HTML 통합·자동주입 먼저 → 그 뒤 B4 보강 패치만 적용. (나) 안은 폐기.
3. **새 입력 UI 위치**: 1차 버전은 HTML 내부 기존 입력 폼 그대로 사용. ProjectSettings 영구 저장은 2차로 분리.
4. **인쇄/PDF 내보내기**: 당장 만들지 않음.
5. **수직모듈 접합 처리(C3 정정)**: 수직모듈도 인접 모듈과의 접합은 발생함. 한 수직3층 모듈이 1~3층을 관통할 때, 4층 모듈과 만나는 면에서는 접합이 생기고, 그 외 층(2층·3층 옆에 일반 모듈이 없으면)에는 접합이 없는 식으로 **층별로 다름**. 어댑터에서 층별로 실제 인접 관계를 풀어 카운트해야 한다.
6. **출처 표기**: 공동 작업물이므로 별도 크레딧 노트 추가하지 않음.
7. **무시하기로 한 버그 / 정책 선택**:
   - B1 코어 없는 케이스 — 구조해석 탭에서 사전 차단되므로 본 탭에선 손대지 않음.
   - B7 모든 일수에 `max(1, …)` 가 걸리는 정책 — 의도된 보수 처리로 두고 변경하지 않음.
8. **수직접합속도·수평접합속도 0 입력 차단**: HTML 입력 폼에 min 값과 검증 메시지를 박아 0 이 입력되지 않도록 UI 단에서 차단(B8 대응).

## 1. 우리 데이터 → 팀원 프로그램 입력 매핑

### 1-1. scene.json 자동 주입(우리가 만들어 넣어줌)

| summary 키 | 출처 |
|---|---|
| floors_above_ground | 모듈/패널의 floor_index 최댓값 + 1 |
| modules_total | 모듈+수직모듈 총 개수 |
| modules_per_floor | floor_index=0 모듈 개수 (수직모듈은 관통 층 모두에서 카운트) |
| footprint_area_m2 | floor0 모듈+바닥패널 footprint 합 |
| core_area_per_floor_m2 | ProjectSettings 의 코어 슬래브 치수 |
| vertical_joints_total | ops_builder 의 모듈-모듈 수직접합 카운트 |
| horizontal_joints_total | ops_builder 의 모듈-모듈 수평접합 카운트(층별 합산) |
| module_max_weight_t | 운송 어댑터의 모듈 중량 산출값 중 최댓값 |
| basement_floors | ProjectSettings 의 지하 층수(없으면 0) |

`components` 배열에는 모듈·바닥패널·벽패널·수직모듈 + **코어 슬래브 1건(C1 신설)** 을 포함시키고, 각 모듈의 joint_records 에 상대 모듈 id·target_xy·target_z 를 채워 넣어 폴백 경로(좌표 인접 추정) 없이도 정확한 카운트가 가능하도록 한다.

### 1-2. 사용자 직접 입력으로 신설(HTML 입력 폼 그대로 사용, 1차)

- 크레인 종류·대수, 최하층/기준층 양중속도(유닛/일)
- 수직접합 1개당 소요일, 수평접합 1개당 소요일 — **둘 다 min > 0 강제**
- 코어 선행일
- 지역(가동율 자동) 또는 가동율 직접 입력, 공사 시작일, 유가
- 모듈당 수직접합 수(자동주입되지만 수동 보정 허용)

### 1-3. ProjectSettings 영구 저장(2차)

위 직접 입력값을 매번 재입력하지 않도록 schedule 섹션을 신설(2차 단계). 1차에서는 HTML 의 input 만 사용.

## 2. 적용할 버그/이슈 처리 결정표

| 코드 | 내용 | 결정 |
|---|---|---|
| B1 | 코어 면적 0 일 때 코어층당일이 1일로 강제 | **패치 안 함** (구조해석에서 사전 차단) |
| B2 | importScene 의 단일 모듈 타입 압축 | **우회**: 우리 어댑터가 multi-type 으로 직접 채움 (moduleTypes 배열을 JS 전역에 직접 주입) |
| B3 | 수직/수평접합 환산 반올림 손실 | **우회**: summary 에 층별 실측을 충분히 채워 readModuleJoints 경로가 정답을 쓰도록 유도 |
| B4 | refs/index.json 에 lh_p7·lh_p9 누락 | **패치**: index.json 에 두 항목 추가 (1단계 통합 후) |
| B5 | 층고 추정 폴백의 `g > 500` 임계 | **우회**: summary 항상 채움 → 폴백 경로 미사용 |
| B6 | max() 빈배열 가드 | **검증만**: 자동주입 흐름에서도 워닝 분기가 정상 동작하는지 회귀테스트 1건으로 확인 |
| B7 | 모든 일수에 `max(1, …)` 강제 | **변경 안 함** (보수 정책 유지) |
| B8 | 수직/수평접합속도 0 처리 | **입력 차단**: HTML input min 속성 + JS 검증 메시지 추가 |
| B9 | 회전·앵커 정합(0/90/180/270 + anchor 0~3) | **우회**: 어댑터에서 position 을 항상 min-corner 로 정규화(운송 어댑터의 사전 변환 재사용) |

## 3. 구현 Phase

### Phase A — 파일 배치 & 빈 탭 임베드
1. `modular_3d/schedule/` 폴더 신설.
2. 팀원 HTML 과 `refs/` 폴더를 `modular_3d/schedule/` 로 복사. (근거자료 PDF·xls 는 무관하므로 복사하지 않음.)
3. `ui/main_3d.py` 의 placeholder("공기 및 접합부") 자리에 QWebEngineView 위젯을 가진 새 패널을 끼움. 탭 라벨을 **"공정표"** 로 변경. 변수명은 `_tab_schedule` 로 정리(C10).
4. QUrl.fromLocalFile 로 HTML 로드. 이 시점에서 자동주입 없이도 빈 입력으로 HTML 이 정상 표시되어야 함.

### Phase B — schedule_adapter 신설
1. `modular_3d/schedule/schedule_adapter.py` 신설.
2. 우리 모델·ProjectSettings·ops_builder 결과를 받아 다음을 산출:
   - summary 9개 키 (위 1-1 표)
   - components 배열 (모듈·바닥패널·벽패널·수직모듈·**core_slab 합성 1건**)
   - 각 모듈 joint_records (target_comp_id·target_xy·target_z 포함)
3. position 은 min-corner 정규화. anchor 0~3 / rotation 0·90·180·270 모두 정상 export 되도록 변환 — 운송 어댑터의 `_world_to_parent_nominal` 과 유사한 사전 변환 사용.
4. 수직모듈 인접 접합은 층별로 풀어 정확히 카운트(C3 정정 반영).
5. 접합 분류(C2): ops_builder 의 OP_KIND 중 모듈-모듈 수직 / 모듈-모듈 수평 두 가지만 카운트. 그 외(코어 연결 등)는 본 탭 모델 외 처리.

### Phase C — QWebChannel 자동주입
1. `ui/schedule_panel.py` 신설. QWebEngineView + QWebChannel 브리지.
2. 탭 진입 시 schedule_adapter 가 만든 데이터를 JSON 직렬화 → JS 의 `importScene(json)` 호출.
3. `moduleTypes` 배열은 importScene 압축 경로를 건너뛰고 어댑터에서 multi-type 으로 직접 주입(B2 우회).
4. HTML 의 "파일 불러오기" 버튼은 호환용으로 그대로 둠.

### Phase D — B4 보강 패치
1. `modular_3d/schedule/refs/index.json` 에 `lh_p7`, `lh_p9` 항목 추가.
2. 라벨은 PDF 원문 페이지 제목과 일치시킴.

### Phase E — 수직/수평접합속도 0 입력 차단 (B8)
1. 두 input 의 `min` 속성을 양수 최소값으로 강제.
2. `oninput` 핸들러에서 0 이하 입력 시 즉시 워닝 메시지 표시 + 마지막 유효값으로 복원.

### Phase F — 회귀 테스트(B6 검증 + 데이터 정합)
1. 우리 어댑터가 만든 scene 데이터를 HTML 로직(브라우저 자동화 없이 JS 단위 추출이 어려우면 Python 측에서 동일 산식을 작은 모사 함수로 검증)에 흘려, summary 우선 경로와 폴백 경로 결과가 일치하는지 1건 회귀 테스트.
2. 빈 입력·세대층 0 같은 비정상 입력에서 워닝 분기가 켜지는지 확인.

### Phase G — ProjectSettings schedule 섹션 (2차, 본 계획서 범위 외)
별도 후속 계획으로 분리. 1차 통합 안정화 후 착수.
