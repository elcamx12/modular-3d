## 1. 이형단면(ㄷ/ㅁ/L자) 교차부 노드공유 [P2c-2] — ★완료(2026-06-29)
- 구현: `_consolidate_dependent_nodes` (b) 갈래 재작성. 거리 임계 추정이 아니라 **각 벽의
  외곽 사각형(중심선±두께/2) 실제 겹침(AABB 교차)**으로 판정 → 물리적으로 맞닿은 직각
  (가로 rot%180==0 + 세로==90) 두 벽만 통합. 떨어진 벽은 사각형 안 겹쳐 자연 제외.
- 모든 층 형상 동일 전제: 평면 정체성(외곽 사각형 round)별로 벽을 묶어 **모서리·교차점은
  한 번만 판정**, 노드 통합만 floor 매칭으로 전 층 일괄. 통합 후 좌표는 두 중심선 직각
  교차점(세로벽 x, 가로벽 y)으로 보정 → 생성순서 무관 좌우 대칭.
- 통합 부작용 처리: 끝 코너가 교차점으로 이동하면 하변 길이가 변해 fiber 폭 합과
  노드 기하 불일치(MVLEM_3D 경고) → 통합으로 길이 변한 wall 의 fiber_widths 를 실제
  하변 길이에 비례 재정규화(비율 보존). 경고 0 확인.
- 검증: A최신/A18(18층)/C최신/B최신/Ascene 모두 교차부 완전 연결. ㅁ자 닫힌 코어·짧은
  연결벽(W480이 두 평행 가로벽 위·아래 모두 연결, 중심선간 180으로 정확 축약) 처리 확인.
  음성 테스트(가로벽 멀리 이동→안 이음) 통과. 골든 8 passed, 회귀 0.
- 한 몸 거동 확인: A최신 ㅁ자 코어 pushover(X, 31스텝) → 초기강성 4345 kN/mm·연화비 0.03
  으로 깨끗한 휨항복 곡선(끊겼으면 각 벽 따로 거동해 강성↓·불규칙). 발산 없음.

## 3. 축력 모듈 eleLoad 통합 — ★해결(2026-07-01)
- ★근본 원인: 과거 발산은 P-Delta·조합 문제가 아니라 **코어 슬래브 둘레 보
  (core_slab_beam)·천장 러너(core_ceiling_runner)가 수직(Uz) 무지지**였던 것. 다이어프램은
  면내(Ux·Uy·Rz)만 구속 → 이 보들에 자중을 실으면 무한 처짐(Linear 조차 변위 6e16mm,
  rc=0 은 1회라 거짓 성공). 모듈 중력 통합이 이 보에도 자중을 실으면서 비로소 드러남.
  진단: 코어/모듈/둘다 중력 분리 → 모듈만도 발산, 코어 role 제외 시 수렴(최대변위 2.72mm).
- ★수정(ops_solver ① 중력): 모듈 부재(기둥·보)만 eleLoad(dl=1,ll=0), **코어 슬래브/천장
  role 제외**(이들은 모듈 아닌 코어 슬래브 면내강성 표현). 중력은 **비선형(KrylovNewton·
  LoadControl 0.1 점증)으로 수렴** 후 loadConst(Linear 1회는 잔류 불평형 → 발산).
- 검증: A최신 완주(60249kN, 코어만 대비 -0.2%), A18 완주(19683kN, 코어만 20860 대비 -5.6%
  — 18층 P-Delta 전도효과 정밀 반영), 발산 0·세분 0, 골든 8 통과.
- ★코어 슬래브 자중 정석 반영 + 수직 무지지 특이 해결 — 해결(2026-07-01). 코어 슬래브/
  천장 보(강체 다이어프램이라 휨 무의미)는 수직(Uz) 무지지 → 두 겹 처리:
  ① 자중을 보에 싣지 않고 양끝 노드 위치의 **최근접 코어벽 노드에 노드력**(자중×보길이/2)
  으로 옮겨 벽으로 전달 — **_apply_eleload_factored 공통화**(solve_vertical·seismic·pushover
  모두 적용, 이전 solve_pushover 인라인 중복 제거).
  ② 코어 슬래브 노드의 무지지 **Uz 를 빌드(ops_builder)에서 fix** — Uz 강성 0 → 행렬 특이
  (UmfPack solve 실패). 자중 0 이어도 0/0 특이라 A예전scene 형상서 등가정적(solve_vertical)
  부터 -3 발산(★사용자 F6 오류 재현). 강체 슬래브라 수직 처짐 0 이 물리적·자중은 벽으로
  전달되므로 fix 가 거동 무관(특이만 제거).
  [폐기] 슬래브 노드를 코어벽에 Uz equalDOF 로 결합하는 방식은 과구속 → 밑면전단 4배(60→
  260MN). 검증: A예전 solve_vertical·solve_all_cases(F6) OK, A최신·A18 OK, A최신 pushover
  60926kN(Uz fix 로 +1.1%), 골든 통과.

## 8. 큰 실무 모델 pushover 성능/수렴 [P6 발견] — ★근본원인 해결(2026-07-01)
- 진단: '느림'의 정체는 성능이 아니라 **18층 발산**이었다. 분해 1회는 UmfPack 로 이미
  빠름(A18 노드 6482 → 3.8s). 18층이 스텝당 수백초로 보인 건 발산하는 비선형 반복을
  한도(200회)까지 돌던 것(수렴 위한 반복 아님). 저층은 수렴.
- ★근본 원인 = **코어 축력 누적 버그**. 기존엔 '자기+위층 같은 group z≥ 자중'을 수동
  합산해 노드에 부여했는데, (a) 한 group 이 코어 둘레 여러 벽(ㅁ자 10세그먼트)을 묶어
  아래벽이 코어 전체 자중 수령(~10배), (b) 그 노드 하중을 해석이 또 아래로 누적(이중)
  → 18층 최하부 축력비 N/(0.85·fck·Ag)=2.19(압축내력 2배) → MVLEM fiber 압축붕괴 →
  변위제어 발산. 3층은 축력비 0.25 라 안 터짐(절대값 작음).
- ★수정(ops_solver ① 중력): 각 벽에 **자기 자중만** 상단 노드에 부여, 층간 누적은 수직
  노드공유 체인(아래벽 상변 n_tl·n_tr == 위벽 하변 n_bl·n_br)으로 **해석이 자동 누적**.
  검증: 체인 깊이 균일(A18 전부 19=18층+바닥), 18층 축력비 2.19→0.07 정상화, 축력 ON
  상태 5mm 스텝 2~5회 수렴(발산 해소). 골든 8 통과.
- 부수 도입(수렴 안정화): **적응 스텝 + 라인서치**(KrylovNewton 실패→NewtonLineSearch→
  증분 절반 세분, 최소 dU/64) + pushover maxIter 200→35(큰 증분 빠른 실패→세분).
  결과 보존(두 해상도 곡선 일치)·골든 통과.
- ★영향(종설 수치): 과대 축력 제거로 저층 밑면전단 -14%(A최신 69922→60397kN), '축력
  효과'가 +24%→**+3.2%**(A최신 축력 ON/OFF 최대전단비). 종설 결론 수치 갱신 필요.
- 검증 진행중: A18 전체 완주(2% drift, 항복·P-Delta 하강) — 별도 백그라운드.
- 남은 성능: 분해 1회 3.8s 는 본질적 하한(희소솔버 최적). 18층 완주는 수십분 규모.
